Продолжаем пошаговое развитие Roulette Dealer Trainer.

Сейчас уже есть процесс:

Создать аттестацию
→ Выбрать игру
→ Настроить выбранную игру
→ Выбрать одного или нескольких дилеров

Следующий этап:

**добавить экран проверки аттестации перед финальным созданием.**

На этом этапе TrainingTemplate и TrainingAssignment ещё НЕ создавать.

## 1. Экран проверки

После выбора дилеров кнопка `Далее` должна открывать страницу проверки.

Используй маршрут:

`/manager/training/new/review`

или уже существующий маршрут этого шага.

На странице показать:

`Новая аттестация`

и итоговую информацию по текущему wizard.

## 2. Блок "Игра"

Показать выбранную игру.

Например:

Игра

Roulette

Рядом добавить кнопку:

`Изменить`

По нажатию вернуть пользователя на экран выбора игры.

При возврате данные текущего wizard не должны автоматически удаляться.

## 3. Блок "Настройки"

Показать краткое резюме выбранных настроек Roulette.

Не нужно просто выводить огромный JSON.

Нужно представить настройки в читаемом виде, используя названия, понятные руководителю.

Например концептуально:

Настройки Roulette

Минимум рулетки: ...
Максимум рулетки: ...
Соседи: ...
Комплиты: ...
Серии: ...
Цвет: ...
Кэш: ...
и остальные параметры, которые реально существуют в текущем RouletteSettings.

Важно:

используй реальный актуальный RouletteSettings из проекта.

Не создавай отдельный сокращённый набор полей вручную.

Если настроек много, можно сгруппировать их так же, как они сгруппированы в существующем Settings Roulette.

## 4. Изменение настроек

В блоке настроек добавить:

`Изменить`

Кнопка должна вернуть пользователя на:

`GameSettingsPage`

После редактирования:

Настройки
→ Далее
→ Выбор дилеров
→ Далее
→ Review

Все остальные данные wizard должны сохраняться.

То есть выбранные дилеры после изменения настройки не должны сбрасываться.

## 5. Блок "Дилеры"

Показать всех выбранных дилеров.

Например:

Дилеры

Иванов Иван Иванович
Петров Пётр Сергеевич
Сидоров Алексей Андреевич

Выбрано: 3

ФИО получать по `dealerIds` из существующего источника Dealer.

Не хранить дублирующие ФИО внутри wizard.

## 6. Изменение дилеров

Добавить кнопку:

`Изменить`

в блоке дилеров.

Она должна вернуть на:

`SelectDealersPage`.

Ранее выбранные дилеры должны оставаться отмеченными.

После изменения и возврата на Review должен отображаться актуальный новый список.

## 7. Структура экрана

Пример:

Новая аттестация

Игра
Roulette
[ Изменить ]

---

Настройки Roulette

Минимум рулетки: ...
Максимум рулетки: ...
Количество соседей: ...
Комплиты: ...
Серии: ...
...

[ Изменить ]

---

Дилеры

Иванов Иван Иванович
Петров Пётр Сергеевич

Выбрано: 2

[ Изменить ]

---

[ Создать аттестацию ]
[ Назад ]
[ Отмена ]

## 8. Кнопка "Назад"

Кнопка:

`Назад`

должна вернуть пользователя на последний шаг:

`Выбор дилеров`.

Данные wizard не терять.

## 9. Кнопка "Отмена"

Кнопка:

`Отмена`

должна завершить текущий wizard и вернуть пользователя на:

`/manager`

После отмены желательно очистить текущий черновик создания аттестации, чтобы при следующем создании не появлялись старые данные.

Если wizard context/state уже имеет функцию reset — используй её.

Не создавать отдельный механизм без необходимости.

## 10. Кнопка "Создать аттестацию"

Добавь основную кнопку:

`Создать аттестацию`

На ЭТОМ этапе она пока НЕ должна окончательно создавать TrainingTemplate/Assignment.

Допустимо временно:

* показать сообщение;
* перейти на временную success-заглушку;
* оставить handler подготовленным.

Финальное сохранение будет следующим отдельным этапом.

Главное сейчас — полностью проверить собранные данные перед созданием.

## 11. Валидация Review

Review должен быть доступен только если wizard содержит:

* выбранный `gameType`;
* `gameConfig`;
* хотя бы один `dealerId`.

Если данных нет, приложение не должно падать.

Например:

если отсутствует gameType:
→ вернуть к выбору игры.

Если отсутствует gameConfig:
→ вернуть к настройкам.

Если отсутствуют dealerIds:
→ вернуть к выбору дилеров.

Используй простой и понятный guard.

## 12. Не создавать отдельную копию настроек для Review

Если нужно представить RouletteSettings в читаемом виде, можно создать небольшой presentation-компонент, например:

`RouletteSettingsSummary`

Но он должен принимать существующий:

`RouletteSettings`

и только отображать его.

Он не должен создавать новую модель настроек.

Концептуально:

`RouletteSettingsForm`
— редактирует

`RouletteSettingsSummary`
— отображает

Оба работают с одним `RouletteSettings`.

Это пригодится позже на странице уже созданной аттестации.

## 13. Архитектура для будущих игр

Экран Review не должен быть полностью захардкожен под Roulette.

Желательная структура:

GameReview
|
├─ ROULETTE
│      → RouletteSettingsSummary
|
├─ BLACKJACK
│      → BlackjackSettingsSummary
|
└─ POKER
→ PokerSettingsSummary

Сейчас реализовать только Roulette.

Не добавлять Blackjack/Poker.

## 14. Смена игры

Особое внимание:

если на Review руководитель нажимает:

`Игра → Изменить`

и в будущем выбирает ДРУГУЮ игру, старый `gameConfig` нельзя применять к новой игре.

Сейчас существует только Roulette, поэтому проблема ещё не проявляется.

Но при реализации state желательно заложить правило:

при фактической смене `gameType` конфигурация предыдущей игры должна очищаться или заменяться defaults новой игры.

Не делать сложной реализации ради будущего, но не связывать `gameConfig` навсегда с любой игрой.

## 15. Пока НЕ создавать TrainingTemplate

После этого этапа состояние по-прежнему только черновик:

{
gameType,
gameConfig,
dealerIds
}

Не сохранять пока:

* TrainingTemplate;
* TrainingAssignment;
* Training;
* GeneratedSpin.

## 16. Не менять Roulette

Не менять:

* Spin;
* ставки;
* генераторы;
* выплаты;
* racetrack;
* игровое поле;
* вопросы;
* звуки;
* рабочую логику Settings.

Допускается только создание read-only компонента для отображения RouletteSettings.

## 17. Проверка полного wizard

Проверь:

1. Открываю `/manager`.
2. Нажимаю `Создать аттестацию`.
3. Выбираю Roulette.
4. Настраиваю Roulette.
5. Выбираю Иванова и Петрова.
6. Нажимаю `Далее`.
7. Открывается Review.
8. Вижу Roulette.
9. Вижу актуальные настройки.
10. Вижу Иванова и Петрова.
11. Нажимаю `Изменить` у настроек.
12. Меняю параметр.
13. Возвращаюсь на Review.
14. Новое значение отображается.
15. Дилеры не потерялись.
16. Нажимаю `Изменить` у дилеров.
17. Добавляю Сидорова.
18. Возвращаюсь.
19. Отображаются три дилера.
20. `Назад` возвращает к выбору дилеров.
21. `Отмена` возвращает `/manager` и очищает wizard.
22. TrainingTemplate пока не создаётся.

## 18. После выполнения

Кратко сообщи:

1. какие файлы созданы;
2. какие файлы изменены;
3. какой маршрут используется для Review;
4. как отображаются настройки Roulette;
5. создан ли отдельный `RouletteSettingsSummary`;
6. как работают кнопки `Изменить`;
7. как работает guard неполного wizard;
8. как очищается wizard при `Отмена`;
9. что делает кнопка `Создать аттестацию` сейчас;
10. подтверждение, что TrainingTemplate/Assignment пока не создаются;
11. подтверждение, что Roulette не изменялась.

Выполни только этот этап.

Не переходи самостоятельно к сохранению TrainingTemplate и TrainingAssignment.
