Продолжаем развитие Roulette Dealer Trainer небольшими этапами.

Уже выполнено:

* есть `/login`;
* есть `/manager`;
* есть `/dealer`;
* руководитель видит список дилеров;
* руководитель может добавить дилера;
* дилеры сохраняются в `localStorage`;
* есть страница конкретного дилера `/manager/dealers/:dealerId`;
* на странице дилера есть кнопка `Создать тренировку`;
* существующая Roulette работает без изменений.

Сейчас нужно выполнить только следующий этап:

**создание настроек тренировки для выбранного дилера и сохранение объекта Training.**

Сам Spin и ставки Roulette на этом этапе НЕ генерировать.

## 1. Новый маршрут

Для создания тренировки добавь маршрут:

`/manager/dealers/:dealerId/training/new`

На него должна вести существующая кнопка:

`Создать тренировку`

со страницы конкретного дилера.

## 2. Экран новой тренировки

Создай отдельную страницу, например:

`CreateTrainingPage`

На ней показать:

```text
Новая тренировка

Дилер:
Иванов Иван Иванович

Игра:
Roulette
```

Пока Roulette — единственная доступная игра.

Не нужно делать выбор Poker или Blackjack.

Можно отображать:

`Игра: Roulette`

как обычный текст.

Архитектурно при этом Training должен содержать `gameType`, чтобы позже можно было добавить другие игры.

## 3. Настройки тренировки

Ниже добавить блок:

`Уровень сложности`

Пока нужны следующие параметры:

### Соседи

Поле:

`Количество соседей`

целое число.

### Комплиты

Поле:

`Количество комплитов`

целое число.

### Серии

Поле:

`Количество серий`

целое число.

### Цвет

Добавить переключатель/checkbox:

`Цветные фишки`

Если включён — показывать поле:

`Количество цветных фишек`

### Кэш

Добавить переключатель/checkbox:

`Кэш на поле`

Если включён — показывать поле:

`Сумма кэша`

Пример экрана:

```text
Новая тренировка

Дилер:
Иванов Иван Иванович

Игра:
Roulette


Уровень сложности

Количество соседей
[ 5 ]

Количество комплитов
[ 2 ]

Количество серий
[ 2 ]


[x] Цветные фишки

Количество цветных фишек
[ 100 ]


[x] Кэш на поле

Сумма кэша
[ 1000 ]


[ Создать тренировку ]

[ Отмена ]
```

## 4. Значения по умолчанию

Для тестирования можно использовать:

```text
Количество соседей = 5
Количество комплитов = 2
Количество серий = 2

Цветные фишки = включены
Количество цветных фишек = 100

Кэш = включён
Сумма кэша = 1000
```

Это пока тестовые значения формы.

## 5. Важное уточнение

Сейчас НЕ нужно полностью переносить все существующие настройки Roulette.

Текущая Roulette имеет гораздо больше параметров.

На этом этапе мы только создаём минимальную модель Training для проверки архитектуры.

Позже мы отдельно свяжем TrainingConfig с настоящими настройками существующей Roulette.

Поэтому существующий Settings экран Roulette сейчас не менять.

## 6. Модель Training

Создай отдельный тип Training.

Например:

```ts
type GameType = "ROULETTE";

type TrainingStatus = "CREATED";

type RouletteTrainingConfig = {
  neighborsCount: number;
  completesCount: number;
  seriesCount: number;

  colorEnabled: boolean;
  colorCount: number;

  cashEnabled: boolean;
  cashAmount: number;
};

type Training = {
  id: string;
  dealerId: string;
  gameType: GameType;
  status: TrainingStatus;
  config: RouletteTrainingConfig;
  createdAt: string;
};
```

Названия могут немного отличаться, если в проекте уже используется другой naming style, но смысл структуры сохранить.

## 7. Training — отдельная сущность

Очень важно:

НЕ хранить Training непосредственно внутри объекта Dealer.

Не делать:

```ts
Dealer {
  id;
  fullName;
  trainings: [...]
}
```

Dealer остаётся:

```ts
Dealer {
  id;
  fullName;
}
```

Training хранится отдельно и связывается через:

```ts
dealerId
```

То есть:

```text
Dealer
   ↑
 dealerId
   |
Training
```

Это нужно для будущего backend и базы данных.

## 8. Хранение Training

На этом этапе Training также можно сохранять в `localStorage`.

Используй отдельный ключ от дилеров.

Например:

`roulette-trainer-trainings`

или другой понятный ключ в стиле текущего проекта.

Желательно сделать отдельный небольшой storage-модуль, например:

`trainingStorage.ts`

с минимальными функциями:

```ts
getTrainings()
saveTrainings()
addTraining()
getTrainingsByDealerId()
```

Не создавать сложный Repository/Service слой.

Позже этот storage будет заменён backend API.

## 9. Создание Training

После нажатия:

`Создать тренировку`

нужно:

1. проверить значения формы;
2. создать уникальный `id`;
3. установить выбранного `dealerId`;
4. установить:

```text
gameType = ROULETTE
status = CREATED
```

5. сохранить config;
6. сохранить `createdAt`;
7. сохранить Training в `localStorage`.

Пока НЕ запускать Roulette.

Пока НЕ генерировать Spin.

## 10. Что происходит после создания

После успешного создания вернуть руководителя на страницу дилера:

`/manager/dealers/:dealerId`

Теперь вместо:

`Тренировок: 0`

должно отображаться реальное количество тренировок этого дилера.

Например:

```text
Иванов Иван Иванович

Тренировок: 1

[ Создать тренировку ]

Тренировки

Roulette
Статус: CREATED
```

Если создано две:

```text
Тренировок: 2
```

## 11. Минимальный список тренировок дилера

На странице конкретного дилера под кнопкой `Создать тренировку` показать его существующие тренировки.

Пока достаточно показывать:

* игру;
* статус;
* дату создания.

Например:

```text
Тренировки

Roulette
Статус: Создана
09.08.2026
```

На этом этапе строка тренировки может быть некликабельной.

Отдельную страницу Training пока создавать не нужно.

## 12. Валидация

Пока нужна только простая защита:

* количество соседей не может быть отрицательным;
* количество комплитов не может быть отрицательным;
* количество серий не может быть отрицательным;
* количество цветных фишек не может быть отрицательным;
* сумма кэша не может быть отрицательной.

Поля количества должны работать с целыми числами.

Сложные ограничения Roulette пока сюда не переносить.

## 13. Кнопка "Отмена"

Кнопка:

`Отмена`

должна вернуть пользователя на:

`/manager/dealers/:dealerId`

и не создавать Training.

## 14. Очень важно — Roulette пока не подключать

На этом этапе Training только создаётся и сохраняется.

НЕ нужно:

* открывать Roulette после создания;
* генерировать выигрышный номер;
* генерировать Spin;
* генерировать соседей;
* генерировать комплиты;
* генерировать серии;
* генерировать цвет;
* генерировать кэш;
* менять существующий генератор Roulette.

Связь Training → Roulette будет отдельным следующим этапом.

## 15. Не менять текущие настройки Roulette

Существующий экран Settings Roulette оставить полностью как есть.

Пока у нас существуют две независимые вещи:

```text
Manager Training Config
```

и

```text
Existing Roulette Settings
```

На следующем этапе мы будем аккуратно решать, как связать их между собой.

Не пытайся самостоятельно объединять эти настройки сейчас.

## 16. Пока НЕ делать

Не нужно:

* делать Spin;
* создавать страницу Training;
* создавать кабинет дилера;
* назначать Training дилеру дополнительно — dealerId уже является назначением;
* создавать login/password;
* создавать User;
* создавать роли;
* делать backend;
* делать API;
* подключать PostgreSQL;
* делать статистику;
* добавлять Poker;
* добавлять Blackjack;
* изменять существующую Roulette.

## 17. Проверка результата

Проверь сценарий:

1. Открываю `/manager`.
2. Выбираю дилера.
3. Открывается `/manager/dealers/{dealerId}`.
4. Нажимаю `Создать тренировку`.
5. Открывается форма новой тренировки.
6. Форма показывает выбранного дилера.
7. Ввожу параметры сложности.
8. Нажимаю `Создать тренировку`.
9. Training сохраняется.
10. Возвращаюсь на страницу дилера.
11. `Тренировок: 0` становится `Тренировок: 1`.
12. В списке появляется новая Roulette-тренировка со статусом CREATED.
13. Обновляю браузер.
14. Training остаётся на месте.
15. Создаю вторую тренировку.
16. Отображается `Тренировок: 2`.
17. Тренировки других дилеров не отображаются у этого дилера.
18. `/login`, `/dealer` и существующая Roulette продолжают работать как раньше.
