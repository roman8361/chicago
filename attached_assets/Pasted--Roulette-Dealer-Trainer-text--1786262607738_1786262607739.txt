Продолжаем пошаговое развитие Roulette Dealer Trainer.

Предыдущий этап уже выполнен:

```text
Создать тренировку
        ↓
Выбор игры
        ↓
Roulette
        ↓
Далее
```

Есть:

* универсальный экран выбора игры;
* `gameType = ROULETTE`;
* реестр доступных игр;
* переход на следующий шаг создания тренировки.

Сейчас нужно реализовать ТОЛЬКО следующий этап:

**экран настроек выбранной игры.**

Для Roulette экран должен использовать тот же функционал настроек, который уже существует в текущем Roulette.

## 1. Целевой процесс

После выбора:

`Roulette`

и нажатия:

`Далее`

должен открываться экран:

```text
Новая тренировка

Игра: Roulette

Настройки Roulette

[ существующие настройки Roulette ]

[ Назад ]
[ Далее ]
[ Отмена ]
```

Пока кнопка `Далее` будет вести на временный следующий шаг.

Выбор дилеров будет реализован отдельным этапом.

## 2. Маршрут

Используй существующий маршрут следующего шага, если он уже был подготовлен.

Например:

`/manager/training/new/settings`

Страница должна понимать выбранный ранее:

```ts
gameType = "ROULETTE"
```

Если пользователь открыл `/settings` напрямую и `gameType` отсутствует, приложение не должно падать.

В таком случае верни пользователя на:

`/manager/training/new/game`

или покажи понятное сообщение и кнопку возврата к выбору игры.

## 3. Архитектура настроек по типу игры

Не делай страницу жёстко привязанной только к Roulette.

Страница должна концептуально работать так:

```text
GameSettingsPage
       |
       ├── ROULETTE
       │      ↓
       │ RouletteSettingsForm
       │
       ├── BLACKJACK
       │      ↓
       │ BlackjackSettingsForm
       │
       └── POKER
              ↓
          PokerSettingsForm
```

Blackjack и Poker сейчас НЕ реализовывать.

Нужно только заложить понятную точку выбора формы по `gameType`.

Например:

```ts
switch (gameType) {
  case "ROULETTE":
    return <RouletteSettingsForm ... />;
}
```

или используй более подходящий текущему проекту вариант.

Не создавать сложный framework/plugin engine.

## 4. Сначала проанализировать существующий Roulette Settings

Перед изменениями найди существующую реализацию настроек Roulette и выясни:

* где находится UI;
* какой объект настроек используется;
* какие поля в нём есть;
* какие значения по умолчанию;
* какая валидация;
* какие select/checkbox/input используются;
* какие зависимости между полями;
* как настройки сейчас передаются в Roulette;
* какие настройки используются генераторами.

Не создавай настройки заново по памяти.

Источником истины является существующая реализация проекта.

## 5. Переиспользовать существующие настройки

Главное требование:

экран:

`Создание тренировки → Roulette → Настройки`

должен иметь тот же функционал, что существующий:

`Roulette → Настройки`.

Не должно быть двух независимых реализаций одинаковой формы.

Желательный результат — выделить переиспользуемый компонент:

```tsx
<RouletteSettingsForm
    value={settings}
    onChange={setSettings}
/>
```

или аналогичный компонент в стиле текущего проекта.

Этот компонент должен быть пригоден для использования:

```text
Existing Roulette Settings
```

и:

```text
Manager Training Wizard
```

## 6. Минимальный безопасный рефакторинг

Существующая Roulette уже работает.

Поэтому:

НЕ переписывай Settings полностью.

Если Settings сейчас встроен в большой компонент, аккуратно вынеси только UI/форму и связанную с ней чистую логику, которая действительно нужна для переиспользования.

Не менять:

* визуальное поведение существующего Settings;
* названия полей;
* значения;
* defaults;
* правила включения/отключения полей;
* ограничения.

После рефакторинга текущий Settings Roulette должен работать точно так же, как до него.

## 7. Единый тип настроек

Если уже существует тип вроде:

```ts
RouletteSettings
```

используй его.

Если отдельного типа нет, а объект настроек существует неформально, можно аккуратно выделить общий тип.

Но не создавать два типа:

```ts
RouletteSettings
```

и:

```ts
TrainingRouletteSettings
```

с одинаковыми полями.

Должен быть один формат:

```text
RouletteSettings
      |
      ├── existing Roulette
      └── future TrainingTemplate.config
```

## 8. Значения по умолчанию

При первом открытии настроек новой тренировки должны использоваться те же default values, которые используются текущим Roulette Settings.

Не копируй defaults вручную в новую страницу, если их можно вынести в общий источник.

Желательно иметь один источник:

```ts
DEFAULT_ROULETTE_SETTINGS
```

или существующий аналог.

И использовать его и в Roulette, и в wizard.

## 9. Важно: настройки wizard пока независимы от текущих Settings Roulette

Хотя форма и модель общие, состояние новой тренировки должно быть отдельным.

Если пользователь на странице создания тренировки изменил:

```text
Количество комплитов
```

это НЕ должно сразу менять текущие рабочие Settings обычного Roulette.

И наоборот.

Переиспользуется:

* компонент;
* тип;
* defaults;
* validation.

Но значение состояния отдельное.

Схема:

```text
               RouletteSettings
                      |
            ┌─────────┴─────────┐
            ↓                   ↓
Current Roulette state    New training state
```

## 10. Состояние wizard

После изменения настроек и перехода назад:

```text
Настройки
   ↓
Назад
   ↓
Выбор игры
```

а затем снова:

```text
Roulette
↓
Далее
```

желательно сохранить уже введённые значения в рамках текущего wizard.

Не нужно пока сохранять их в `localStorage` как TrainingTemplate.

Можно использовать существующий state/context wizard.

Если текущая реализация wizard теряет state при переходах, можно минимально расширить её.

## 11. Кнопка "Назад"

`Назад`:

```text
Настройки
   ↓
Выбор игры
```

Пользователь может поменять игру.

Поскольку сейчас существует только Roulette, функционально это пока простой возврат.

В будущем при смене игры настройки предыдущей игры не должны случайно применяться к новой игре.

## 12. Кнопка "Далее"

После корректных настроек:

`Далее`

должна перейти на следующий этап wizard.

Например маршрут:

`/manager/training/new/dealers`

Сам выбор дилеров сейчас НЕ реализовывать.

Если страницы ещё нет, можно создать временную заглушку:

```text
Выбор дилеров

Будет реализовано следующим этапом.

[ Назад ]
```

При этом wizard должен сохранить:

```text
gameType
+
gameConfig
```

## 13. Структура состояния wizard

После этого этапа состояние создания тренировки концептуально должно содержать:

```ts
{
  gameType: "ROULETTE",
  gameConfig: {
    ...полная копия RouletteSettings
  }
}
```

Пока здесь НЕ должно быть:

```ts
dealerIds
trainingTemplateId
assignments
spin
```

## 14. Валидация

Используй существующие правила валидации Settings Roulette.

Не придумывай отдельные правила для Training Wizard.

Если существующий Settings автоматически ограничивает значения или показывает ошибки — новая форма должна вести себя аналогично.

## 15. Не создавать TrainingTemplate

После нажатия `Далее` пока ничего окончательно не сохранять.

Не создавать:

* TrainingTemplate;
* TrainingAssignment;
* Training;
* Spin.

Сейчас мы только собираем данные wizard:

```text
gameType + gameConfig
```

## 16. Не трогать генерацию Roulette

Запрещено менять:

* Spin;
* генератор соседей;
* генератор серий;
* комплиты;
* цвет;
* кэш;
* выигрышный номер;
* выплаты;
* вопросы;
* звуки;
* racetrack;
* игровое поле.

Этот этап касается только переиспользования Settings.

## 17. Проверка нового экрана

Проверь сценарий:

1. Открываю кабинет руководителя.
2. Нажимаю `Создать тренировку`.
3. Выбираю Roulette.
4. Нажимаю `Далее`.
5. Открываются настройки Roulette.
6. Вижу тот же набор параметров, что в обычном Settings.
7. Значения по умолчанию совпадают.
8. Меняю несколько параметров.
9. Они сохраняются в состоянии wizard.
10. Нажимаю `Назад`.
11. Возвращаюсь к выбору игры.
12. Снова выбираю Roulette и нажимаю `Далее`.
13. Ранее введённые настройки сохранились.
14. Нажимаю `Далее`.
15. Открывается временный следующий экран выбора дилеров.
16. TrainingTemplate ещё не создан.

## 18. Regression-проверка существующего Settings

Обязательно отдельно проверь обычный существующий экран Roulette.

После вынесения общего компонента должны работать как раньше:

* открытие Settings;
* изменение всех параметров;
* сохранение/применение;
* Spin;
* генерация ставок;
* звуки.

Не допускается изменение игрового поведения.

## 19. После выполнения

Кратко сообщи:

1. какие файлы созданы;
2. какие файлы изменены;
3. какой компонент теперь отвечает за общую форму Roulette Settings;
4. какой тип настроек используется;
5. где находятся defaults;
6. каким образом отдельное состояние wizard не влияет на обычные Settings Roulette;
7. как хранится `gameType + gameConfig` между шагами;
8. куда ведёт `Далее`;
9. какие изменения понадобились в существующем Settings;
10. подтверждение, что генераторы, Spin и звуки не менялись.

Выполни только этот этап.

Не реализовывай пока:

* выбор нескольких дилеров;
* TrainingTemplate;
* TrainingAssignment;
* удаление тренировки;
* генерацию Spin.
