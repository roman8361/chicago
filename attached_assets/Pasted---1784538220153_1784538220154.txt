ИСПРАВЛЕНИЕ ЛОГИКИ ВЫБОРА НОМИНАЛОВ КЭША

Сейчас после добавления проверки диапазона приложение перестало позволять выбрать два допустимых номинала.

Нужно исправить логику так, чтобы ограничение диапазона и ограничение «максимум два выбранных номинала» работали независимо друг от друга.

---

ОСНОВНОЕ ПРАВИЛО

Пользователь может выбрать одновременно до двух номиналов, если каждый из них находится в диапазоне рулетки:

```text
minBet <= denomination <= maxBet

Границы диапазона включаются.

Это значит:

номинал, равный минимальной ставке, допустим;
номинал, равный максимальной ставке, допустим.

ПРИМЕР

Диапазон рулетки:

Минимум = 5
Максимум = 100

Номиналы:

5, 10, 25, 50, 100

Все эти номиналы допустимы.

Пользователь должен иметь возможность выбрать:

[5, 100]

Оба значения находятся внутри диапазона, включая его границы.

Нельзя запрещать выбор второго номинала только потому, что один номинал уже выбран.

ВАЖНОЕ УТОЧНЕНИЕ

Проверка диапазона должна блокировать только номиналы:

value < minBet

или:

value > maxBet

Не использовать:

value <= minBet

или:

value >= maxBet

Иначе номиналы, равные границам, ошибочно становятся недоступными.

Правильная проверка:

const isBelowMinimum = value < minBet;
const isAboveMaximum = value > maxBet;
const isAllowed = value >= minBet && value <= maxBet;

ПОРЯДОК ПРОВЕРОК

Обработчик должен работать в следующем порядке:

Определить, выбран ли номинал сейчас.
Если выбран — обработать снятие выбора.
Если не выбран — проверить попадание в диапазон.
Если номинал вне диапазона — показать сообщение и завершить обработку.
Если номинал допустимый — применить логику выбора максимум двух номиналов.
Если уже выбраны два допустимых номинала — заменить самый старый по FIFO.

ВАЖНО ДЛЯ УЖЕ ВЫБРАННЫХ НОМИНАЛОВ

Если номинал уже выбран, пользователь должен иметь возможность снять его.

Проверка диапазона не должна блокировать снятие уже выбранного значения.

Это особенно важно после изменения диапазона настроек.

Пример:

Выбрано: [100, 500]
Новый диапазон: 5–100

Номинал 500 теперь вне диапазона, но пользователь всё равно должен иметь возможность нажать на него и снять выбор.

Поэтому сначала проверять:

const isSelected = current.includes(value);

и только потом проверять диапазон для добавления нового номинала.

РЕКОМЕНДУЕМАЯ РЕАЛИЗАЦИЯ

const MAX_SELECTED_CASH_DENOMINATIONS = 2;

const toggleCashDenomination = (value: number) => {
  setSelectedCashDenominations(current => {
    const isSelected = current.includes(value);

    // Уже выбранный номинал можно снять.
    if (isSelected) {
      // Не разрешаем оставить список полностью пустым.
      if (current.length === 1) {
        return current;
      }

      return current.filter(item => item !== value);
    }

    // Проверка диапазона применяется только при добавлении.
    if (value < minBet) {
      showCashDenominationMessage(
        `Номинал ${value} меньше минимальной ставки рулетки — ${minBet}.`
      );

      return current;
    }

    if (value > maxBet) {
      showCashDenominationMessage(
        `Номинал ${value} превышает максимальную ставку рулетки — ${maxBet}.`
      );

      return current;
    }

    // Добавляем второй допустимый номинал.
    if (current.length < MAX_SELECTED_CASH_DENOMINATIONS) {
      return [...current, value];
    }

    // Если уже выбрано два номинала,
    // удаляем самый старый и добавляем новый.
    return [
      ...current.slice(1),
      value
    ];
  });
};

Названия состояния, переменных и функций адаптировать под текущий проект.

ПРИМЕР РАБОТЫ ДЛЯ ДИАПАЗОНА 5–100

Начальное состояние:

[5]

Пользователь нажимает 100:

[5, 100]

Пользователь нажимает 50:

[100, 50]

Удаляется самый старый номинал 5.

Пользователь нажимает 10:

[50, 10]

Удаляется самый старый номинал 100.

ПРИМЕР НЕДОПУСТИМОГО ВЫБОРА

Диапазон:

5–100

Выбрано:

[5, 100]

Пользователь нажимает 500:

выбранные значения не меняются;
результат остаётся:
[5, 100]
показывается сообщение:
Номинал 500 превышает максимальную ставку рулетки — 100.

Недопустимый клик не должен удалять номинал 5 по FIFO.

ПРОВЕРКА ВИЗУАЛЬНОГО СОСТОЯНИЯ

Для каждого номинала вычислять:

const isSelected = selectedCashDenominations.includes(value);

const isOutOfRange =
  value < minBet ||
  value > maxBet;

Номиналы, равные границам, должны считаться допустимыми:

value === minBet → допустим
value === maxBet → допустим

Пример:

minBet = 5
maxBet = 100

Тогда:

5   → допустим
10  → допустим
25  → допустим
50  → допустим
100 → допустим
500 → недопустим

НЕ БЛОКИРОВАТЬ ВТОРОЙ ДОПУСТИМЫЙ НОМИНАЛ

Не использовать условие вида:

const isDisabled =
  selectedCashDenominations.length >= 1;

или:

const isDisabled =
  selectedCashDenominations.length >= 2;

Для допустимых номиналов не должно быть disabled.

Даже когда выбраны два номинала, третий допустимый номинал должен оставаться кликабельным, потому что он запускает FIFO-замену.

ПРАВИЛЬНОЕ СОСТОЯНИЕ ЭЛЕМЕНТА

const isSelected = selectedCashDenominations.includes(value);
const isOutOfRange = value < minBet || value > maxBet;
<button
  type="button"
  aria-pressed={isSelected}
  aria-disabled={isOutOfRange && !isSelected}
  onClick={() => toggleCashDenomination(value)}
>
  {value}
</button>

Не устанавливать настоящий disabled, потому что:

недопустимый номинал должен показывать сообщение при клике;
допустимый третий номинал должен запускать FIFO-замену;
уже выбранный номинал должен позволять снять выбор.

ЕСЛИ НОМИНАЛЫ РИСУЮТСЯ ЧЕРЕЗ CHECKBOX

Не использовать:

disabled={isOutOfRange || selectedCashDenominations.length >= 2}

Это блокирует:

выбор второго допустимого номинала;
FIFO-замену;
показ сообщения.

Использовать управляемый компонент:

checked={isSelected}

а проверку выполнять только в onChange или onClick.

Пример:

<label
  className={isOutOfRange ? "cash-denomination--unavailable" : ""}
  onClick={event => {
    event.preventDefault();
    toggleCashDenomination(value);
  }}
>
  <input
    type="checkbox"
    checked={isSelected}
    readOnly
  />

  <span>{value}</span>
</label>

ПРОВЕРКА ИЗМЕНЕНИЯ ДИАПАЗОНА

После изменения minBet или maxBet проверить уже выбранные значения:

const validSelected = current.filter(
  value => value >= minBet && value <= maxBet
);

Но не сокращать корректный набор из двух значений до одного.

Пример:

Диапазон: 5–100
Выбрано: [5, 100]

После проверки должно остаться:

[5, 100]

Не должно превращаться в:

[5]

или:

[100]

ЕСЛИ ПОСЛЕ ИЗМЕНЕНИЯ ДИАПАЗОНА НЕТ ВЫБРАННЫХ

Выбрать первый доступный номинал, который входит в диапазон:

const firstAllowed = availableCashDenominations.find(
  value => value >= minBet && value <= maxBet
);

Если допустимых номиналов несколько, не выбирать автоматически два. Достаточно выбрать один.

КРИТЕРИИ ГОТОВНОСТИ

При диапазоне 5–100 можно выбрать номинал 5.
При диапазоне 5–100 можно выбрать номинал 100.
При диапазоне 5–100 можно одновременно выбрать [5, 100].
Границы диапазона проверяются включительно.
Второй допустимый номинал не блокируется.
Третий допустимый номинал запускает FIFO-замену.
Недопустимый номинал не изменяет текущий выбор.
При клике на недопустимый номинал показывается сообщение.
Уже выбранный номинал можно снять.
Проверка диапазона не сокращает корректный набор из двух выбранных номиналов.
Не используется настоящий disabled, который блокирует клики.
Генерация кэш-фишек продолжает использовать до двух выбранных допустимых номиналов.
