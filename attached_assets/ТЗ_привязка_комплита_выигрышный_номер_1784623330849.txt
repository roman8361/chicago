ЗАДАЧА

Изменить логику генерации ставок «Комплит» так, чтобы при наличии хотя бы одного комплита минимум один из сгенерированных комплитов обязательно пересекался с выигрышным номером.

---

ОСНОВНОЕ ПРАВИЛО

Если в текущем спине сгенерирована хотя бы одна ставка «Комплит», то выигрышный номер должен входить хотя бы в одну ставочную позицию минимум одного комплита.

Под «входит» понимается любое касание выигрышного номера ставками, входящими в комплит:

- straight;
- split;
- street;
- corner;
- six-line;
- другие позиции, описанные в `completeBets` для выбранного номера.

Необязательно, чтобы выигрышный номер совпадал с центральным номером комплита.

Достаточно, чтобы хотя бы одна ставка из состава комплита покрывала выигрышный номер.

---

ПРИМЕРЫ

Если установлен комплит номера 5, выигрышным может быть:

- 5 — через straight;
- 2 — через split, street или corner;
- 4;
- 6;
- 8;
- любой другой номер, который покрывается хотя бы одной позицией из `completeBets[5]`.

Главное условие:

```ts
completeBetPositions.some(position =>
  position.numbers.includes(winningNumber)
)

НЕСКОЛЬКО КОМПЛИТОВ

Если в настройках указано несколько комплитов, например 2 или 3:

минимум один комплит обязательно должен пересекаться с выигрышным номером;
остальные комплиты могут проиграть;
остальные комплиты также могут пересекаться с выигрышным номером;
количество выигравших комплитов должно определяться случайно.

Допустимые варианты для трёх комплитов:

сыграл только один;
сыграли два;
сыграли все три.

Недопустимый вариант:

не сыграл ни один комплит.

РЕКОМЕНДУЕМАЯ ПОСЛЕДОВАТЕЛЬНОСТЬ ГЕНЕРАЦИИ

Определить количество комплитов из настроек.
Сгенерировать уникальные номера комплитов по существующим правилам.
Случайно определить, сколько комплитов должны пересекаться с выигрышным номером:
const winningCompleteCount = randomInt(1, generatedCompletes.length);
Случайно выбрать из сгенерированных комплитов указанное количество выигрышных.
Найти номера, которые покрываются выбранными комплитами.
Выбрать выигрышный номер из допустимого пересечения.
Выполнить итоговую проверку:
const winningCompletes = generatedCompletes.filter(complete =>
  completeTouchesNumber(complete.number, winningNumber)
);

if (winningCompletes.length === 0) {
  // скорректировать выигрышный номер либо один комплит
}

ВАЖНОЕ УТОЧНЕНИЕ ПО СЛУЧАЙНОСТИ

Нельзя всегда выбирать выигрышным центральный номер первого комплита.

Необходимо случайно выбирать:

какой именно комплит сыграет;
сколько комплитов сыграет;
какой ставочной позицией комплит коснётся выигрышного номера;
сам выигрышный номер из множества допустимых номеров.

Это обеспечит разные сценарии:

выигрыш через straight;
выигрыш через split;
выигрыш через street;
выигрыш через corner;
выигрыш через six-line.

ФУНКЦИЯ ПРОВЕРКИ ПЕРЕСЕЧЕНИЯ

Рекомендуется реализовать отдельную функцию:

function completeTouchesNumber(
  completeNumber: number,
  winningNumber: number,
  rules: RouletteRules
): boolean {
  const completePositions = rules.completeBets[completeNumber];

  if (!completePositions) {
    return false;
  }

  return completePositions.some(position =>
    position.numbers.includes(winningNumber)
  );
}

Формат чтения position.numbers адаптировать под фактическую структуру rouletteRules.json.

Если позиции хранятся строками, сначала преобразовать их в массив покрываемых номеров.

ИСТОЧНИК ДАННЫХ

Для определения состава комплита использовать только:

rouletteRules.completeBets

Не создавать отдельные захардкоженные таблицы пересечений.

Все номера, которых касается комплит, должны вычисляться из фактических ставок, входящих в его состав.

БОЛЕЕ НАДЁЖНЫЙ ВАРИАНТ АЛГОРИТМА

Чтобы не нарушить другие правила генерации, рекомендуется сначала генерировать комплиты, а затем выбирать выигрышный номер.

Пример:

const generatedCompletes = generateCompletes(settings, rules);

let winningNumber = generateRandomWinningNumber();

if (generatedCompletes.length > 0) {
  const requiredWinningCount = randomInt(
    1,
    generatedCompletes.length
  );

  winningNumber = chooseWinningNumberForCompletes(
    generatedCompletes,
    requiredWinningCount,
    rules
  );
}

Функция chooseWinningNumberForCompletes должна:

сформировать для каждого комплита множество покрываемых номеров;
найти номера, которые дают нужное количество выигравших комплитов;
случайно выбрать один из подходящих номеров;
если номеров для выбранного количества нет — попробовать другое количество;
гарантировать, что итоговое количество выигравших комплитов не меньше одного.

УЧЁТ РЕАЛЬНЫХ ПЕРЕСЕЧЕНИЙ

Не каждую случайно выбранную комбинацию комплитов можно заставить выиграть одним номером.

Например, два комплита могут не иметь общего покрываемого номера.

Поэтому нельзя сначала жёстко выбрать два выигрышных комплита, а затем без проверки искать общий номер.

Нужно вычислить карту:

winningNumber -> список комплитов, которые он задевает

Пример:

const candidates = Array.from({ length: 37 }, (_, number) => {
  const touchedCompleteIndexes = generatedCompletes
    .map((complete, index) =>
      completeTouchesNumber(complete.number, number, rules)
        ? index
        : null
    )
    .filter((index): index is number => index !== null);

  return {
    number,
    touchedCompleteIndexes,
  };
});

Затем оставить только варианты, где сыграл минимум один комплит:

const validCandidates = candidates.filter(
  candidate => candidate.touchedCompleteIndexes.length > 0
);

После этого можно случайно выбрать вариант:

const selectedCandidate = randomItem(validCandidates);
const winningNumber = selectedCandidate.number;

Такой подход естественно создаёт случайное количество выигравших комплитов:

иногда один;
иногда несколько;
иногда все.

РЕКОМЕНДУЕМЫЙ ИТОГОВЫЙ ПОДХОД

Не задавать количество выигрышных комплитов заранее.

Лучше:

сгенерировать комплиты;
для каждого номера 0–36 определить, сколько комплитов он задевает;
исключить номера, которые не задевают ни одного комплита;
случайно выбрать выигрышный номер из оставшихся.

Пример:

function chooseWinningNumberWithCompleteHit(
  completes: GeneratedComplete[],
  rules: RouletteRules
): number {
  const candidates = Array.from({ length: 37 }, (_, number) => ({
    number,
    hitCount: completes.filter(complete =>
      completeTouchesNumber(complete.number, number, rules)
    ).length,
  })).filter(candidate => candidate.hitCount > 0);

  return randomItem(candidates).number;
}

Этот вариант автоматически выполняет все условия:

хотя бы один комплит обязательно сыграет;
могут сыграть несколько комплитов;
количество сыгравших комплитов остаётся случайным.

НЕ ИЗМЕНЯТЬ

количество комплитов из настроек;
правило уникальности номеров комплитов;
расчёт количества фишек комплита;
формирование суммы комплита;
округление суммы до кратности;
визуальное отображение комплита;
состав ставок completeBets;
расчёт выплаты;
правила генерации серий, соседей и обычных ставок.

ИТОГОВАЯ ВАЛИДАЦИЯ ПОСЛЕ ГЕНЕРАЦИИ

После полного формирования спина обязательно выполнить проверку:

if (
  generatedCompletes.length > 0 &&
  !generatedCompletes.some(complete =>
    completeTouchesNumber(
      complete.number,
      winningNumber,
      rouletteRules
    )
  )
) {
  winningNumber = chooseWinningNumberWithCompleteHit(
    generatedCompletes,
    rouletteRules
  );
}

Не перегенерировать весь спин.

При невалидном результате необходимо заменить только выигрышный номер либо один из комплитов.

КРИТЕРИИ ГОТОВНОСТИ

Если комплитов нет, выигрышный номер формируется по прежней логике.
Если есть хотя бы один комплит, минимум один комплит обязательно касается выигрышного номера.
При нескольких комплитах может выиграть один, несколько или все.
Количество выигравших комплитов определяется случайно.
Выигрыш возможен через любую ставочную позицию комплита, а не только через straight.
Для определения пересечений используется rouletteRules.completeBets.
Ни один спин с комплитами не заканчивается ситуацией, когда проиграли все комплиты.
Остальная логика генерации и расчётов не изменена.
