Продолжаем развитие Roulette Dealer Trainer.

Сейчас уже есть:

* TrainingTemplate;
* TrainingAssignment;
* RouletteExercise;
* TrainingResult;
* кабинет дилера;
* запуск аттестации;
* статус `CREATED → IN_PROGRESS`;
* startedAt;
* сохранённый RouletteExercise;
* существующие вопросы Roulette;
* завершение аттестации;
* статус `COMPLETED`;
* completedAt;
* итоговый TrainingResult.

Следующий этап:

# Сохранение промежуточного прогресса аттестации

Нужно сделать так, чтобы дилер мог:

1. начать аттестацию;
2. ответить на часть вопросов;
3. выйти из аттестации или обновить страницу;
4. нажать `Продолжить аттестацию`;
5. продолжить с того же места.

Уже данные ответы не должны теряться.

---

# 1. Главный сценарий

Пример:

```text id="kx7t3p"
10 вопросов

Дилер ответил:
1
2
3
4

Сейчас находится на вопросе 5

↓
refresh / выход
↓
Продолжить аттестацию
↓

вопросы 1–4 уже сохранены
открывается вопрос 5
```

Нельзя начинать опрос заново.

---

# 2. Создать отдельную сущность TrainingProgress

Не хранить промежуточное состояние внутри:

* TrainingTemplate;
* Dealer;
* RouletteExercise;
* TrainingResult.

Создать отдельную модель.

Концептуально:

```ts id="gfdi4n"
type TrainingProgress = {
  assignmentId: string;

  currentQuestionIndex: number;

  answers: TrainingAnswer[];

  updatedAt: string;
};
```

Если существующая модель вопросов требует дополнительных полей — адаптировать.

Главное:

Progress принадлежит конкретному `TrainingAssignment`.

---

# 3. Один Assignment — один Progress

Правило:

```text id="lh1r0g"
1 TrainingAssignment
=
0 или 1 TrainingProgress
```

Пока аттестация не начата:

Progress может отсутствовать.

После начала/первого ответа появляется Progress.

---

# 4. Не создавать второй формат ответов

Если уже существует:

`TrainingAnswer`

для финального TrainingResult — переиспользовать тот же формат для Progress.

Не создавать отдельно:

```text id="ox7tbq"
ProgressAnswer
ResultAnswer
```

с одинаковыми полями.

Желательно:

```text id="akj6fz"
TrainingProgress.answers
```

и:

```text id="295hzn"
TrainingResult.answers
```

используют один `TrainingAnswer`.

---

# 5. Когда сохранять progress

После каждого подтверждённого ответа дилера:

1. существующая Roulette проверяет ответ;
2. формируется TrainingAnswer;
3. TrainingAnswer добавляется в Progress;
4. обновляется currentQuestionIndex;
5. обновляется updatedAt;
6. Progress сохраняется.

Не сохранять сырой ввод до проверки, если текущий flow вопросов сначала требует нажать `Проверить`.

---

# 6. Не менять существующую проверку ответов

Правильность ответа по-прежнему определяет существующая Roulette.

Autosave только сохраняет результат уже выполненной проверки.

Не создавать новую validation/checking logic.

---

# 7. Что означает currentQuestionIndex

Нужно использовать существующую индексацию вопросов.

Например:

```text id="yqnsz8"
0 = первый вопрос
1 = второй вопрос
...
```

или текущий подход проекта.

Не смешивать zero-based и one-based индексы.

Если дилер завершил вопрос №4 и следующим должен увидеть №5, после сохранения index должен указывать именно на следующий незавершённый вопрос.

---

# 8. Восстановление при открытии /play

При:

`IN_PROGRESS → Продолжить аттестацию`

страница должна:

1. загрузить Assignment;
2. загрузить сохранённый RouletteExercise;
3. загрузить TrainingProgress по assignmentId;
4. восстановить сохранённые answers;
5. восстановить currentQuestionIndex;
6. открыть существующий UI вопросов на нужном месте.

Новый Spin не запускать.

---

# 9. Refresh страницы /play

Если дилер уже находится:

`/dealer/attestations/:assignmentId/play`

и делает refresh:

* status остаётся IN_PROGRESS;
* Spin-анимация повторно не запускается;
* RouletteExercise остаётся тем же;
* TrainingProgress читается из storage;
* уже отвеченные вопросы восстанавливаются;
* открывается текущий незавершённый вопрос.

---

# 10. Уже отвеченные вопросы нельзя проходить повторно

Если Progress содержит ответы на вопросы 1–4, при продолжении нельзя снова требовать ответы 1–4.

Flow должен продолжиться с первого вопроса без сохранённого финального ответа.

---

# 11. Не менять RouletteExercise

Progress никак не изменяет:

* winningNumber;
* ставки;
* series;
* neighbors;
* complete;
* color;
* cash;
* исходные правильные данные вопросов.

Exercise остаётся immutable snapshot задания.

---

# 12. localStorage

Пока использовать отдельный key.

Например:

`roulette-trainer-training-progress`

или naming style проекта.

Создать storage-модуль.

---

# 13. Минимальный API progress storage

Например:

```ts id="fhyha1"
getTrainingProgresses()

getTrainingProgressByAssignmentId(
  assignmentId
)

saveTrainingProgress(
  progress
)

deleteTrainingProgressByAssignmentId(
  assignmentId
)
```

Для Progress удобно использовать upsert-поведение:

если уже существует для assignmentId — обновить;
если нет — создать.

---

# 14. Не работать с localStorage прямо из большого Roulette UI

Не размазывать:

```ts id="bkhi2o"
localStorage.setItem(...)
```

по question handlers.

Использовать отдельный storage/service.

---

# 15. updatedAt

Каждый раз при сохранении progress обновлять:

`updatedAt`.

Хранить полный timestamp.

В UI пока отображать его необязательно.

---

# 16. Первый progress

Допустим дилер нажал `Начать аттестацию`, но ещё не ответил ни на один вопрос.

Можно:

* создать пустой Progress сразу при старте;
  или
* создать при первом подтверждённом ответе.

Выбери более простой вариант для текущей архитектуры.

Главное — дальнейшее восстановление должно работать корректно.

---

# 17. Завершение аттестации

Когда дилер дошёл до конца и нажал:

`Завершить аттестацию`

использовать сохранённые ответы Progress как основу для TrainingResult.

Концептуально:

```text id="92tlxm"
TrainingProgress.answers
        ↓
создать immutable TrainingResult
        ↓
Assignment → COMPLETED
        ↓
удалить TrainingProgress
```

---

# 18. После COMPLETED progress удалить

После успешного создания TrainingResult удалить:

`TrainingProgress`

для этого assignmentId.

Почему:

* Result уже является финальным snapshot;
* Progress больше не нужен;
* нельзя иметь два источника истины после завершения.

---

# 19. Сначала сохранить Result, потом удалять Progress

Правильный порядок:

```text id="ff8rgs"
получить Progress
↓
создать TrainingResult
↓
сохранить TrainingResult
↓
Assignment → COMPLETED
↓
удалить Progress
```

Не удалять Progress раньше успешного формирования Result.

---

# 20. Если завершение не удалось

Если TrainingResult не удалось сформировать/сохранить:

* Assignment оставить IN_PROGRESS;
* Progress не удалять;
* дилер должен иметь возможность продолжить.

---

# 21. Если Progress отсутствует у IN_PROGRESS

В старых данных уже могут существовать:

```text id="s0m61t"
Assignment = IN_PROGRESS
Progress отсутствует
```

Приложение не должно падать.

Если нет сохранённых ответов, можно безопасно начать блок вопросов с первого вопроса, используя тот же RouletteExercise.

Но не запускать новый Spin.

---

# 22. Если Progress повреждён

Например:

`currentQuestionIndex` выходит за количество вопросов.

Не допускать runtime error.

Можно нормализовать:

```text id="k5chg1"
0 <= currentQuestionIndex <= questions.length
```

Если данные явно некорректны — безопасно восстановить первый незавершённый вопрос из answers.

---

# 23. Надёжнее определять позицию по answers

Если возможно, не доверять только `currentQuestionIndex`.

При восстановлении проверить:

```text id="wqhl6x"
answers.length
+
currentQuestionIndex
```

и согласовать их с фактическим количеством вопросов.

Не нужно строить сложный recovery engine.

Просто не позволять индексу указывать на уже завершённый или несуществующий вопрос.

---

# 24. Не перезаписывать уже сохранённый ответ

Если вопрос уже присутствует в Progress.answers, повторное открытие страницы не должно добавлять его второй раз.

Использовать устойчивый:

`questionId`

или другой существующий стабильный идентификатор.

Если current question model не имеет id, сначала аккуратно определить стабильный способ идентификации.

---

# 25. Порядок answers

Сохранять ответы в порядке прохождения.

Это важно для будущего отчёта руководителя.

---

# 26. Выход из игрового экрана

При:

`Назад к аттестации`

никакие ответы не терять.

Поскольку они сохраняются после каждой проверки, отдельное действие `Сохранить` дилеру не нужно.

---

# 27. Закрытие вкладки

Так как Progress сохраняется сразу после ответа, закрытие вкладки после последнего подтверждённого ответа не должно потерять этот ответ.

Не нужно делать beforeunload hacks.

---

# 28. Не сохранять состояние анимации

TrainingProgress не должен содержать:

* wheel rotation;
* animationPlayed;
* audio position;
* UI transitions.

Только учебный прогресс по вопросам.

---

# 29. Не хранить settings

TrainingProgress не должен дублировать:

`TrainingTemplate.config`.

---

# 30. Не хранить Exercise

TrainingProgress не должен дублировать:

`RouletteExercise`.

Только ссылка через assignmentId.

---

# 31. PRACTICE режим

В обычном:

`/roulette`

Progress не создавать.

Autosave относится только к:

`ATTESTATION`.

Обычная тренировочная Roulette должна оставаться stateless в этом смысле.

---

# 32. Несколько дилеров

У каждого Assignment свой Progress.

Например:

```text id="m0cwsb"
Иванов
Assignment A
Progress A
4/10 вопросов

Петров
Assignment B
Progress B
7/10 вопросов
```

Они полностью независимы.

---

# 33. Один дилер в двух аттестациях

Даже если dealerId одинаковый:

```text id="0hxbau"
Assignment A
Assignment B
```

Progress должен быть отдельным, потому что связь идёт по:

`assignmentId`.

Не хранить progress по dealerId.

---

# 34. Удаление Assignment CREATED

CREATED обычно ещё не имеет Progress.

Но если по каким-то причинам Progress существует при удалении Assignment, удалить его вместе с Assignment.

Не оставлять orphan progress.

---

# 35. Удаление всей аттестации

При удалении Template/Assignments также удалить связанные TrainingProgress.

Не затрагивать Progress других аттестаций.

---

# 36. Изменение настроек до старта

Если все Assignment CREATED и Exercise пересоздаются после изменения config:

TrainingProgress у таких Assignment быть не должно.

Если существует старый пустой progress — удалить его вместе с пересозданием Exercise.

---

# 37. UI индикатор

На странице дилера для IN_PROGRESS можно дополнительно показать:

```text id="2gu4k2"
Прогресс: 4 из 10
```

только если это легко получить из TrainingProgress.

Это полезно, но не обязательно для основной реализации.

Если добавляешь — totalQuestions брать из фактического набора вопросов/Exercise, а answered count из Progress.answers.

---

# 38. Проверка основного сценария

Создать аттестацию с 10 вопросами.

1. Иванов начинает.
2. Assignment → IN_PROGRESS.
3. Отвечает на вопросы 1–4.
4. Проверить storage:

   * Progress существует;
   * 4 answers;
   * currentQuestionIndex указывает на 5-й вопрос.
5. Нажать `Назад`.
6. Открыть `Продолжить аттестацию`.
7. Открывается тот же Exercise.
8. Spin-анимация не запускается.
9. Открывается вопрос 5.
10. Ответы 1–4 не потеряны.

---

# 39. Проверка refresh

После вопроса 6 выполнить refresh.

Ожидается:

* Assignment IN_PROGRESS;
* Exercise тот же;
* Progress сохранён;
* уже отвеченные вопросы не задаются повторно;
* открывается вопрос 7.

---

# 40. Проверка завершения

Ответить на все вопросы.

Нажать:

`Завершить аттестацию`.

Проверить:

* TrainingResult создан;
* Result содержит все ответы Progress;
* Assignment → COMPLETED;
* completedAt записан;
* TrainingProgress удалён;
* Result page работает.

---

# 41. Проверка двух дилеров

Иванов отвечает 3 вопроса.

Петров отвечает 5.

Проверить:

```text id="rr3eyj"
Progress Иванова
!=
Progress Петрова
```

Продолжение каждого открывает его собственный вопрос.

---

# 42. Проверка PRACTICE

Открыть `/roulette`.

Сделать Spin и пройти вопросы.

Убедиться:

* TrainingProgress не создаётся;
* TrainingAssignment не используется;
* обычная логика Roulette работает как раньше.

---

# 43. Не менять

Не менять:

* генерацию ставок;
* winningNumber;
* Spin-анимацию;
* звук;
* Settings;
* RouletteExercise;
* правильные ответы;
* порядок существующих вопросов.

Этот этап только про сохранение и восстановление прогресса.
