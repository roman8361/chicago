Продолжаем развитие существующего Roulette Dealer Trainer небольшими этапами.

Первый этап уже выполнен:

* есть `/login`;
* есть `/manager`;
* есть `/dealer`;
* существующая Roulette доступна из новых экранов;
* Roulette, её игровая логика и звуки работают как раньше.

Сейчас нужно выполнить ТОЛЬКО второй этап — добавить минимальный список дилеров в личный кабинет руководителя.

## Главная задача

На странице `/manager` добавить раздел:

**Дилеры**

Пока список должен быть тестовым и храниться только во frontend.

Backend, база данных, localStorage и настоящие пользователи на этом этапе НЕ нужны.

## 1. Тестовые данные

Создай небольшой список дилеров, например:

* Иванов Иван Иванович
* Петров Пётр Сергеевич
* Сидоров Алексей Андреевич

Каждый дилер должен иметь отдельный уникальный `id`.

Например структура данных:

```ts
type Dealer = {
  id: string;
  fullName: string;
};
```

Тестовые данные не нужно размещать непосредственно внутри JSX, если это ухудшает структуру кода.

Можно вынести их в отдельный файл, например:

```text
data/mockDealers.ts
```

или использовать подход, который лучше соответствует текущей структуре проекта.

## 2. Экран руководителя

На `/manager` оставить заголовок:

**Личный кабинет руководителя**

Ниже добавить блок:

**Дилеры**

В нём показать список тестовых дилеров.

Пример:

```text
Личный кабинет руководителя

Дилеры

Иванов Иван Иванович
Петров Пётр Сергеевич
Сидоров Алексей Андреевич
```

Список должен выглядеть аккуратно и соответствовать существующему стилю приложения.

Не нужно делать сложный дизайн.

## 3. Карточка/строка дилера

Каждый дилер должен отображаться отдельной строкой или небольшой карточкой.

Пока достаточно показывать только:

* ФИО.

Можно подготовить строку дилера так, чтобы позже туда можно было добавить:

* статус;
* количество тренировок;
* кнопку открытия;
* редактирование.

Но сами эти функции сейчас НЕ реализовывать.

Если есть смысл, можно создать переиспользуемый компонент:

```text
DealerList
DealerListItem
```

Но не нужно создавать лишнюю архитектуру ради трёх строк.

## 4. Кнопка добавления

В интерфейсе добавить кнопку:

**+ Добавить дилера**

ВАЖНО:

На этом этапе кнопка может быть неактивной или пока ничего не делать.

Не создавать форму добавления дилера.

Форма будет отдельным следующим этапом.

## 5. Существующая Roulette

Сохранить текущую кнопку перехода к Roulette, если она была добавлена на первом этапе.

Ничего в существующей Roulette не менять.

Не менять:

* Spin;
* генерацию ставок;
* настройки;
* racetrack;
* игровое поле;
* вопросы;
* звуки;
* дизайн Roulette.

## 6. DealerPage

Страницу `/dealer` сейчас не развивать.

Она должна остаться в том состоянии, в котором была после первого этапа.

## 7. Что сейчас НЕ делать

Не нужно:

* создавать форму добавления дилера;
* удалять дилеров;
* редактировать дилеров;
* создавать страницу конкретного дилера;
* создавать логины;
* генерировать пароли;
* создавать роли;
* делать авторизацию;
* использовать localStorage;
* создавать backend;
* создавать API;
* подключать PostgreSQL;
* создавать тренировки;
* переносить настройки Roulette;
* рефакторить существующую Roulette.

Это будет сделано отдельными следующими этапами.

## 8. Архитектурное требование

Сущность дилера сейчас должна быть отдельной от будущего пользователя системы.

То есть сейчас Dealer — это бизнес-сущность дилера:

```ts
Dealer {
  id;
  fullName;
}
```

Не нужно сейчас добавлять в неё:

```text
login
password
role
```

Позже учётная запись пользователя будет связана с дилером отдельно.

Это позволит в будущем нормально реализовать:

```text
User
  ├── roles
  └── Dealer profile
```

и поддержать пользователей с разными наборами ролей.

## 9. Проверка результата

После изменений должно быть:

1. `/login` работает как после первого этапа.
2. `/dealer` работает как после первого этапа.
3. На `/manager` отображается список из трёх тестовых дилеров.
4. Есть кнопка `+ Добавить дилера`.
5. Существующая Roulette по-прежнему открывается.
6. Roulette и звуки работают без изменений.
7. Не появилось backend/database/auth функциональности.
