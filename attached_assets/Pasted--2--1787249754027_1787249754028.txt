Необходимо доработать существующую генерацию для случая, когда в настройках выбрано **2 комплита номера**.

ВАЖНО: новое требование должно **дополнить существующую реализацию**, а не заменить её.

Сейчас уже корректно работают:

* один комплит номера — задевает выигрышный номер;
* комплит дюжины — задевает выигрышный номер;
* комплит дюжины + один комплит номера — работают по существующим ограничениям.

Эту логику не менять.

Новая логика применяется только для случая:

**количество комплитов номера = 2.**

## Основное требование

При генерации двух комплитов номера должны выполняться одновременно следующие условия:

1. Оба комплита должны пересекаться с выигрышным номером.

2. Два комплита должны пересекаться между собой хотя бы одной общей физической позицией комплита.

3. По возможности два комплита должны иметь **разное значение «по сколько играет комплит»** после применения всех действующих правил:

   * min/max рулетки;
   * диапазона генерации;
   * кратности комплитов;
   * округления;
   * ограничения максимальной ставкой.

При этом первые два условия являются обязательными всегда.

Разное значение «по сколько» обязательно только тогда, когда текущие настройки реально позволяют получить минимум два разных допустимых значения.

---

## 1. Пересечение с выигрышным номером

Сначала сохранить уже существующее правило:

каждый из двух комплитов должен иметь хотя бы одно выигрышное касание с выпавшим номером.

То есть после генерации должно быть:

* первый комплит задевает winningNumber;
* второй комплит задевает winningNumber.

Нельзя ради разного значения ставки выбрать второй комплит, который перестаёт пересекаться с выигрышным номером.

---

## 2. Пересечение комплитов между собой

Кроме пересечения с выигрышным номером два выбранных комплита должны пересекаться между собой.

Под пересечением понимать наличие хотя бы одной общей физической позиции в их раскладах:

* Straight;
* Split;
* Street;
* Corner;
* Six Line.

Использовать существующие карты комплитов.

Не определять пересечение просто по близости номеров.

Пример:

комплит №1 и комплит №4 имеют общие физические позиции и поэтому могут быть выбраны совместно.

После выбора первого комплита список кандидатов второго должен быть ограничен только комплитами, которые:

* пересекаются с выигрышным номером;
* пересекаются с первым комплитом.

---

## 3. Разные значения «по сколько играет комплит»

После выбора двух допустимых комплитов необходимо генерировать их суммы по существующим правилам.

Но дополнительно нужно стремиться получить разные значения:

`playPerUnitComplete1 != playPerUnitComplete2`

Например:

кратность комплитов:

10.

Допустимые значения после всех ограничений:

20, 30, 40, 50, 60.

Тогда нельзя без необходимости получить:

* первый комплит по 40;
* второй комплит по 40.

Нужно выбрать другое допустимое значение для второго, например:

* первый по 40;
* второй по 50.

или:

* первый по 30;
* второй по 60.

Конкретные значения остаются случайными.

---

## 4. Сначала определить, возможно ли получить разные значения

Нельзя просто несколько раз случайно пытаться получить другое значение и затем считать, что одинаковая ставка допустима.

Сначала необходимо определить набор реально допустимых значений «по сколько» для текущих настроек.

Этот набор должен учитывать существующие ограничения:

* минимум рулетки;
* максимум рулетки;
* диапазон генерации комплита;
* настройку «Кратность комплитов»;
* округление по кратности;
* максимальную ставку.

После применения всех правил получить набор допустимых значений.

### Если допустимых значений два или больше

Разные значения для двух комплитов обязательны.

Например:

допустимы:

20, 40, 60, 80.

Первому случайно выбрано:

40.

Для второго выбирать случайно только из:

20, 60, 80.

Значение 40 исключается для второго комплита.

### Если допустимо только одно значение

Одинаковое значение разрешается.

Например:

из-за текущих:

* min/max;
* кратности;
* ограничений генерации

единственное допустимое значение:

100.

Тогда:

* первый комплит играет по 100;
* второй комплит играет по 100.

Это корректное поведение.

Не считать генерацию ошибочной и не запускать бесконечные повторные попытки.

---

## 5. Пример, когда значения должны отличаться

Условия:

* рулетка 1–100;
* кратность комплитов — 10;
* действующий диапазон генерации позволяет получить:
  20, 30, 40, 50, 60, 70, 80.

Выбраны два совместимых комплита:

№1 и №4.

Оба:

* задевают выигрышный номер;
* пересекаются между собой.

Первый комплит случайно получил:

50.

Для второго значение 50 больше не является допустимым кандидатом, потому что существуют другие варианты.

Например второй получает:

70.

Итог:

* комплит №1 — по 50;
* комплит №4 — по 70.

---

## 6. Пример, когда одинаковое значение разрешено

Условия подобраны так, что после применения:

* максимума рулетки;
* минимума;
* диапазона;
* кратности комплитов;
* округления

остаётся только одно допустимое значение:

100.

Тогда два комплита могут играть:

* первый по 100;
* второй по 100.

Здесь нельзя искусственно создавать второе значение или нарушать другие ограничения.

Совпадение допустимо, потому что получить разные значения математически невозможно.

---

## 7. Приоритет требований

Для двух комплитов использовать следующий приоритет:

### Приоритет 1 — обязательный

Оба комплита пересекаются с выигрышным номером.

### Приоритет 2 — обязательный

Комплиты пересекаются между собой.

### Приоритет 3 — обязательный при наличии выбора

Значения «по сколько играет» разные.

### Исключение

Если после применения текущих настроек существует только одно допустимое значение «по сколько», разрешить одинаковые значения.

Нельзя ради разной ставки нарушать первые два требования.

---

## 8. Последовательность генерации

Рекомендуемый порядок:

1. Получить выигрышный номер по существующим правилам.

2. Сформировать кандидатов для первого комплита, которые задевают выигрышный номер.

3. Случайно выбрать первый комплит.

4. Сформировать кандидатов для второго комплита, которые одновременно:

   * задевают выигрышный номер;
   * пересекаются с первым комплитом.

5. Случайно выбрать второй комплит.

6. Определить допустимые значения ставки для первого и второго комплита с учётом текущих настроек.

7. Случайно определить значение первого комплита.

8. Для второго:

   * если существует хотя бы одно другое допустимое значение — исключить значение первого и выбрать другое;
   * если другого допустимого значения нет — разрешить то же значение.

9. Провести итоговую валидацию.

---

## 9. Итоговая валидация

После генерации двух комплитов проверить:

* количество комплитов = 2;
* номера комплитов разные;
* первый задевает выигрышный номер;
* второй задевает выигрышный номер;
* комплиты пересекаются между собой;
* ставки каждого удовлетворяют существующим правилам генерации;
* если доступно минимум два значения «по сколько» — значения комплитов различаются;
* если доступно только одно значение — одинаковые значения допустимы.

Если нарушено обязательное условие выбора номеров комплитов, повторить соответствующую часть генерации.

---

## 10. Взаимодействие с другими требованиями

Не ломать существующие зависимости выигрышного номера от:

* серий;
* соседей;
* комплита дюжины;
* других уже реализованных ограничений.

Если одновременно присутствуют серии или соседи, выигрышный номер по-прежнему должен удовлетворять их обязательным правилам.

Новое правило двух комплитов добавляется к общему набору ограничений.

Не выбирать новый winningNumber отдельно внутри генератора двух комплитов, если он уже определён общим алгоритмом.

---

## 11. Что нельзя менять

Не менять:

* генерацию одного комплита;
* генерацию комплита дюжины;
* существующее правило касания выигрышного номера;
* алгоритм расчёта суммы комплита;
* диапазон генерации ставки;
* кратность комплитов;
* алгоритмы экзаменационных вопросов;
* расчёты сдачи;
* выплаты.

Нужно только дополнить генерацию для случая двух комплитов.

---

## 12. Обязательные тесты

Проверить минимум:

1. Два комплита всегда задевают выигрышный номер.

2. Два комплита всегда пересекаются между собой.

3. При наличии нескольких допустимых значений «по сколько» значения комплитов различаются.

4. Первый по 40, при наличии 20/30/50/60 второй не может снова получить 40.

5. При единственном допустимом значении оба комплита могут получить одинаковую ставку.

6. Одинаковая ставка не считается ошибкой, если другого допустимого значения нет.

7. Не возникает бесконечной повторной генерации при невозможности получить разные значения.

8. Разница ставок не достигается за счёт нарушения максимума рулетки.

9. Разница ставок не достигается за счёт нарушения кратности.

10. Разница ставок не достигается за счёт нарушения диапазона генерации.

11. Серии + два комплита — сохраняются требования серий.

12. Соседи + два комплита — сохраняются требования соседей.

13. Серии + соседи + два комплита — все обязательные ограничения выполняются совместно.

После выполнения кратко сообщи:

* как выбирается второй комплит;
* как проверяется пересечение двух комплитов;
* как определяется набор допустимых значений «по сколько»;
* когда разные значения обязательны;
* в каком случае одинаковые значения разрешены;
* подтверждение, что предыдущая логика генерации не была заменена, а только дополнена.
