РАСПОЛОЖЕНИЕ ВОПРОСА

Новый вопрос должен идти сразу после вопроса:

«Посчитайте сдачу с пересечений ставок на треке со ставками на поле без учета ставок «комплит».»

Нумерация должна оставаться динамической.

Не хардкодить номер вопроса.

Если предыдущие условные вопросы были пропущены, новый вопрос должен получить следующий фактический порядковый номер без разрывов.

---

УСЛОВИЕ ПОЯВЛЕНИЯ

Вопрос показывать только при одновременном выполнении двух условий:

1. В текущем раунде есть хотя бы один комплит:
   - комплит номера;
   - или комплит дюжины.

2. В текущем раунде есть хотя бы одна ставка на треке:
   - Serie 5/8;
   - Orphelins;
   - Serie 0/2/3;
   - Zero Spiel;
   - или «Соседи номера».

Если нет комплитов — вопрос не показывать.

Если нет ставок на треке — вопрос не показывать.

Если есть комплиты и ставки трека, но между ними фактически нет пересечений, вопрос всё равно показывать, а правильный ответ должен быть:

0

---

СМЫСЛ ВОПРОСА

Ставки с трека мысленно раскладываются на реальные позиции основного поля.

Комплиты также раскладываются на реальные позиции поля согласно правилам из `rouletteRules.json`.

Нужно найти позиции, на которые одновременно попали:

- ставки комплитов;
- ставки с трека.

Если общая сумма на такой позиции превышает лимит позиции, превышение считается сдачей.

Пользователь вводит одну сумму:

общую сдачу со всех пересечений комплитов со ставками трека.

---

ЧТО УЧИТЫВАЕТСЯ

Учитывать:

- все комплиты номеров;
- комплит дюжины;
- все активные серии;
- все активные ставки «Соседи номера»;
- пересечения на Straight Up;
- пересечения на Split;
- пересечения на Street;
- пересечения на Corner;
- пересечения на Six-Line.

---

ЧТО НЕ УЧИТЫВАЕТСЯ

В этом вопросе не учитывать обычные первоначальные ставки поля:

- цветные фишки;
- кэш-фишки.

Они уже рассматриваются в других вопросах.

В текущем вопросе сравниваются только две группы:

1. Комплиты.
2. Ставки трека.

---

ИСТОЧНИК ДАННЫХ

Все позиции брать из `rouletteRules.json`.

Для комплитов номеров:

`completeBets[].bets`

Для комплита дюжины:

`dozenComplete.dozens[].bets`

Для серий:

`trackBets[seriesKey].bets`

Для соседей:

`neighbours[number]`

Не хардкодить состав ставок в расчётном коде.

---

ШАГ 1. ОПРЕДЕЛИТЬ, ПО СКОЛЬКО ИГРАЕТ КАЖДЫЙ КОМПЛИТ

Для каждого комплита:

```text
rawPlay = completeAmount / chipsRequired

Ограничить значение максимумом рулетки:

limitedRawPlay = min(rawPlay, maximum)

Округлить вниз до кратности комплита:

completePlayPerUnit =
floor(limitedRawPlay / completeMultiplicity) × completeMultiplicity

Для каждой позиции комплита:

completePositionAmount =
completePlayPerUnit × position.chips

ПРИМЕР КОМПЛИТА №4

Ставка:

7895

Для номера 4 из JSON:

chipsRequired = 30

Кратность комплита:

100

Расчёт:

7895 / 30 = 263.166...

Максимум рулетки:

300

Значение максимум не превышает.

Округляем вниз до кратности 100:

200

Комплит №4 играет по:

200

Если на Split 4-7 в JSON указано:

chips = 2

то комплит ставит на этот Split:

200 × 2 = 400

ПРИМЕР КОМПЛИТА №32

Ставка:

11695

Для номера 32 из JSON:

chipsRequired = 40

Расчёт:

11695 / 40 = 292.375

Кратность комплита:

100

Округляем вниз:

200

Комплит №32 играет по:

200

На Split 32-35 комплит ставит:

200 × 2 = 400

ШАГ 2. РАЗЛОЖИТЬ СЕРИИ НА ПОЗИЦИИ ПОЛЯ

Для каждой активной серии:

rawPlay = seriesAmount / divisor

Ограничить максимумом рулетки:

limitedRawPlay = min(rawPlay, maximum)

Округлить вниз до кратности серий:

seriesPlayPerUnit =
floor(limitedRawPlay / seriesMultiplicity) × seriesMultiplicity

Для каждой позиции серии из trackBets.bets:

seriesPositionAmount =
seriesPlayPerUnit × position.chips

ПРИМЕР SERIE 0/2/3

Ставка:

2650

Divisor:

9

Кратность серий:

10

Расчёт:

2650 / 9 = 294.444...

Округляем вниз до кратности 10:

290

Serie 0/2/3 играет по:

290

На обычные Split с chips = 1 ставится по:

290

В том числе:

Split 4-7 = 290
Split 32-35 = 290

ШАГ 3. РАЗЛОЖИТЬ СОСЕДЕЙ НА STRAIGHT UP

Для каждой ставки «Соседи номера»:

Получить пять номеров из rouletteRules.json → neighbours.
Разделить сумму соседей на 5.
neighbourPlayPerNumber =
neighbourAmount / 5

Ставки соседей уже генерируются без сдачи по кратности соседей, поэтому полученное значение должно быть целым и соответствовать кратности соседей.

Каждый из пяти номеров получает отдельную ставку Straight Up.

ПРИМЕР СОСЕДЕЙ 21

Ставка:

950

Расчёт:

950 / 5 = 190

Соседи 21 играют по:

190

Из JSON:

"21": [19, 4, 21, 2, 25]

Значит на Straight Up 4 ставится:

190

ШАГ 4. НОРМАЛИЗОВАТЬ ПОЗИЦИИ

Для поиска пересечений использовать единый ключ позиции:

betType:sortedNumbers

Примеры:

straightUp:4
split:4-7
split:32-35
corner:25-26-28-29
street:0-2-3
sixLine:1-2-3-4-5-6

Номера внутри ключа сортировать.

Например:

split:4-7

и

split:7-4

должны считаться одной позицией.

ШАГ 5. СОБРАТЬ ОБЩУЮ СУММУ КОМПЛИТОВ ПО ПОЗИЦИЯМ

Создать карту:

completePositionMap

Добавить в неё:

все позиции всех комплитов номеров;
все позиции комплита дюжины.

Если несколько комплитов попали на одну позицию, их суммы складываются.

Пример:

completePositionMap["split:4-7"] = 400

или при пересечении нескольких комплитов:

completePositionMap["split:4-7"] =
completeA + completeB + dozenComplete

ШАГ 6. СОБРАТЬ ОБЩУЮ СУММУ ТРЕКА ПО ПОЗИЦИЯМ

Создать карту:

trackPositionMap

Добавить:

все позиции всех активных серий;
все Straight Up позиции всех соседей.

Если несколько ставок трека попали на одну позицию, их суммы складываются.

УЧЁТ РАНЕЕ ОТДАННОЙ СДАЧИ

В предыдущих вопросах уже могла быть рассчитана сдача:

между комплитами;
между ставками трека.

Нельзя повторно использовать сумму, которая уже должна быть возвращена игроку.

Поэтому перед расчётом нового пересечения отдельно ограничить каждую группу лимитом позиции:

effectiveCompleteAmount =
min(totalCompleteAmount, positionLimit)
effectiveTrackAmount =
min(totalTrackAmount, positionLimit)

После этого считать только новое превышение, возникшее при объединении двух групп:

newChange =
max(
  0,
  effectiveCompleteAmount
  + effectiveTrackAmount
  - positionLimit
)

Это исключает повторный подсчёт сдачи, которая уже была рассчитана в предыдущих вопросах.

ШАГ 7. ЛИМИТЫ ПОЗИЦИЙ

Использовать максимум рулетки из настроек.

Правильные коэффициенты:

Straight Up = maximum × 1
Split       = maximum × 2
Street      = maximum × 3
Corner      = maximum × 4
Six-Line    = maximum × 6

При максимуме рулетки 300:

Straight Up = 300
Split       = 600
Street      = 900
Corner      = 1200
Six-Line    = 1800

Важно:

Six-Line использует коэффициент 6, а не 5.

ШАГ 8. ПОСЧИТАТЬ СДАЧУ

Проверять только позиции, которые одновременно существуют:

в completePositionMap;
в trackPositionMap.

Для каждой общей позиции:

change =
max(
  0,
  effectiveCompleteAmount
  + effectiveTrackAmount
  - positionLimit
)

Общий правильный ответ:

totalChange =
sum(change)

по всем пересечениям.
