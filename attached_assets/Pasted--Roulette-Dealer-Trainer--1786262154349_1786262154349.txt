Продолжаем пошаговое развитие Roulette Dealer Trainer.

Уже есть:

* кабинет руководителя;
* список дилеров;
* добавление дилеров;
* страница конкретного дилера;
* кнопка `Создать тренировку`;
* существующая Roulette со всеми настройками и звуками.

Мы меняем процесс создания тренировки.

Целевая последовательность в будущем должна быть такой:

```text
Создать тренировку
        ↓
Выбор игры
        ↓
Настройки выбранной игры
        ↓
Выбор одного или нескольких дилеров
        ↓
Создание тренировки
```

Сейчас нужно реализовать ТОЛЬКО первый шаг этого процесса — экран выбора игры.

## 1. Изменить поведение кнопки "Создать тренировку"

При нажатии `Создать тренировку` больше НЕ нужно сразу открывать настройки Roulette.

Должен открываться отдельный экран выбора игры.

Используй маршрут примерно:

`/manager/training/new/game`

или другой аналогичный маршрут, соответствующий существующему роутингу проекта.

ВАЖНО:

Экран создания тренировки больше не должен архитектурно принадлежать конкретному дилеру, потому что позже одну тренировку можно будет назначить сразу нескольким дилерам.

Поэтому не нужно строить новый процесс вокруг маршрута:

`/manager/dealers/:dealerId/training/new`

как обязательной основной точки создания.

Если пользователь пришёл из карточки конкретного дилера, его `dealerId` пока можно сохранить как контекст для будущего предварительного выбора дилера, но экран выбора игры должен быть универсальным.

## 2. Экран выбора игры

Создай страницу, например:

`SelectGamePage`

или аналогичное название.

На странице:

```text
Новая тренировка

Выберите игру
```

Ниже отображается список доступных игр.

Сейчас доступна только:

`Roulette`

Она должна отображаться как отдельная карточка/элемент выбора с checkbox или другим простым элементом выбора.

Пример:

```text
Новая тренировка

Выберите игру

☐ Roulette

[ Далее ]

[ Отмена ]
```

## 3. Сейчас выбирается только одна игра

Несмотря на визуальное использование checkbox/card, одна TrainingTemplate на данном этапе должна относиться только к одной игре.

То есть пользователь НЕ должен одновременно выбрать:

```text
Roulette + Blackjack
```

для одной тренировки.

Архитектурно:

```ts
gameType: "ROULETTE"
```

а НЕ:

```ts
gameTypes: ["ROULETTE", "BLACKJACK"]
```

При выборе другой игры в будущем предыдущий выбор должен сниматься.

Если для такого поведения логичнее использовать radio-like selection внутри карточек — это допустимо.

Главное:
**одна конфигурация тренировки = одна выбранная игра.**

## 4. Создать расширяемый реестр игр

Очень важно:

НЕ писать непосредственно в JSX:

```tsx
Roulette
```

как единственную захардкоженную игру.

Создай простой реестр доступных игр.

Например:

```ts
type GameType =
  | "ROULETTE"
  | "BLACKJACK"
  | "POKER";

type GameDefinition = {
  type: GameType;
  title: string;
  enabled: boolean;
};
```

Пока список содержит только:

```ts
{
  type: "ROULETTE",
  title: "Roulette",
  enabled: true
}
```

Не добавляй реально Blackjack и Poker в UI, если их ещё нет.

Но структура должна позволять позже легко добавить:

```ts
{
  type: "BLACKJACK",
  title: "Blackjack",
  enabled: true
}
```

и:

```ts
{
  type: "POKER",
  title: "Poker",
  enabled: true
}
```

без переписывания самого SelectGamePage.

Например реестр можно вынести в:

`games.ts`

`gameRegistry.ts`

или подходящий существующей структуре файл.

## 5. Кнопка "Далее"

Пока выбрать можно только Roulette.

Если игра не выбрана:

кнопка `Далее` должна быть disabled либо показать простое сообщение:

`Выберите игру`

Если Roulette выбрана:

`Далее`

должна переходить на следующий маршрут для настроек игры.

Например:

`/manager/training/new/settings`

При переходе нужно передать/сохранить выбранный:

```ts
gameType = "ROULETTE"
```

Выбери простой способ хранения состояния wizard, соответствующий текущему React-приложению.

Пока НЕ сохраняй TrainingTemplate в localStorage.

Мы ещё только проходим мастер создания.

## 6. Не передавать название игры строкой по всему приложению

Используй стабильный идентификатор:

```ts
ROULETTE
```

а отображаемое название:

```text
Roulette
```

получай из реестра игр.

Это понадобится, когда появятся другие игры.

## 7. Кнопка "Отмена"

Кнопка `Отмена` должна вернуть руководителя назад.

Если создание было запущено со страницы конкретного дилера — желательно вернуться туда.

Если это усложняет текущую реализацию, пока допустимо вернуть на `/manager`.

Никакая тренировка при отмене не создаётся.

## 8. Пока НЕ реализовывать экран настроек

Маршрут для следующего шага можно подготовить, но НЕ нужно сейчас переносить туда Settings Roulette.

Если после `Далее` нужен временный экран, можно показать:

```text
Настройки Roulette

Настройки будут добавлены следующим этапом.

[ Назад ]
```

Главное сейчас проверить сам процесс:

```text
Создать тренировку
→ Выбор игры
→ Далее
```

## 9. Пока НЕ создавать TrainingTemplate

На этом этапе НЕ нужно сохранять:

* Training;
* TrainingTemplate;
* TrainingAssignment;
* настройки;
* список дилеров;
* Spin.

Мы сейчас создаём только первый шаг wizard.

## 10. Не менять Roulette

Существующую Roulette не изменять.

Особенно не менять:

* Settings;
* Spin;
* генераторы ставок;
* вопросы;
* racetrack;
* игровое поле;
* звуки;
* дизайн.

## 11. Желательная архитектура процесса

Нужно заложить возможность дальнейшего развития примерно так:

```text
CreateTraining
      |
      v
SelectGamePage
      |
      | gameType
      v
GameSettingsPage
      |
      | gameType + config
      v
SelectDealersPage
      |
      v
TrainingTemplate
      +
TrainingAssignments
```

На этом этапе реализуется только:

```text
SelectGamePage
```

и передача выбранного `gameType` следующему шагу.

## 12. Проверка

Проверь сценарии:

1. Открываю кабинет руководителя.
2. Нажимаю `Создать тренировку`.
3. Открывается новый экран `Выберите игру`.
4. На экране отображается Roulette.
5. Без выбора нельзя перейти дальше.
6. Выбираю Roulette.
7. Нажимаю `Далее`.
8. Приложение знает, что выбран `gameType = ROULETTE`.
9. Можно вернуться назад и изменить выбор.
10. `Отмена` прекращает создание.
11. Никакой Training/TrainingTemplate пока не сохраняется.
12. Существующая Roulette продолжает работать без изменений.

## 13. После выполнения

Кратко сообщи:

1. какие файлы созданы;
2. какие файлы изменены;
3. какой маршрут используется для выбора игры;
4. где расположен реестр игр;
5. какая структура `GameType/GameDefinition` используется;
6. как хранится выбранная игра между шагами;
7. куда ведёт кнопка `Далее`;
8. подтверждение, что Roulette и Settings не изменялись.

Выполни только этот этап.

Не переходи самостоятельно к реализации настроек Roulette, выбору дилеров или TrainingTemplate.
