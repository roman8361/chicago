Необходимо доработать раздел «Настройки карт» в проекте Roulette Dealer Trainer.

Задача — подготовить универсальную систему справочников комбинаций для разных карточных игр.

Сейчас в проекте есть «Русский покер», но в дальнейшем будут добавлены другие виды покера и карточные игры.

У каждой игры могут быть собственные:
- комбинации;
- правила определения комбинаций;
- приоритеты комбинаций;
- дополнительные игровые правила.

Поэтому необходимо сразу заложить расширяемую архитектуру.

ВАЖНО:
На данном этапе реализуем только структуру справочников, навигацию и пустую страницу просмотра комбинаций.

Содержимое комбинаций и игровую логику добавим позже.

Не изменять существующие механики карточного стола и рулетки.

--------------------------------------------------
1. АРХИТЕКТУРА СПРАВОЧНИКОВ
--------------------------------------------------

Для каждой карточной игры предусмотреть отдельный JSON-справочник комбинаций.

Рекомендуемая структура:

src/
  poker/
    games/
      russian-poker/
        combinations.json
        rules.json

    shared/
      cards.json

Структура примерная.

Перед реализацией изучи существующую архитектуру проекта и выбери подходящее место для справочников.

Не нужно переносить существующие файлы без необходимости.

Назначение:

combinations.json
— комбинации конкретной карточной игры.

rules.json
— дополнительные правила конкретной игры.

cards.json
— общий справочник игральных карт, который может использоваться всеми карточными играми.

ВАЖНО:
Если общий справочник карт уже существует, использовать его. Не создавать дубликат.

Сейчас создать только пустую заготовку combinations.json для русского покера с корректной JSON-структурой.

rules.json пока создавать не обязательно, если он не используется.

Не заполнять combinations.json реальными комбинациями.

Их состав и структуру данных мы определим отдельно.

--------------------------------------------------
2. УНИВЕРСАЛЬНАЯ СИСТЕМА КОМБИНАЦИЙ
--------------------------------------------------

Не привязывать механизм просмотра комбинаций исключительно к русскому покеру.

Предусмотреть универсальную страницу просмотра, которая получает идентификатор игры.

Например:

gameId = "russian-poker"

В дальнейшем могут появиться:

gameId = "texas-holdem"

gameId = "three-card-poker"

и другие.

Для каждой игры должен использоваться собственный combinations.json.

Принцип:

gameId
→ определение справочника игры
→ загрузка соответствующего JSON
→ отображение комбинаций.

Не использовать длинные цепочки условий для каждой новой игры, если можно организовать конфигурацию или реестр игр.

Сейчас зарегистрировать только:

russian-poker.

Не создавать другие игры заранее.

--------------------------------------------------
3. НАСТРОЙКИ КАРТ
--------------------------------------------------

В существующем меню «Настройки карт» найти раздел:

«Русский покер».

Внутри него добавить пункт:

«Комбинации»

Рядом разместить кнопку:

«Посмотреть».

Визуально:

Русский покер

[ ] Русский покер

Комбинации       [Посмотреть]

Пункт «Комбинации» должен быть доступен независимо от состояния checkbox «Русский покер».

То есть пользователь может открыть справочник, даже если русский покер сейчас выключен.

Не менять существующее поведение checkbox.

--------------------------------------------------
4. ПЕРЕХОД К СПРАВОЧНИКУ
--------------------------------------------------

При нажатии кнопки «Посмотреть» открыть отдельную страницу просмотра комбинаций.

Для русского покера заголовок:

«Комбинации русского покера».

Страница должна использовать универсальный компонент просмотра комбинаций.

Идентификатор игры:

russian-poker.

Маршрут можно организовать, например:

/cards/combinations/russian-poker

Но использовать существующий подход к маршрутизации проекта.

Не создавать новую систему маршрутизации, если в проекте уже есть готовая.

--------------------------------------------------
5. СОДЕРЖИМОЕ СТРАНИЦЫ
--------------------------------------------------

Пока на странице отображать:

Заголовок:

«Комбинации русского покера»

И информационный текст:

«Справочник комбинаций пока не заполнен».

Не добавлять сейчас:

- флеш;
- стрит;
- фулл-хаус;
- каре;
- другие комбинации;
- примеры карт;
- выплаты;
- коэффициенты;
- приоритеты комбинаций.

Всё это обсудим отдельно.

Страница должна корректно работать с пустым JSON-справочником.

Не должно быть ошибок, если комбинации отсутствуют.

--------------------------------------------------
6. КНОПКА «НАЗАД»
--------------------------------------------------

На странице комбинаций добавить кнопку:

«Назад».

При нажатии возвращать пользователя в настройки карт.

Важно:

- настройки не сбрасываются;
- checkbox «Русский покер» сохраняет своё значение;
- другие параметры карточного стола не меняются;
- текущая раздача не перезапускается;
- карты не генерируются повторно.

Просмотр справочника — исключительно информационная функция.

--------------------------------------------------
7. ПОДГОТОВКА К ДРУГИМ ИГРАМ
--------------------------------------------------

В дальнейшем настройки могут выглядеть так:

Настройки карт

Русский покер
  [ ] Русский покер
  Комбинации [Посмотреть]

Техасский холдем
  [ ] Техасский холдем
  Комбинации [Посмотреть]

Другой вид покера
  [ ] Другой вид покера
  Комбинации [Посмотреть]

У каждой игры:

- собственный идентификатор;
- собственный JSON;
- собственные настройки;
- собственные правила.

При этом компонент просмотра комбинаций должен быть общим.

Для добавления новой игры в будущем должно быть достаточно:

1. Зарегистрировать новую игру.
2. Добавить её JSON-справочник.
3. Добавить пункт в настройки.
4. Использовать существующий компонент просмотра.

Не должно требоваться переписывать страницу комбинаций.

--------------------------------------------------
8. РАЗДЕЛЕНИЕ ДАННЫХ И ЛОГИКИ
--------------------------------------------------

Предусмотреть разделение трёх уровней.

Уровень 1 — данные.

JSON-справочник комбинаций конкретной игры.

Уровень 2 — отображение.

Универсальный компонент просмотра комбинаций.

Уровень 3 — игровая логика.

В будущем генератор раздач и проверка комбинаций смогут использовать соответствующие правила игры.

Сейчас игровую логику НЕ реализовывать.

ВАЖНО:
Не делать JSON автоматически исполняемым источником правил. В дальнейшем отдельно определим, какие данные достаточно хранить в JSON, а какие правила должны реализовываться в коде.

--------------------------------------------------
9. ВНЕШНИЙ ВИД
--------------------------------------------------

Сохранить существующий стиль приложения:

Chicago / Art Deco / Casino.

Использовать:

- тёмно-зелёное сукно;
- золотистые заголовки;
- тонкие золотые линии;
- существующие кнопки;
- существующую типографику.

Страница комбинаций должна выглядеть как естественная часть карточного модуля.

Не создавать новый независимый дизайн.

--------------------------------------------------
10. НЕ МЕНЯТЬ СУЩЕСТВУЮЩИЕ ФУНКЦИИ
--------------------------------------------------

Не изменять:

- рулеточный модуль;
- генерацию ставок;
- настройки рулетки;
- карточное сукно;
- расположение ANTE;
- расположение шести карт;
- отображение рубашек;
- flip-анимацию;
- кнопку «Старт»;
- генерацию карт;
- существующие изображения PNG;
- таймер;
- вопросы аттестации;
- расчёты;
- существующую навигацию, кроме нового перехода.

Новая функциональность должна дополнять существующую реализацию, а не заменять её.

--------------------------------------------------
11. ОБЯЗАТЕЛЬНЫЕ ПРОВЕРКИ
--------------------------------------------------

Проверить:

1. В настройках карт появился пункт «Комбинации» внутри раздела «Русский покер».

2. Кнопка «Посмотреть» работает.

3. Открывается страница «Комбинации русского покера».

4. Страница использует универсальный компонент просмотра.

5. Для русского покера используется идентификатор russian-poker.

6. Создан пустой корректный combinations.json.

7. Пустой справочник не вызывает ошибок.

8. Кнопка «Назад» возвращает в настройки карт.

9. Настройки после возврата сохраняются.

10. Справочник можно открыть при выключенном русском покере.

11. Просмотр справочника не запускает раздачу.

12. Существующие карты и flip-анимация работают как раньше.

13. Архитектура позволяет в дальнейшем добавить отдельный JSON для другой игры без переписывания компонента просмотра.

--------------------------------------------------
12. ПОСЛЕ ВЫПОЛНЕНИЯ
--------------------------------------------------

Кратко сообщи:

1. Где находится combinations.json русского покера.
2. Как организован универсальный просмотр комбинаций.
3. Какой маршрут используется.
4. Как выполняется переход из настроек.
5. Как добавить справочник для другой игры в будущем.
6. Подтверди, что существующая игровая логика не изменена.

На этом этапе остановиться.

Следующим этапом мы отдельно определим:
- какие комбинации есть в русском покере;
- какие данные необходимо хранить для каждой комбинации;
- как они будут отображаться;
- как использовать их при генерации и проверке раздач.
