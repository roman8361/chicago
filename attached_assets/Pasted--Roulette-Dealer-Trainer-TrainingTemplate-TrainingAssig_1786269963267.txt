Продолжаем развитие Roulette Dealer Trainer.

Сейчас уже есть:

* TrainingTemplate;
* TrainingAssignment;
* RouletteExercise;
* отдельный Exercise для каждого Assignment;
* статусы Assignment:

  * CREATED;
  * IN_PROGRESS;
  * COMPLETED;
* кабинет руководителя;
* раздел аттестаций;
* существующий `/dealer`.

Следующий этап:

# Сделать кабинет дилера и раздел "Мои аттестации"

На этом этапе НЕ открывать Roulette и НЕ менять статус на IN_PROGRESS.

Дилер пока только видит назначенные ему аттестации.

## 1. Страница кабинета дилера

Использовать существующий маршрут:

`/dealer`

Страница должна стать полноценным минимальным кабинетом дилера.

Пример:

```text
Личный кабинет дилера

Мои аттестации

Roulette
Назначена: 09.08.2026 12:12
Статус: Не начата

[ Открыть ]
```

Если назначений несколько — показать их списком.

## 2. Как определить текущего дилера

Настоящей авторизации пока нет.

Используй существующий временный механизм входа дилера, который уже есть в проекте.

Если сейчас кнопка:

`Войти как дилер`

не привязана к конкретному Dealer, добавь минимальный тестовый способ выбрать дилера перед входом.

Например на временном login screen:

```text
Войти как дилер

Дилер:
[ Иванов Иван Иванович ▼ ]

[ Войти ]
```

или аналогичный простой вариант.

Главное:

после входа приложение должно знать:

`currentDealerId`.

Не создавать настоящую authentication system.

## 3. Временная dealer session

Для текущего frontend-only этапа можно хранить:

```ts
currentDealerId
```

в уже существующем auth/session state.

Если такого state нет — создать минимальный механизм.

Допустимо использовать sessionStorage/localStorage, если это соответствует текущей архитектуре.

Но не смешивать `currentDealerId` с самой сущностью Dealer.

## 4. Не хранить роль внутри Dealer

Dealer остаётся бизнес-сущностью:

```ts
{
  id,
  fullName
}
```

Не добавлять туда:

```ts
role
password
login
currentUser
```

Настоящий User появится позже вместе с backend/auth.

## 5. Получение аттестаций дилера

Для текущего `currentDealerId`:

1. получить все TrainingAssignment;
2. выбрать только:

```text
assignment.dealerId === currentDealerId
```

3. для каждого Assignment получить соответствующий TrainingTemplate.

Таким образом дилер должен видеть только свои назначения.

## 6. Дилер не должен видеть чужие Assignment

Например существуют:

```text
Иванов:
Assignment #1
Assignment #4

Петров:
Assignment #2
```

Если вошёл Иванов, показывать только:

```text
Assignment #1
Assignment #4
```

Assignment Петрова не отображать.

Это важно даже на временной frontend-реализации.

## 7. Карточка аттестации

Для каждого Assignment показывать минимум:

* название игры;
* дату и время назначения/создания;
* статус;
* кнопку `Открыть`.

Например:

```text
Roulette

Назначена:
09.08.2026 12:12

Статус:
Не начата

[ Открыть ]
```

## 8. Какую дату показывать

Предпочтительно использовать:

`TrainingAssignment.createdAt`

потому что конкретный дилер мог быть добавлен к аттестации позже.

Например:

Template создан:

`09.08.2026 10:00`

а Петров добавлен:

`09.08.2026 14:30`

У Петрова в кабинете нужно показывать:

`09.08.2026 14:30`.

Использовать уже существующий formatter:

`DD.MM.YYYY HH:mm`

без секунд.

## 9. Название игры

Не показывать техническое:

`ROULETTE`.

Использовать game registry и отображать:

`Roulette`.

## 10. Статусы

Использовать уже существующее отображение:

```text
CREATED → Не начата
IN_PROGRESS → В процессе
COMPLETED → Завершена
```

Не создавать новую отдельную таблицу соответствий.

Переиспользовать общий helper.

## 11. Сортировка

Список аттестаций дилера сортировать:

самые новые назначения сверху.

По:

`TrainingAssignment.createdAt`.

## 12. Пустой список

Если дилеру ничего не назначено:

показать:

```text
Мои аттестации

Нет назначенных аттестаций.
```

Не показывать кнопку создания.

Дилер не может сам создавать аттестацию.

## 13. Кнопка "Открыть"

Кнопка `Открыть` должна вести на отдельную страницу Assignment.

Например:

`/dealer/attestations/:assignmentId`

Создать минимальную страницу.

Пока НЕ открывать на ней Roulette.

## 14. Страница конкретного назначения

На странице показать:

```text
Аттестация

Игра:
Roulette

Назначена:
09.08.2026 12:12

Статус:
Не начата

Задание:
Подготовлено

[ Начать аттестацию ]

[ Назад ]
```

Но кнопка:

`Начать аттестацию`

на этом этапе пока НЕ должна запускать Roulette.

Можно оставить её disabled или подготовить переход-заглушку.

Сам запуск будет следующим этапом.

## 15. Проверка наличия RouletteExercise

На странице Assignment проверить:

есть ли RouletteExercise для этого assignmentId.

Если есть:

показывать:

`Задание подготовлено`.

Если нет:

показывать:

`Задание не подготовлено`.

Не генерировать его автоматически здесь.

По текущей архитектуре Exercise должен быть создан заранее.

## 16. Не регенерировать Exercise

Очень важно:

открытие кабинета дилера или страницы Assignment не должно вызывать:

`generateRouletteExercise`.

Только читать уже сохранённые данные.

Никакой генерации в:

* render;
* useEffect;
* route loader.

## 17. Проверка принадлежности Assignment дилеру

Если Иванов вручную откроет URL:

`/dealer/attestations/assignment-petrov`

страница не должна показывать данные Петрова.

Проверить:

```text
assignment.dealerId === currentDealerId
```

Если не совпадает:

показать:

`Аттестация недоступна`

и кнопку:

`Вернуться в кабинет`.

Даже несмотря на отсутствие настоящей backend-защиты, frontend должен вести себя корректно.

## 18. Если Assignment не существует

Показать:

```text
Аттестация не найдена

[ Вернуться в кабинет ]
```

Не допускать runtime error.

## 19. Если Template удалён/повреждён

Если Assignment существует, но соответствующий TrainingTemplate не найден:

показать понятное сообщение:

`Данные аттестации недоступны`.

Не падать.

## 20. Если Dealer удалён

Если текущий currentDealerId больше не существует в Dealer storage:

не пытаться отображать старые назначения как обычный кабинет.

Показать:

```text
Дилер не найден.
```

и возможность вернуться на временный экран входа.

## 21. Показывать имя дилера

В верхней части кабинета желательно показать:

```text
Личный кабинет дилера

Иванов Иван Иванович
```

Имя брать из Dealer storage по currentDealerId.

## 22. Не показывать настройки

Дилер не должен видеть:

* настройки Roulette;
* TrainingTemplate.config;
* минимумы/максимумы;
* настройки комплитов;
* настройки серий;
* настройки соседей;
* служебную конфигурацию аттестации.

Ему нужна только сама назначенная аттестация.

## 23. Не показывать других дилеров

На странице Assignment также не показывать:

* список остальных участников Template;
* количество назначенных дилеров;
* их статусы.

Дилер работает только со своим Assignment.

## 24. Не добавлять управление

В кабинете дилера не должно быть:

* изменить настройки;
* изменить дилеров;
* удалить аттестацию;
* создать аттестацию;
* добавить дилера.

Это функции руководителя.

## 25. Status пока не менять

Открытие:

`Мои аттестации`

или:

`Открыть`

не переводит Assignment из CREATED в IN_PROGRESS.

CREATED должен оставаться до фактического запуска аттестации.

## 26. Кнопка "Начать аттестацию"

Пока подготовить её визуально.

Если Assignment:

`CREATED`

показывать:

`Начать аттестацию`.

Если:

`IN_PROGRESS`

в будущем будет:

`Продолжить аттестацию`.

Если:

`COMPLETED`

в будущем будет просмотр результата.

На этом этапе можно уже правильно менять текст кнопки по status, но переход к Roulette пока не реализовывать.

## 27. Варианты кнопки по статусу

Можно подготовить:

```text
CREATED
→ Начать аттестацию

IN_PROGRESS
→ Продолжить аттестацию

COMPLETED
→ Аттестация завершена
```

Для COMPLETED кнопка может быть disabled.

Но не реализовывать результаты.

## 28. Не менять кабинет руководителя

Не менять существующие:

* создание аттестации;
* TrainingTemplate;
* управление дилерами;
* изменение настроек;
* изменение участников;
* удаление;
* список аттестаций руководителя.

## 29. Не менять Roulette

Не изменять:

* Roulette UI;
* Spin;
* настройки;
* генераторы;
* вопросы;
* звуки;
* racetrack.

## 30. Проверка сценария Иванова

Есть:

```text
Template A
→ Иванов

Template B
→ Иванов

Template C
→ Петров
```

Войти как Иванов.

Должно быть:

```text
Мои аттестации

Template B
Template A
```

Template C не отображается.

## 31. Проверка Петрова

Войти как Петров.

Показать только:

`Template C`.

## 32. Проверка прямого URL

Войти как Иванов.

Попытаться открыть Assignment Петрова по URL.

Результат:

`Аттестация недоступна`.

## 33. Проверка Exercise

Открыть Assignment Иванова.

Exercise существует.

Показать:

`Задание подготовлено`.

Обновить браузер.

Exercise id и его содержимое не изменяются.

## 34. Проверка статусов

CREATED:

`Не начата`

IN_PROGRESS:

`В процессе`

COMPLETED:

`Завершена`

Использовать существующий helper.

## 35. После выполнения

Кратко сообщи:

1. какие файлы созданы;
2. какие файлы изменены;
3. как определяется currentDealerId;
4. где временно хранится dealer session;
5. как загружаются Assignment конкретного дилера;
6. как исключаются чужие Assignment;
7. какой маршрут используется для страницы назначения;
8. какую дату видит дилер;
9. как определяется status label;
10. как проверяется наличие RouletteExercise;
11. как защищён прямой URL чужого Assignment;
12. что происходит при неизвестном Assignment;
13. подтверждение, что открытие страницы не меняет status;
14. подтверждение, что Exercise не регенерируется;
15. подтверждение, что Roulette пока не открывается.

Выполни только этот этап.

Не переходи самостоятельно к запуску Roulette, ответам дилера или завершению аттестации.
