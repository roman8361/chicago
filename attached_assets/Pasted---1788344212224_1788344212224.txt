Нужно точечно изменить визуальное отображение денежных фишек (кэша) на основном поле рулетки.

ВАЖНО: меняем только цвет отображения кэш-фишек в зависимости от их итогового номинала/суммы.

Не менять:

- генерацию кэша;
- распределение кэша по позициям;
- суммирование кэша;
- номиналы;
- расчёты;
- лимиты;
- взаимодействие с цветными ставками;
- остальные типы фишек.

## Новое правило цвета кэш-фишки

Цвет денежной фишки должен автоматически определяться по её отображаемой сумме.

Использовать следующие диапазоны:

### 5–24
Бордовая / тёмно-красная фишка.

Важно:
не использовать обычный ярко-красный цвет, потому что кэш не должен визуально сливаться с красными цветными ставками.

Цвет должен быть именно глубоким бордовым.

### 25–99
Зелёная фишка.

Использовать хорошо читаемый насыщенный зелёный оттенок, соответствующий общему стилю рулетки.

### 100–499
Оставить текущий стандартный цвет кэш-фишки.

То есть существующее оформление кэш-фишек этого диапазона не менять.

### 500–999
Белая фишка.

Она должна хорошо выделяться на зелёном поле.

Сохранить существующий стиль фишки, обводку и читаемость значения.

### 1000–4999
Оранжевая фишка.

Использовать насыщенный, но не кислотный оранжевый оттенок в общем премиальном стиле интерфейса.

### 5000 и больше
Тёмно-фиолетовая фишка.

Важно:

- использовать именно тёмный насыщенный фиолетовый;
- не использовать розовый;
- не использовать яркий magenta;
- фишка должна хорошо отличаться от остальных номиналов и не сливаться с другими ставками.

## Важное правило для суммированного кэша

У нас на одной физической позиции несколько денежных фишек могут суммироваться.

Например:

100 + 25 = 125.

В интерфейсе отображается итоговая ставка:

125.

Цвет такой фишки необходимо определять НЕ по отдельным исходным номиналам 100 и 25, а по ИТОГОВОЙ СУММЕ позиции.

В данном примере:

125 попадает в диапазон 100–499,

следовательно используется стандартный текущий цвет кэш-фишки.

Другой пример:

500 + 100 = 600.

Итог:

600.

Диапазон:

500–999.

Следовательно отображается белая кэш-фишка.

Ещё пример:

1000 + 1000 + 500 = 2500.

Итог:

2500.

Следовательно фишка оранжевая.

Если итог:

5000 или больше,

фишка тёмно-фиолетовая.

## Единая функция определения цвета

Желательно не размазывать проверки диапазонов по разным компонентам.

Сделать единое определение визуального варианта кэш-фишки по её итоговой сумме.

Логика диапазонов:

5 <= amount <= 24
→ бордовая

25 <= amount <= 99
→ зелёная

100 <= amount <= 499
→ текущий стандартный цвет

500 <= amount <= 999
→ белая

1000 <= amount <= 4999
→ оранжевая

amount >= 5000
→ тёмно-фиолетовая

## Читаемость номинала

Для каждого цвета подобрать существующий или подходящий контраст текста, чтобы значение фишки хорошо читалось.

Особенно проверить:

- белую фишку;
- бордовую;
- тёмно-фиолетовую;
- оранжевую.

Не менять размер самих кэш-фишек и размер текста без необходимости.

## Где применять

Новое цветовое правило должно применяться ко всем денежным фишкам основного поля, включая суммированные ставки.

Если initial spin затем отображается в итоговом «Отчёте по спину», там кэш должен выглядеть так же, как на первоначальном поле.

Не должно быть ситуации:

на первоначальном спине 600 — белая,

а в отчёте 600 отображается старым цветом.

Использовать одну и ту же визуальную логику.

## Не затронуть цветные ставки

Очень важно не перепутать:

это правило относится только к CASH / денежным фишкам.

Обычные цветные фишки рулетки не менять.

## Проверить границы диапазонов

Обязательно проверить:

5 → бордовая
24 → бордовая

25 → зелёная
99 → зелёная

100 → текущая стандартная
499 → текущая стандартная

500 → белая
999 → белая

1000 → оранжевая
4999 → оранжевая

5000 → тёмно-фиолетовая

10000 → тёмно-фиолетовая

Также проверить суммированные значения:

100 + 25 = 125 → стандартная

500 + 100 = 600 → белая

1000 + 500 = 1500 → оранжевая

5000 + 1000 = 6000 → тёмно-фиолетовая.

После выполнения кратко сообщи:

- где реализовано определение цвета кэша;
- подтверждение, что цвет определяется по итоговой сумме позиции;
- какие цвета используются для шести диапазонов;
- подтверждение, что генерация и расчёты кэша не изменялись.
