# Задание для Replit: генерация серии раздач русского покера

Необходимо доработать существующий карточный модуль Roulette Dealer Trainer.

Работаем только с игрой **«Русский покер»**.

Ранее мы создали JSON-справочник двойных комбинаций русского покера, сгруппировали раздачи по категориям и добавили кнопку «Дальше» под шестью картами.

Теперь нужно связать эти элементы и реализовать полноценную серию раздач на основании настроек пользователя.

**ВАЖНО:** использовать уже существующий JSON и готовые компоненты карт. Не переписывать с нуля работающую функциональность.

## 1. Новые настройки русского покера

В существующем разделе:

Настройки карт → Русский покер

добавить два блока настроек.

### 1.1. Количество раздач

Название параметра:

**«Количество раздач»**

Тип: числовое поле.

Допустимые значения:

- Минимум: 1
- Максимум: 100
- По умолчанию: 10

Разрешать только целые числа.

Не допускать запуск серии с некорректным значением.

При сохранении проверять диапазон 1–100.

Настройка должна сохраняться вместе с остальными настройками карточного модуля.

### 1.2. Группы комбинаций

Добавить отдельный блок:

**«Группы комбинаций»**

Список групп получать динамически из существующего JSON-справочника двойных комбинаций русского покера.

Не прописывать названия групп вручную в компонентах интерфейса.

Например, если JSON содержит:

- Two pairs
- Three of a kind
- Straight
- Flush
- Full House
- Four of a kind
- Straight Flush
- Royal Flush

то все эти группы должны появиться в настройках.

Использовать фактический список из JSON, даже если названия отличаются от приведённых примеров.

Каждая группа должна иметь собственный checkbox.

Разрешить выбирать несколько групп одновременно.

Пример:

☐ Two pairs

☑ Three of a kind

☑ Straight

☑ Flush

☐ Full House

☐ Four of a kind

Выбор группы выполняется нажатием на checkbox или название группы.

При сохранении настроек сохранять не названия, а стабильные идентификаторы групп (`groupId`).

Это важно, чтобы дальнейшее изменение отображаемого названия не ломало настройки.

По умолчанию выбрать все группы, которые содержат хотя бы одну корректную раздачу.

Добавить удобные действия:

- «Выбрать все»
- «Снять все»

Пустые группы, не содержащие корректных раздач, не должны участвовать в генерации. Их можно отображать как недоступные с пояснением.

## 2. Проверка настроек

Для запуска серии необходимо:

1. Включён режим «Русский покер».
2. Указано количество раздач от 1 до 100.
3. Выбрана минимум одна группа.
4. Каждая выбранная группа содержит минимум одну корректную раздачу в JSON.

Если ни одна группа не выбрана, при попытке запуска показать сообщение:

«Выберите хотя бы одну группу комбинаций».

Не запускать генерацию и не показывать случайные карты из других источников.

При некорректном JSON вывести понятную ошибку.

Не допускать бесконечных циклов или зависания интерфейса.

## 3. Источник раздач

Все раздачи брать из существующего:

`double-combinations.json`

Точный путь определить по фактической структуре проекта.

Использовать существующие поля:

- `groups`
- `group.id`
- `group.name`
- `group.deals`
- `deal.id`
- `deal.cards`
- `deal.bonusCombinations`

Если структура немного отличается, адаптироваться к реальному JSON без уничтожения существующих данных.

Каждая раздача — массив ровно из шести уникальных карт.

Например:

`["dj", "sk", "ck", "hj", "sq", "dq"]`

Коды карт должны соответствовать существующим PNG.

Не генерировать новые комбинации алгоритмически.

Не изменять содержимое JSON при показе раздач.

## 4. Формирование серии раздач

После нажатия кнопки «Старт» необходимо сформировать план всей серии раздач.

План должен содержать ровно столько элементов, сколько указано в настройке «Количество раздач».

Каждый элемент плана должен содержать:

- идентификатор группы;
- идентификатор выбранной раздачи;
- шесть карт;
- порядковый номер раздачи в серии.

План серии формировать один раз при запуске.

Нажатие «Дальше» должно переходить к следующему элементу готового плана, а не пересоздавать случайным образом всю серию.

Это обеспечит стабильную последовательность.

## 5. Равномерное распределение между группами

Это одно из главных требований.

Количество раздач должно распределяться между выбранными группами максимально равномерно.

Пример 1:

Выбраны:

- Three of a kind
- Straight
- Flush

Количество раздач: 10.

Распределение:

- Three of a kind — 3
- Straight — 3
- Flush — 4

Какая именно группа получит четвёртую раздачу, определять случайно.

Пример 2:

Выбраны 4 группы.

Количество раздач: 20.

Каждая группа должна получить по 5 раздач.

Пример 3:

Выбраны 3 группы.

Количество раздач: 11.

Распределение:

4, 4, 3.

Пример 4:

Выбраны 5 групп.

Количество раздач: 2.

Случайно выбрать две разные группы и сформировать по одной раздаче из каждой.

Группы, которым в данной серии досталось 0 раздач, допустимы только если количество раздач меньше количества выбранных групп.

### Алгоритм распределения

Пусть:

- N — общее количество раздач;
- G — количество выбранных непустых групп.

Базовое количество:

`base = floor(N / G)`

Остаток:

`remainder = N % G`

Каждая группа получает `base`.

Затем случайно выбрать `remainder` различных групп и добавить каждой по одной раздаче.

Разница между количеством раздач любых двух выбранных групп должна быть не больше 1.

## 6. Порядок групп — обязательное чередование

После определения количества раздач сформировать случайную последовательность групп.

Главное правило:

**Если в серии реально участвуют две или более группы, две соседние раздачи не должны принадлежать одной группе, если это математически возможно.**

Пример допустимой последовательности:

Straight → Flush → Three of a kind → Straight → Three of a kind → Flush → Straight

Пример недопустимой последовательности:

Straight → Straight → Flush → Three of a kind

Не сортировать раздачи по группам.

Не выводить сначала все Straight, потом все Flush.

Порядок должен выглядеть случайным, но соблюдать ограничение на соседние группы.

### Реализация

Использовать алгоритм построения последовательности с учётом оставшихся квот каждой группы.

На каждом шаге:

1. Определить группы, у которых остались раздачи.
2. Исключить группу предыдущей раздачи, если есть допустимая альтернатива.
3. Учитывать оставшиеся квоты, чтобы не создать ситуацию, когда к концу серии чередование станет невозможным.
4. Среди допустимых групп выбирать случайным образом.
5. Продолжать до заполнения всей серии.

Можно использовать алгоритм с контролем максимальной оставшейся квоты, приоритетную очередь либо другой корректный подход.

Не использовать бесконечный перебор случайных последовательностей.

### Краевые случаи

Если выбрана одна группа, последовательные раздачи одной группы разрешены.

Если выбраны две группы и количество раздач 10, распределение должно быть 5/5, последовательность чередуется.

Если выбраны две группы и количество раздач 11, распределение 6/5, последовательность также должна чередоваться.

С учётом заданного равномерного распределения при двух и более реально участвующих группах чередование должно быть достижимо.

Если алгоритм не сумел построить такую последовательность, считать это ошибкой алгоритма, а не молча нарушать правило.

## 7. Максимальное разнообразие раздач внутри группы

Это второе ключевое требование.

В рамках каждой группы необходимо максимально избегать повторения одной и той же шестикарточной раздачи.

Например, в JSON группы Straight хранится 15 уникальных вариантов.

Пользователь запросил 10 раздач Straight.

Ожидаем:

10 разных вариантов.

Повторов быть не должно.

### Если раздач требуется больше, чем вариантов в JSON

Мы выбрали следующую стратегию:

**Сначала использовать все уникальные варианты. После их исчерпания повторно перемешивать пул и использовать варианты снова.**

Пример:

В группе Straight есть 12 разных раздач.

Пользователю требуется 25 раздач этой группы.

Алгоритм:

1. Перемешать все 12 вариантов.
2. Использовать каждый вариант один раз.
3. Когда список исчерпан, снова перемешать 12 вариантов.
4. Продолжить выбор без повторов в новом цикле.
5. После второго полного цикла выбрать ещё один вариант.

Итого: 12 + 12 + 1 = 25.

### Дополнительное правило

При переходе от одного цикла к следующему по возможности не повторять последнюю раздачу предыдущего цикла первой раздачей нового цикла.

Пример:

Последняя раздача цикла:

Straight-007.

Первая раздача следующего цикла не должна быть Straight-007, если в группе есть другой вариант.

Если в группе только один уникальный вариант, повторения разрешены.

### Уникальность по фактическим картам

При проверке разнообразия учитывать не только `deal.id`, но и фактические шесть карт.

Если две записи JSON содержат одинаковые шесть карт в разном порядке, они должны считаться одной уникальной шестикарточной раздачей для целей выбора.

При этом оригинальные записи и связанные с ними бонусные комбинации не удалять из JSON.

Если есть разные записи с одинаковым набором карт, выбирать конкретную запись из такой группы эквивалентных записей по определённому правилу, не искажая данные.

Порядок шести карт в выбранной записи сохранять таким, каким он задан в JSON.

## 8. Подготовка карт перед стартом

Существующий сценарий должен сохраниться.

Если пользователь включил «Русский покер», до запуска серии на столе отображаются шесть рубашек.

Использовать существующий:

`back.png`

Лицевые изображения до нажатия «Старт» не показывать.

Настройки групп не должны менять расположение рубашек.

## 9. Кнопка «Старт»

При нажатии «Старт»:

1. Проверить настройки.
2. Сформировать распределение количества раздач между группами.
3. Сформировать последовательность групп с соблюдением чередования.
4. Выбрать конкретные раздачи из JSON.
5. Сохранить готовый план серии в состоянии приложения.
6. Установить текущую раздачу №1.
7. Запустить существующую flip-анимацию шести карт.
8. Показать шесть лицевых карт первой раздачи.

Не менять механику существующей анимации.

Карты должны переворачиваться на прежних местах.

Не перемещать карты и не менять их размеры.

## 10. Кнопка «Дальше»

Под шестью картами уже существует кнопка:

**«Дальше»**

Теперь необходимо подключить к ней игровую логику.

При нажатии:

1. Определить следующую раздачу в подготовленном плане.
2. Закрыть текущие карты рубашками.
3. Запустить существующую анимацию переворота для следующей раздачи.
4. Показать шесть карт следующего элемента плана.
5. Увеличить номер текущей раздачи на 1.

Не формировать новый план серии при каждом нажатии «Дальше».

Не выбирать группу заново вне подготовленной последовательности.

### Защита от повторных нажатий

Во время перехода между раздачами:

- временно блокировать повторные нажатия «Дальше»;
- не допускать пропуска раздач из-за двойного клика;
- не запускать одновременно несколько flip-анимаций;
- не допускать рассинхронизации карт и номера раздачи.

После завершения анимации кнопка снова доступна.

## 11. Счётчик раздач

Добавить небольшой текстовый счётчик рядом с кнопкой «Дальше» или над ней.

Формат:

**Раздача 1 из 10**

После перехода:

**Раздача 2 из 10**

И так далее.

Счётчик должен обновляться вместе с фактически показанной раздачей.

Возможное расположение:

[Шесть игровых карт]

Раздача 3 из 10

[Дальше]

Сохранить существующий стиль казино.

Не менять положение ряда карт ради счётчика.

## 12. Завершение серии

После показа последней раздачи кнопка «Дальше» не должна создавать новую раздачу.

Например:

Раздача 10 из 10.

После этого показать состояние:

**«Серия завершена»**

Кнопку «Дальше» скрыть или сделать недоступной.

Не начинать новую серию автоматически.

Открытые карты последней раздачи оставить на столе.

Пользователь сможет начать новую серию отдельным нажатием существующей кнопки «Старт», если это допускает текущий интерфейс.

При запуске новой серии:

- сбросить старый план;
- заново распределить группы;
- заново перемешать варианты;
- начать с первой раздачи;
- сохранить актуальные настройки.

## 13. Изменение настроек

Если пользователь меняет количество раздач или выбранные группы:

- сохранить новые настройки;
- не менять случайным образом уже показанные карты;
- не пересчитывать частично пройденную серию;
- применять новые настройки только при запуске новой серии.

Если в приложении уже существует механизм сброса игровой сессии при изменении настроек, сохранить его согласованное поведение.

Не допускать частичного смешивания старого и нового плана.

## 14. Разделение ответственности

Рекомендую логически разделить:

**Данные**

Загрузка и валидация `double-combinations.json`.

**Генератор серии**

Распределение по группам, порядок групп, выбор раздач и контроль повторов.

**Игровое состояние**

Текущий номер раздачи, весь план серии, состояние анимации, завершение серии.

**Интерфейс**

Шесть карт, рубашки, кнопка «Старт», кнопка «Дальше», счётчик.

Не размещать весь алгоритм внутри обработчика кнопки «Дальше».

Генератор должен быть тестируемым отдельно от React-компонентов.

## 15. Дополнительная валидация JSON

Перед использованием данных проверить:

- корректность структуры групп;
- уникальность ID групп;
- корректность ID раздач;
- наличие шести карт в каждой раздаче;
- отсутствие повторяющихся карт внутри раздачи;
- существование кодов карт;
- отсутствие неизвестных групп в выбранных настройках.

Ранее мы согласовали исправления строк Excel 48, 58, 108, 110, 112, 117 и 142.

Эти исправления уже должны находиться в подготовленном JSON.

Не изменять их повторно без необходимости.

Если обнаружены ошибки, сообщить о них, а не исправлять случайной заменой карт.

## 16. Автоматические тесты

Добавить тесты на алгоритм генерации серий.

Обязательные сценарии:

**Тест 1.** Одна группа, 10 раздач.

Результат: все 10 из выбранной группы.

**Тест 2.** Три группы, 10 раздач.

Результат: распределение 3/3/4.

**Тест 3.** Четыре группы, 20 раздач.

Результат: 5/5/5/5.

**Тест 4.** Пять групп, 2 раздачи.

Результат: две разные группы по одной раздаче.

**Тест 5.** Две группы, 11 раздач.

Результат: 6/5 и отсутствие соседних одинаковых групп.

**Тест 6.** Три группы, 100 раздач.

Результат: 34/33/33, отсутствие соседних одинаковых групп.

**Тест 7.** Группа имеет 12 уникальных раздач, необходимо выбрать 10.

Результат: 10 различных шестикарточных наборов.

**Тест 8.** Группа имеет 12 уникальных раздач, необходимо выбрать 25.

Результат: первые 12 уникальны, следующие 12 уникальны в новом цикле, затем ещё одна раздача.

**Тест 9.** В группе только одна допустимая раздача.

Результат: повторение разрешено, генерация не зависает.

**Тест 10.** Пользователь не выбрал ни одной группы.

Результат: запуск отклонён, показано понятное сообщение.

**Тест 11.** Быстрое двойное нажатие «Дальше».

Результат: переход только на одну раздачу.

**Тест 12.** Последняя раздача серии.

Результат: новая раздача не создаётся, появляется сообщение «Серия завершена».

**Тест 13.** Разные записи JSON содержат один и тот же набор карт в разном порядке.

Результат: при контроле уникальности они считаются одинаковой шестикарточной раздачей.

Для тестирования случайных алгоритмов предусмотреть возможность подставлять фиксированный генератор случайных чисел или seed.

Не писать нестабильные тесты, которые иногда проходят, а иногда падают из-за случайности.

## 17. Чего сейчас НЕ делать

Не добавлять:

- генерацию комбинаций по правилам покера вне JSON;
- новые карточные игры;
- новые категории, отсутствующие в справочнике;
- вычисление выплат;
- определение победивших комбинаций;
- новые экзаменационные вопросы;
- оценку ответов дилера;
- изменение правил ANTE или BONUS;
- редактирование JSON через интерфейс.

Не изменять рулетку и существующую механику ставок.

## 18. Итоговая проверка в браузере

Проверить полный пользовательский сценарий:

1. Открыть настройки карточного стола.
2. Включить «Русский покер».
3. Выбрать группы Three of a kind, Flush, Straight.
4. Установить количество раздач 10.
5. Сохранить настройки.
6. Вернуться на стол.
7. Убедиться, что отображаются шесть рубашек.
8. Нажать «Старт».
9. Проверить первую раздачу и flip-анимацию.
10. Нажимать «Дальше» до окончания серии.
11. Убедиться, что показано ровно 10 раздач.
12. Убедиться, что используются только три выбранные группы.
13. Проверить распределение 3/3/4 в любом порядке.
14. Проверить, что соседние раздачи не принадлежат одной группе.
15. Проверить минимальное число повторов шестикарточных наборов.
16. Проверить завершение серии.
17. Начать новую серию и убедиться, что порядок и выбор комбинаций могут отличаться.
