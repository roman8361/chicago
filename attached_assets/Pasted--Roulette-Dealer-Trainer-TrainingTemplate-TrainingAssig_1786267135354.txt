Продолжаем развитие Roulette Dealer Trainer.

Сейчас уже есть:

* TrainingTemplate;
* TrainingAssignment;
* создание аттестации;
* назначение нескольких дилеров;
* изменение дилеров;
* изменение настроек;
* удаление аттестации;
* отдельный раздел `Аттестации`;
* дата и время создания.

Следующий этап:

**добавить жизненный цикл TrainingAssignment через статусы.**

На этом этапе пока НЕ генерировать Spin и НЕ реализовывать прохождение аттестации дилером.

## 1. Статусы TrainingAssignment

Расширить модель `TrainingAssignment`.

Использовать следующие статусы:

```ts
type TrainingAssignmentStatus =
  | "CREATED"
  | "IN_PROGRESS"
  | "COMPLETED";
```

Значение:

```text
CREATED
аттестация назначена дилеру, но дилер её ещё не начал

IN_PROGRESS
дилер начал прохождение

COMPLETED
дилер завершил прохождение
```

## 2. Не добавлять общий status в TrainingTemplate

Очень важно:

не хранить один статус всей аттестации в `TrainingTemplate`.

Потому что одна аттестация может быть назначена нескольким дилерам.

Например:

```text
Аттестация Roulette

Иванов     COMPLETED
Петров     IN_PROGRESS
Сидоров    CREATED
```

Поэтому статус принадлежит именно:

`TrainingAssignment`.

## 3. Новые назначения

При создании новой аттестации каждый новый Assignment должен создаваться со статусом:

```ts
status: "CREATED"
```

То же самое при добавлении нового дилера к уже существующей аттестации.

## 4. Старые данные localStorage

В localStorage уже могут существовать старые `TrainingAssignment`.

Если у старой записи отсутствует `status`, приложение не должно падать.

При чтении считать такую запись:

`CREATED`.

Можно сделать безопасную нормализацию данных в storage layer.

Не нужно вручную заставлять пользователя очищать localStorage.

## 5. Отображение на странице аттестации

На странице:

`/manager/attestations/:templateId`

рядом с каждым дилером показать его статус.

Например:

```text
Дилеры

Иванов Иван Иванович
Статус: Не начата

Петров Пётр Сергеевич
Статус: В процессе

Сидоров Алексей Андреевич
Статус: Завершена
```

Использовать пользовательские названия:

```text
CREATED → Не начата
IN_PROGRESS → В процессе
COMPLETED → Завершена
```

Не показывать руководителю технические значения enum.

## 6. Общий статус в списке аттестаций

На странице:

`/manager/attestations`

можно показать вычисляемое состояние аттестации.

Но НЕ сохранять его в Template.

Вычислять по Assignment.

Правило:

### Если все CREATED

показывать:

`Не начата`

### Если хотя бы один IN_PROGRESS

показывать:

`В процессе`

### Если есть COMPLETED, но ещё есть CREATED

показывать:

`В процессе`

### Если все COMPLETED

показывать:

`Завершена`

То есть концептуально:

```text
все COMPLETED
→ Завершена

иначе если есть IN_PROGRESS или COMPLETED
→ В процессе

иначе
→ Не начата
```

## 7. Helper для отображения статуса

Не размазывать проверки строк по JSX.

Создать небольшой helper, например:

```ts
getAssignmentStatusLabel(status)
```

и при необходимости:

```ts
getTemplateStatus(assignments)
```

Названия можно адаптировать под текущую структуру проекта.

## 8. Статусы пока не переключать из интерфейса руководителя

На этом этапе руководитель только ВИДИТ статусы.

Не добавлять кнопки:

* Начать;
* Завершить;
* Изменить статус.

Позже статус будет меняться действиями дилера.

## 9. Подготовить storage для обновления статуса

Добавить минимальную функцию:

```ts
updateTrainingAssignmentStatus(
  assignmentId,
  status
)
```

или аналогичную.

Она понадобится на следующем этапе при запуске аттестации дилером.

Сейчас UI эту функцию может ещё не использовать.

## 10. Ограничение изменения дилеров

Теперь можно ввести первое простое бизнес-правило.

Дилера можно убрать из аттестации только если его Assignment имеет:

`CREATED`.

Если статус:

`IN_PROGRESS`

или:

`COMPLETED`

руководитель не должен иметь возможность снять его checkbox и удалить Assignment.

На экране `Изменить дилеров` такой дилер должен оставаться выбранным, а checkbox быть disabled.

Например:

```text
☑ Иванов Иван Иванович
Не начата

☑ Петров Пётр Сергеевич
В процессе
checkbox disabled

☑ Сидоров Алексей Андреевич
Завершена
checkbox disabled
```

Таким образом мы не удаляем историю уже начатого прохождения.

## 11. Добавлять новых дилеров можно

Даже если другие дилеры уже начали аттестацию, руководитель пока может добавить нового дилера.

Новый Assignment получает:

`CREATED`.

## 12. Ограничение изменения настроек

Добавить простое правило:

настройки TrainingTemplate можно изменять только пока НИ ОДИН Assignment не начал аттестацию.

То есть редактирование разрешено, если:

```text
все Assignment = CREATED
```

Если хотя бы один:

`IN_PROGRESS`

или:

`COMPLETED`

кнопку:

`Изменить настройки`

нужно сделать disabled или скрыть.

Лучше показать пояснение:

`Настройки нельзя изменить после начала аттестации.`

Это важно, чтобы дилер не начал выполнять одно задание, а руководитель затем поменял его параметры.

## 13. Удаление аттестации

Пока использовать такое правило:

полностью удалить аттестацию можно только если:

```text
все Assignment = CREATED
```

Если хотя бы один дилер имеет:

`IN_PROGRESS`

или:

`COMPLETED`

кнопку:

`Удалить аттестацию`

заблокировать.

Показать:

`Аттестацию нельзя удалить после начала прохождения.`

Позже вместе с backend можно будет заменить это архивированием.

## 14. Не добавлять ARCHIVED сейчас

Не вводить пока:

```text
CANCELLED
ARCHIVED
FAILED
PAUSED
```

Нам сейчас достаточно:

```text
CREATED
IN_PROGRESS
COMPLETED
```

Не усложнять lifecycle раньше времени.

## 15. Дата изменения статуса пока не нужна

Не добавлять сейчас:

```ts
startedAt
completedAt
```

Это сделаем тогда, когда реально появятся действия:

`Начать`

и:

`Завершить`.

Сейчас только готовим status.

## 16. TrainingTemplate не менять без необходимости

TrainingTemplate по-прежнему содержит:

```text
id
gameType
config
createdAt
updatedAt
```

Не добавлять туда:

```text
status
dealerStatuses
progress
```

## 17. Проверка статусов

Проверь:

### Сценарий 1

Создаётся новая аттестация для трёх дилеров.

Все три Assignment:

`CREATED`.

На странице отображается:

```text
Иванов — Не начата
Петров — Не начата
Сидоров — Не начата
```

Общий статус:

`Не начата`.

### Сценарий 2

Для теста программно изменить Петрова на:

`IN_PROGRESS`.

Получаем:

```text
Иванов — Не начата
Петров — В процессе
Сидоров — Не начата
```

Общий статус:

`В процессе`.

Петрова нельзя удалить из аттестации.

Настройки нельзя изменить.

Аттестацию нельзя удалить.

### Сценарий 3

Все Assignment:

`COMPLETED`.

Общий статус:

`Завершена`.

## 18. Проверка старых данных

Если в localStorage есть Assignment:

```ts
{
  id: "...",
  trainingTemplateId: "...",
  dealerId: "...",
  createdAt: "..."
}
```

без `status`:

он должен корректно отображаться как:

`Не начата`.

## 19. Не делать кабинет дилера

На этом этапе НЕ реализовывать:

* список аттестаций дилера;
* кнопку `Начать`;
* прохождение;
* вопросы;
* ответы;
* завершение.

Это следующие этапы.

## 20. Не генерировать Spin

Не создавать:

* GeneratedSpin;
* winningNumber;
* bets;
* questions;
* results.

## 21. Не менять Roulette

Не изменять:

* рабочий Roulette screen;
* Settings;
* Spin;
* генераторы;
* racetrack;
* вопросы;
* звуки.
