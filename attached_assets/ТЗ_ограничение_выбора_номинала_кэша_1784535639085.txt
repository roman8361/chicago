ЗАДАЧА

Изменить поведение выбора номиналов в разделе:

«Настройки» → «Номинал кэша на поле».

Пользователь по-прежнему может одновременно использовать не более двух номиналов, но невыбранные номиналы не нужно блокировать или скрывать.

Когда уже выбраны два номинала и пользователь выбирает третий, необходимо автоматически удалить номинал, который был выбран раньше всех, и добавить новый номинал.

Выбор должен работать по принципу FIFO:

«первым выбран — первым удалён».

---

ОСНОВНОЕ ПОВЕДЕНИЕ

Одновременно могут быть выбраны:

- минимум 1 номинал;
- максимум 2 номинала.

Все номиналы всегда остаются:

- видимыми;
- активными;
- доступными для нажатия.

Не применять `disabled` к невыбранным номиналам после выбора двух значений.

---

ПРИМЕР

Изначально выбран номинал:

100

Пользователь нажимает:

500

Результат:

[100, 500]

Порядок выбора:

1. 100 — выбран раньше;
2. 500 — выбран позже.

Затем пользователь нажимает:

1000

Так как уже выбраны два номинала, нужно удалить самый старый выбор:

100

И добавить новый номинал:

1000

Результат:

[500, 1000]

Затем пользователь нажимает:

50

Самым старым выбранным номиналом теперь является:

500

Нужно удалить 500 и добавить 50.

Результат:

[1000, 50]

---

ВАЖНО ПРО ПОРЯДОК

Массив выбранных номиналов должен одновременно хранить порядок выбора.

Первый элемент массива:

- номинал, выбранный раньше всех.

Последний элемент массива:

- номинал, выбранный последним.

Пример:

```ts
selectedCashDenominations = [100, 500];

Это означает:

100 был выбран первым;
500 был выбран вторым.

После выбора 1000:

selectedCashDenominations = [500, 1000];

После выбора 50:

selectedCashDenominations = [1000, 50];

Не сортировать выбранные значения по возрастанию или убыванию, иначе будет потерян порядок выбора.

ЛОГИКА НАЖАТИЯ НА НЕВЫБРАННЫЙ НОМИНАЛ

Если выбран только один номинал:

добавить новый номинал в конец массива.

Пример:

[100] + выбор 500
→ [100, 500]

Если уже выбраны два номинала:

Удалить первый элемент массива.
Добавить новый номинал в конец массива.

Пример:

[100, 500] + выбор 1000
→ [500, 1000]

ЛОГИКА НАЖАТИЯ НА УЖЕ ВЫБРАННЫЙ НОМИНАЛ

Если пользователь нажимает на уже выбранный номинал:

снять этот номинал;
второй выбранный номинал оставить;
порядок оставшегося номинала сохранить.

Пример:

[100, 500]

Пользователь нажимает 100:

[500]

Пользователь нажимает 500:

[100]

МИНИМУМ ОДИН НОМИНАЛ

Не разрешать снять последний оставшийся номинал.

Пример:

[100]

Пользователь повторно нажимает 100.

Результат должен остаться:

[100]

Не допускать пустой массив.

Не использовать браузерный alert.

При необходимости можно использовать существующий toast или inline-подсказку:

«Необходимо выбрать хотя бы один номинал».

РЕКОМЕНДУЕМАЯ ЛОГИКА

const toggleCashDenomination = (value: number) => {
  setSelectedCashDenominations(current => {
    const isSelected = current.includes(value);

    if (isSelected) {
      if (current.length === 1) {
        return current;
      }

      return current.filter(item => item !== value);
    }

    if (current.length < 2) {
      return [...current, value];
    }

    return [current[1], value];
  });
};

Названия переменных и функций адаптировать под текущий проект.

Если в будущем максимальное количество выбранных номиналов будет вынесено в константу, можно использовать универсальную реализацию:

const MAX_SELECTED_CASH_DENOMINATIONS = 2;

const toggleCashDenomination = (value: number) => {
  setSelectedCashDenominations(current => {
    if (current.includes(value)) {
      if (current.length === 1) {
        return current;
      }

      return current.filter(item => item !== value);
    }

    if (current.length < MAX_SELECTED_CASH_DENOMINATIONS) {
      return [...current, value];
    }

    return [
      ...current.slice(1),
      value
    ];
  });
};

ИНТЕРФЕЙС

Все доступные номиналы должны всегда отображаться.

Даже если уже выбраны два номинала:

остальные чекбоксы не блокировать;
не использовать disabled;
не уменьшать прозрачность;
не скрывать;
не запрещать клик.

Выбранные номиналы отображать существующим активным состоянием чекбокса.

При выборе третьего номинала интерфейс должен за одно обновление:

снять отметку с самого старого номинала;
поставить отметку на новом номинале.

Не должно быть промежуточного состояния с тремя выбранными номиналами.

СПИСОК ДОСТУПНЫХ НОМИНАЛОВ

Сохранить весь существующий список номиналов проекта.

Если сейчас используются:

10;
25;
50;
100;
250;
500;
1000;
5000;
10000;
50000;

не удалять и не ограничивать список.

Изменяется только количество одновременно выбранных номиналов.

СОХРАНЕНИЕ В LOCALSTORAGE

Сохранять выбранные номиналы в том же порядке, в котором они были выбраны.

Пример:

[1000, 50]

После перезагрузки страницы порядок должен сохраниться:

1000 считается более старым выбором;
50 считается более новым выбором.

Если после перезагрузки пользователь выберет 500, должно удалиться значение 1000:

[1000, 50] + 500
→ [50, 500]

НОРМАЛИЗАЦИЯ СТАРЫХ НАСТРОЕК

Если в localStorage или старом состоянии сохранено больше двух номиналов:

[10, 25, 50, 100]

оставить последние два значения, потому что они считаются последними выбранными:

[50, 100]

Не оставлять первые два значения.

Удалить дубликаты, сохранив корректный порядок выбора.

Пример:

[100, 500, 100, 1000]

После нормализации должно остаться максимум два последних уникальных номинала:

[100, 1000]

Если после фильтрации не осталось допустимых значений, использовать дефолт проекта, например:

[100]

СБРОС НАСТРОЕК

При нажатии «Сбросить настройки»:

восстановить существующий дефолтный набор номиналов;
дефолт должен содержать не более двух значений;
порядок дефолтных значений должен сохраняться;
чекбоксы должны сразу обновиться.

ГЕНЕРАЦИЯ КЭШ-ФИШЕК

Не менять существующие правила генерации кэш-фишек.

Генератор должен использовать текущий массив выбранных номиналов:

selectedCashDenominations

Если выбран один номинал:

использовать только его.

Если выбраны два номинала:

использовать оба номинала;
обеспечить присутствие каждого номинала;
распределять количество фишек между ними приблизительно равномерно;
подбирать сумму максимально близко к значению «Сумма кэша».

Порядок выбора номиналов не должен менять математический приоритет при генерации, если такого требования ранее не было.

Порядок нужен только для определения, какой номинал удалить при следующем выборе.

НЕ МЕНЯТЬ

доступные номиналы;
внешний вид раздела;
существующий компонент чекбокса;
генерацию суммы кэша;
размещение кэш-фишек;
расчёт выигрыша;
итоговую выплату;
правила пересечения ставок.

КРИТЕРИИ ГОТОВНОСТИ

Одновременно выбрано не более двух номиналов.
Все номиналы всегда видны и доступны для нажатия.
После выбора третьего номинала удаляется самый старый выбранный.
Новый номинал добавляется в конец порядка выбора.
Для [100, 500] выбор 1000 даёт [500, 1000].
Для [500, 1000] выбор 50 даёт [1000, 50].
Повторный клик по выбранному номиналу снимает его.
Последний оставшийся номинал снять нельзя.
В интерфейсе никогда не появляется три выбранных номинала.
Порядок выбора сохраняется в localStorage.
Старые настройки с большим количеством номиналов нормализуются до двух последних уникальных значений.
Генерация кэш-фишек продолжает работать по существующим правилам.
