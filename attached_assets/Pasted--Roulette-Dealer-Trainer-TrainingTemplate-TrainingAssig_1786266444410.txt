Продолжаем развитие Roulette Dealer Trainer.

Сейчас уже есть:

* TrainingTemplate;
* TrainingAssignment;
* страница созданной аттестации;
* возможность изменять список дилеров у созданной аттестации;
* существующий переиспользуемый RouletteSettingsForm;
* RouletteSettingsSummary.

Нужно реализовать только следующий этап:

**изменение настроек уже созданной аттестации.**

## 1. Кнопка "Изменить настройки"

На странице:

`/manager/attestations/:templateId`

кнопка:

`Изменить настройки`

должна открывать отдельный экран редактирования.

Маршрут можно сделать:

`/manager/attestations/:templateId/settings`

## 2. Экран редактирования

На странице показать:

```text
Аттестация

Игра: Roulette

Изменить настройки
```

Ниже должна открываться та же форма настроек Roulette, которая уже используется при создании аттестации.

То есть использовать существующий:

`RouletteSettingsForm`

Не создавать вторую отдельную форму.

## 3. Начальные значения

При открытии формы необходимо:

1. найти TrainingTemplate по `templateId`;
2. взять `template.config`;
3. создать локальную копию;
4. передать её в RouletteSettingsForm.

Форма должна открываться уже заполненной актуальными настройками этой аттестации.

Не использовать default settings вместо сохранённых значений.

## 4. Локальный черновик

До нажатия `Сохранить` изменения не должны сразу менять TrainingTemplate.

То есть:

TrainingTemplate.config
↓
копия для формы
↓
пользователь меняет значения
↓
Сохранить
↓
только после этого обновляется Template

Кнопка `Отмена` должна полностью отбросить изменения.

## 5. Сохранение

После нажатия:

`Сохранить`

нужно обновить только:

`TrainingTemplate.config`

и:

`TrainingTemplate.updatedAt`

Не менять:

* id;
* gameType;
* createdAt;
* TrainingAssignment;
* dealerId;
* список назначенных дилеров.

## 6. updatedAt

При успешном изменении настроек обновить:

`updatedAt`

на текущее время.

`createdAt` должен остаться прежним.

## 7. Снимок настроек

При сохранении Template должен получить независимую копию настроек.

Не сохранять mutable reference на локальный state формы.

После выхода со страницы последующие изменения обычных Settings Roulette не должны менять сохранённую аттестацию.

## 8. Назначения дилеров не менять

Очень важно:

редактирование настроек не должно пересоздавать TrainingAssignment.

Например у аттестации есть:

* Иванов;
* Петров;
* Сидоров.

После изменения `Количество комплитов` эти три Assignment должны остаться с теми же:

* id;
* dealerId;
* createdAt;
* status.

Меняется только TrainingTemplate.config.

## 9. Не создавать новый Template

Редактирование существующей аттестации не должно создавать:

`TrainingTemplate #2`

вместо существующего.

Должен обновляться тот же Template по тому же `id`.

## 10. Возврат после сохранения

После успешного сохранения вернуть пользователя на:

`/manager/attestations/:templateId`

На странице аттестации `RouletteSettingsSummary` должен сразу показать новые значения.

## 11. Отмена

Кнопка:

`Отмена`

должна вернуть пользователя на страницу аттестации без изменений.

Например:

было:

`Комплиты = 2`

в форме пользователь поставил:

`Комплиты = 3`

но нажал `Отмена`.

После возврата должно остаться:

`Комплиты = 2`.

## 12. Использовать существующую валидацию

Форма редактирования должна использовать те же правила:

* min/max;
* числовые ограничения;
* checkbox dependencies;
* select;
* series;
* complete;
* color;
* cash;
* остальные существующие RouletteSettings.

Не создавать отдельные validation rules для редактирования.

## 13. Подготовка к будущим играм

Страница редактирования архитектурно должна определять форму по:

`template.gameType`.

Концептуально:

```ts
switch (template.gameType) {
  case "ROULETTE":
    return <RouletteSettingsForm ... />;
}
```

Позже:

```text
BLACKJACK
→ BlackjackSettingsForm

POKER
→ PokerSettingsForm
```

Сейчас реализовать только ROULETTE.

## 14. Если Template не найден

Если открыт неизвестный `templateId`, показать:

```text
Аттестация не найдена

[ Вернуться в кабинет ]
```

Не допускать runtime error.

## 15. Пока редактирование разрешено

Сейчас можно редактировать аттестацию со статусом CREATED.

В будущем после появления:

* IN_PROGRESS;
* COMPLETED;

мы отдельно введём ограничения.

Сейчас не нужно добавлять сложную проверку статуса.

## 16. Не менять список дилеров

На этом этапе не трогать функциональность:

`Изменить дилеров`.

Она уже реализована отдельно.

## 17. Не генерировать Spin

После изменения настроек пока ничего не генерировать.

Не создавать:

* winningNumber;
* bets;
* questions;
* GeneratedSpin;
* GeneratedExercise.

## 18. Не менять рабочий Roulette

Очень важно:

не менять:

* текущий Spin;
* генераторы ставок;
* игровой экран;
* racetrack;
* вопросы;
* звуки;
* обычное поведение Settings Roulette.

Допустимо использовать уже вынесенный общий RouletteSettingsForm.

## 19. Проверка

Проверь сценарий:

1. Создаю аттестацию Roulette.
2. Назначаю Иванова и Петрова.
3. Открываю аттестацию.
4. Нажимаю `Изменить настройки`.
5. Форма заполнена сохранёнными значениями Template.
6. Меняю несколько параметров.
7. Нажимаю `Сохранить`.
8. Возвращаюсь на страницу аттестации.
9. Новые значения отображаются.
10. `updatedAt` изменился.
11. `createdAt` остался прежним.
12. Template сохранил тот же id.
13. Assignment Иванова и Петрова сохранили свои id.
14. Количество дилеров не изменилось.
15. После перезагрузки браузера новые настройки сохраняются.

Дополнительно:

16. Меняю значение в форме.
17. Нажимаю `Отмена`.
18. Старое значение остаётся.
19. Неизвестный templateId не вызывает runtime error.

## 20. После выполнения

Кратко сообщи:

1. какие файлы созданы;
2. какие файлы изменены;
3. какой маршрут используется;
4. как загружается существующий config;
5. какой компонент формы используется;
6. как реализован локальный draft;
7. как обновляется TrainingTemplate;
8. как обновляется updatedAt;
9. подтверждение, что Assignment не пересоздаются;
10. подтверждение, что Template id не меняется;
11. подтверждение, что Spin не генерируется;
12. подтверждение, что Roulette не изменялась.

Выполни только этот этап.

Не переходи самостоятельно к удалению аттестации или генерации Spin.
