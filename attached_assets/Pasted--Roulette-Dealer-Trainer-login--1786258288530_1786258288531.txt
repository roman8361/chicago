Продолжаем развитие Roulette Dealer Trainer небольшими этапами.

Уже выполнено:

* есть `/login`;
* есть `/manager`;
* есть `/dealer`;
* на странице `/manager` отображается тестовый список дилеров;
* есть кнопка `+ Добавить дилера`;
* существующая Roulette работает без изменений.

Сейчас нужно выполнить только следующий этап: добавить возможность создать нового дилера через интерфейс руководителя.

## 1. Кнопка "+ Добавить дилера"

Сделай кнопку активной.

При нажатии должна открываться небольшая форма добавления дилера.

Можно использовать:

* отдельный блок на странице;
* modal/dialog;
* отдельную небольшую страницу.

Выбери самый простой вариант, который хорошо соответствует текущей структуре проекта.

Большую UI-архитектуру ради этой формы не создавать.

## 2. Поля формы

Пока необходимо только одно поле:

**ФИО дилера**

Например:

```text
Добавить дилера

ФИО
[ Иванов Иван Иванович ]

[ Добавить ]
[ Отмена ]
```

Не добавлять пока:

* логин;
* пароль;
* email;
* телефон;
* роль;
* статус;
* уровень;
* подразделение;
* другие данные.

Это будет добавляться позже при необходимости.

## 3. Валидация

Минимальная проверка:

* ФИО не должно быть пустым;
* пробелы в начале и конце нужно убрать;
* если поле пустое, дилер не создаётся.

Можно показать простое сообщение:

`Введите ФИО дилера`

Сложную валидацию ФИО сейчас делать не нужно.

## 4. Добавление дилера

После нажатия "Добавить":

создай объект:

```ts
Dealer {
  id: string;
  fullName: string;
}
```

Для `id` используй простой безопасный механизм генерации уникального id, подходящий для текущего frontend.

После добавления новый дилер сразу должен появиться в списке дилеров на `/manager`.

Пример:

До:

```text
Дилеры

Иванов Иван Иванович
Петров Пётр Сергеевич
Сидоров Алексей Андреевич
```

Добавляем:

```text
Смирнов Андрей Викторович
```

После:

```text
Дилеры

Иванов Иван Иванович
Петров Пётр Сергеевич
Сидоров Алексей Андреевич
Смирнов Андрей Викторович
```

## 5. Хранение данных

На этом этапе используй `localStorage`.

Нужно, чтобы добавленные дилеры не исчезали после обновления страницы браузера.

При первом запуске, если в `localStorage` ещё ничего нет, можно использовать существующих тестовых дилеров как начальные данные.

После первого изменения список сохраняется в `localStorage`.

Важно:

работу с `localStorage` желательно не размазывать по JSX.

Если это соответствует текущей структуре проекта, вынеси её в небольшой отдельный модуль, например:

```text
dealerStorage.ts
```

с функциями примерно:

```ts
getDealers()
saveDealers()
addDealer()
```

Но не создавай сложный repository/service слой. Позже `localStorage` будет заменён backend API.

## 6. Архитектурное требование

Сохраняем текущую простую модель:

```ts
type Dealer = {
  id: string;
  fullName: string;
};
```

Не добавлять сюда:

```text
login
password
role
```

Учётная запись пользователя позже будет отдельной сущностью.

## 7. Отмена

Кнопка `Отмена` должна:

* закрыть форму;
* не создавать дилера;
* очистить введённое значение.

После успешного добавления форма также должна закрываться или очищаться.

## 8. Пока НЕ делать

Не нужно:

* редактировать дилера;
* удалять дилера;
* делать страницу конкретного дилера;
* генерировать логин;
* генерировать пароль;
* создавать User;
* создавать роли;
* делать авторизацию;
* создавать backend;
* создавать API;
* подключать PostgreSQL;
* создавать тренировку;
* создавать настройки тренировки;
* менять `/dealer`;
* менять Roulette.

## 9. Roulette

Существующий экран Roulette вообще не изменять.

Не менять:

* игровое поле;
* racetrack;
* Spin;
* генераторы;
* ставки;
* вопросы;
* настройки;
* звуки;
* дизайн.

## 10. Проверка

После реализации проверь сценарий:

1. Открываю `/manager`.
2. Вижу существующих дилеров.
3. Нажимаю `+ Добавить дилера`.
4. Ввожу `Смирнов Андрей Викторович`.
5. Нажимаю `Добавить`.
6. Новый дилер появляется в списке.
7. Обновляю страницу браузера.
8. Новый дилер остаётся в списке.
9. Если попытаться добавить пустое ФИО — дилер не создаётся.
10. Кнопка `Отмена` корректно закрывает форму.
11. `/login`, `/dealer` и существующая Roulette продолжают работать.

## 11. После выполнения

Кратко сообщи:

1. какие файлы созданы;
2. какие файлы изменены;
3. где хранится список дилеров;
4. какой ключ `localStorage` используется;
5. как генерируется `id` дилера;
6. подтверждение, что Roulette не изменялась.

Выполни только этот этап и не переходи самостоятельно к созданию страниц дилера, тренировок, логинов или backend.
