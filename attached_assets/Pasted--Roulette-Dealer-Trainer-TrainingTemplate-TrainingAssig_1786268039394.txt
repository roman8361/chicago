Продолжаем развитие Roulette Dealer Trainer.

Сейчас уже есть:

* TrainingTemplate;
* TrainingAssignment;
* аттестации;
* назначение нескольких дилеров;
* статусы Assignment:

  * CREATED;
  * IN_PROGRESS;
  * COMPLETED;
* существующая полностью рабочая Roulette;
* существующая кнопка Spin;
* рабочая генерация:

  * выигрышного номера;
  * комплитов;
  * соседей;
  * серий;
  * цветных ставок;
  * кэша;
  * вопросов и связанных данных.

Следующий этап:

# Создать и сохранить отдельный Spin для каждого TrainingAssignment

ВАЖНО:

На этом этапе НЕ делать кабинет дилера и НЕ запускать прохождение аттестации.

Сначала нужно правильно связать существующий генератор Roulette с новой архитектурой аттестаций.

---

# 1. Главный принцип

Есть одна аттестация:

```text
TrainingTemplate #100

gameType = ROULETTE

config = RouletteSettings
```

Она назначена трём дилерам:

```text
Assignment #1 → Иванов
Assignment #2 → Петров
Assignment #3 → Сидоров
```

Каждый дилер должен получить отдельный случайный Spin:

```text
Assignment #1 → RouletteExercise #1001
Assignment #2 → RouletteExercise #1002
Assignment #3 → RouletteExercise #1003
```

Все три Spin генерируются по одним настройкам:

```text
TrainingTemplate.config
```

Но результат генерации у каждого дилера свой.

---

# 2. НЕ создавать один Spin на весь TrainingTemplate

Неправильно:

```text
TrainingTemplate #100
        ↓
     Spin #500
        ↓
Иванов / Петров / Сидоров
```

В этом случае все дилеры получат одинаковое задание.

Так делать нельзя.

Правильно:

```text
TrainingTemplate #100
        |
        ├── Assignment Иванов
        │          ↓
        │      Spin #501
        │
        ├── Assignment Петров
        │          ↓
        │      Spin #502
        │
        └── Assignment Сидоров
                   ↓
               Spin #503
```

---

# 3. Сначала проанализировать существующий Spin

Перед изменением кода внимательно найти существующую реализацию кнопки:

`Spin`

и определить:

* где выбирается winningNumber;
* где генерируются цветные ставки;
* где генерируется Cash;
* где генерируются Complete;
* где генерируются Neighbors;
* где генерируются Series;
* где применяются RouletteSettings;
* где формируются вопросы;
* какие вспомогательные данные нужны Roulette после генерации;
* какие данные сейчас находятся только в React state.

Не переписывай алгоритмы генерации.

Текущая рабочая Roulette является источником истины.

---

# 4. Не дублировать генераторы

Нельзя делать:

```ts
generateTrainingSpin()
```

со второй независимой реализацией алгоритмов, если существующая Roulette уже имеет такую генерацию.

Нужно добиться, чтобы:

```text
обычная Roulette
```

и:

```text
аттестация
```

использовали одни и те же функции генерации.

---

# 5. Аккуратно отделить генерацию от UI

Если сейчас логика Spin находится непосредственно внутри React-компонента Roulette, выполнить минимальный безопасный рефакторинг.

Нужно получить функцию концептуально вида:

```ts
generateRouletteSpin(settings)
```

или:

```ts
generateRouletteExercise(settings)
```

которая:

1. принимает `RouletteSettings`;
2. выполняет существующую генерацию;
3. возвращает результат генерации.

Например концептуально:

```ts
const exercise = generateRouletteExercise(
  rouletteSettings
);
```

ВАЖНО:

не переписывать сами правила генерации.

Нужно вынести существующую логику настолько, насколько это необходимо для повторного использования.

---

# 6. Обычная кнопка Spin должна продолжить работать

После рефакторинга текущая обычная Roulette должна использовать этот же генератор.

Например:

```text
Spin button
     ↓
generateRouletteExercise(settings)
     ↓
отобразить результат
```

Таким образом генерация остаётся единой.

---

# 7. Модель сохранённого задания

Создать отдельную сущность для результата Roulette.

Предпочтительное название:

`RouletteExercise`

или:

`GeneratedRouletteExercise`.

Например:

```ts
type RouletteExercise = {
  id: string;

  assignmentId: string;

  createdAt: string;

  data: {
    ...
  };
};
```

Но не придумывай поля `data` по памяти.

Сначала изучи фактический результат существующей генерации.

---

# 8. Что должно сохраняться

Сохранённого объекта должно быть достаточно, чтобы в будущем открыть Roulette дилеру БЕЗ повторного Spin.

То есть после загрузки сохранённого Exercise Roulette должна быть способна восстановить именно то игровое поле, которое было сгенерировано.

Нужно сохранить все реально необходимые данные результата генерации.

В том числе, если они используются текущей Roulette:

* winningNumber;
* complete bets;
* dozen complete;
* neighbors;
* series;
* colored bets;
* cash bets;
* значения ставок;
* расположение ставок;
* данные, необходимые для вопросов;
* правильные расчётные значения;
* другие результаты существующего Spin.

ВАЖНО:

не ограничиваться только winningNumber.

---

# 9. Не сохранять визуальные DOM-данные

Не нужно сохранять:

* DOM elements;
* React components;
* CSS;
* canvas;
* пиксельные координаты, если они вычисляются из бизнес-позиции;
* визуальный state, который можно восстановить из результата генерации.

Сохранять нужно данные задания, а не его отрисовку.

Если текущая бизнес-модель ставки уже содержит координаты как обязательную часть существующей реализации — не ломай её искусственно.

---

# 10. Связь с Assignment

Каждый RouletteExercise должен однозначно принадлежать одному:

`TrainingAssignment`.

Предпочтительно:

```ts
assignmentId: string
```

Не связывать Exercise напрямую только с:

`trainingTemplateId`

или:

`dealerId`.

Assignment уже является связью:

```text
Template + Dealer
```

поэтому именно он должен владеть конкретным заданием.

---

# 11. Один Assignment — один текущий Exercise

На данном этапе принять правило:

```text
1 TrainingAssignment
=
1 RouletteExercise
```

Не создавать несколько Spin для одного Assignment.

Перед генерацией обязательно проверить:

```text
существует ли Exercise для assignmentId
```

Если существует:

вернуть существующий.

Не генерировать новый.

---

# 12. Идемпотентная функция

Желательно иметь операцию концептуально:

```ts
getOrCreateRouletteExercise(assignmentId)
```

Логика:

```text
найти Assignment
      ↓
найти существующий Exercise
      ↓
есть
→ вернуть его

нет
→ найти TrainingTemplate
→ взять config
→ generateRouletteExercise(config)
→ сохранить
→ вернуть
```

Названия функций адаптируй к текущей архитектуре.

---

# 13. Настройки брать из Template

Exercise должен генерироваться по:

```ts
trainingTemplate.config
```

а НЕ по текущим глобальным настройкам обычной Roulette.

Например:

в обычной Roulette сейчас:

```text
Neighbors = 5
```

а в созданной аттестации сохранено:

```text
Neighbors = 2
```

Exercise аттестации должен генерироваться с:

```text
Neighbors = 2
```

---

# 14. Template.config — источник условий генерации

Связь должна быть:

```text
TrainingAssignment
       ↓
trainingTemplateId
       ↓
TrainingTemplate
       ↓
config
       ↓
generateRouletteExercise(config)
```

Не копировать настройки в TrainingAssignment.

---

# 15. Exercise — snapshot результата

После генерации Exercise становится зафиксированным заданием.

Например:

```text
winningNumber = 17
neighbors = ...
series = ...
cash = ...
complete = ...
```

Если затем открыть это Assignment второй раз:

должно остаться:

```text
winningNumber = 17
```

а не появиться новый случайный номер.

---

# 16. Даже refresh не должен менять Spin

Проверить:

```text
создали Exercise
↓
обновили браузер
↓
загрузили Exercise
```

Результат должен быть идентичным.

Никакой повторной случайной генерации на render/useEffect.

---

# 17. Хранение

Пока использовать localStorage.

Создать отдельный storage для RouletteExercise.

Например:

```text
roulette-trainer-roulette-exercises
```

или название в текущем стиле проекта.

Не сохранять Exercise внутри TrainingTemplate.

Не сохранять Exercise внутри Dealer.

---

# 18. Storage API

Добавить минимальные операции, например:

```ts
getRouletteExercises()

getRouletteExerciseById(id)

getRouletteExerciseByAssignmentId(
  assignmentId
)

addRouletteExercise(
  exercise
)

deleteRouletteExerciseByAssignmentId(
  assignmentId
)
```

Не создавать сложный Repository framework.

---

# 19. Когда генерировать Exercise

На этом этапе лучше генерировать задания после создания Assignment.

После успешного создания аттестации:

```text
создали Template
↓
создали Assignment для каждого дилера
↓
создать RouletteExercise для каждого Assignment
```

ТОЛЬКО если:

```text
gameType = ROULETTE
```

Таким образом к моменту появления аттестации у каждого дилера уже будет своё готовое задание.

---

# 20. Добавление дилера позже

Если руководитель позже использует:

`Изменить дилеров`

и добавляет нового дилера:

```text
создаётся новый TrainingAssignment
```

для него также нужно создать свой RouletteExercise.

Например:

было:

```text
Иванов → Exercise #1
Петров → Exercise #2
```

добавили:

```text
Сидоров
```

результат:

```text
Сидоров → новый Exercise #3
```

Exercise Иванова и Петрова НЕ регенерировать.

---

# 21. Удаление дилера до начала

Если Assignment со статусом CREATED удаляется из аттестации:

нужно удалить и связанный:

`RouletteExercise`.

То есть:

```text
удалить Assignment
+
удалить его Exercise
```

Но не трогать Exercise других Assignment.

---

# 22. Удаление всей аттестации

При удалении TrainingTemplate сейчас удаляются связанные Assignment.

Теперь также необходимо удалить все RouletteExercise, принадлежащие этим Assignment.

Правильный порядок концептуально:

```text
Template
  ↓
найти Assignments
  ↓
найти их assignmentId
  ↓
удалить Exercises
  ↓
удалить Assignments
  ↓
удалить Template
```

Не оставлять orphan Exercises в localStorage.

---

# 23. Изменение настроек

Сейчас настройки Template разрешено менять только пока все Assignment имеют:

`CREATED`.

Но после появления заранее сгенерированных Exercise возникает важный вопрос.

Если руководитель изменяет настройки ДО начала аттестации:

сохранённые Exercises уже были сгенерированы по старым настройкам.

Поэтому после успешного изменения:

`TrainingTemplate.config`

нужно пересоздать Exercises всех Assignment этого Template.

Только поскольку:

```text
все Assignment = CREATED
```

это безопасно.

Алгоритм:

```text
изменили config
      ↓
сохранить Template
      ↓
для каждого CREATED Assignment
      ↓
удалить старый Exercise
      ↓
сгенерировать новый Exercise
```

Так настройки и реальные задания не расходятся.

---

# 24. Если аттестация уже началась

Для:

```text
IN_PROGRESS
COMPLETED
```

настройки уже нельзя менять.

Поэтому их Exercise никогда не должен регенерироваться.

Существующее правило блокировки настроек сохранить.

---

# 25. Status пока НЕ менять

Сам факт генерации Exercise не означает начало прохождения.

Assignment после генерации остаётся:

`CREATED`.

Не переводить его в:

`IN_PROGRESS`.

Статус будет меняться только тогда, когда дилер реально нажмёт:

`Начать аттестацию`.

---

# 26. На странице руководителя можно добавить технически полезную проверку

На странице конкретной аттестации НЕ нужно показывать весь Spin.

Но можно при необходимости показывать простой признак:

```text
Задание подготовлено
```

для Assignment, у которого Exercise существует.

Это необязательно.

Не перегружай UI.

Главное — корректное создание и хранение данных.

---

# 27. Пока не показывать Spin дилеру

На этом этапе НЕ создавать:

* экран прохождения дилером;
* кнопку Начать;
* dealer roulette mode;
* ответы;
* результаты.

Только подготовить задания.

---

# 28. Не менять внешний вид Roulette

Не менять:

* дизайн;
* поле;
* racetrack;
* chips;
* шрифты;
* звуки;
* расположение элементов.

Разрешается только минимальный внутренний рефакторинг генерации для переиспользования.

---

# 29. Самая важная regression-проверка

После выноса генератора открыть обычную Roulette.

Проверить:

1. Settings работают.
2. Spin работает.
3. Winning Number генерируется.
4. Комплиты генерируются.
5. Соседи генерируются.
6. Серии генерируются.
7. Цвет генерируется.
8. Cash генерируется.
9. Вопросы работают.
10. Звуки работают.
11. Существующие правила ставок не изменились.

Никаких функциональных изменений обычного Spin быть не должно.

---

# 30. Проверка разных дилеров

Создать одну аттестацию:

```text
Roulette
```

для:

```text
Иванов
Петров
Сидоров
```

Проверить:

```text
1 TrainingTemplate
3 TrainingAssignment
3 RouletteExercise
```

У каждого Exercise:

```text
разный id
разный assignmentId
```

Допускается случайное совпадение отдельных значений, например winningNumber, потому что генерация случайная.

Нельзя искусственно заставлять winningNumber обязательно различаться.

Главное — это три независимых запуска генератора.

---

# 31. Проверка повторного чтения

Для Иванова:

```text
Exercise #1
winningNumber = X
```

Считать Exercise повторно.

Должно остаться:

```text
Exercise #1
winningNumber = X
```

Нельзя создать:

```text
Exercise #4
```

для того же Assignment.

---

# 32. Проверка изменения настроек

Создать аттестацию для двух дилеров.

Оба:

`CREATED`.

Запомнить id Exercises.

Изменить настройки аттестации.

После сохранения:

* Template id тот же;
* Assignment id те же;
* старые Exercise удалены;
* для обоих Assignment созданы новые Exercise;
* новые Exercise используют новые настройки.

---

# 33. Проверка добавления дилера

Изначально:

```text
Иванов → Exercise A
```

Добавить Петрова.

Результат:

```text
Иванов → тот же Exercise A
Петров → новый Exercise B
```

Exercise Иванова не должен измениться.

---

# 34. Проверка удаления дилера

Иванов и Петров имеют CREATED.

Удалить Петрова из аттестации.

Должны удалиться:

```text
Assignment Петрова
Exercise Петрова
```

Должны остаться:

```text
Assignment Иванова
Exercise Иванова
```

---

# 35. Проверка удаления аттестации

Удалить всю аттестацию.

Не должно остаться:

* Template;
* её Assignments;
* её Exercises.

Dealer остаются.

---

# 36. Не вводить универсальный GeneratedExercise слишком рано

Сейчас реально реализована только Roulette.

Можно использовать `RouletteExercise`.

Не нужно строить сложную универсальную систему для Blackjack/Poker заранее.

Но связь должна позволять в будущем:

```text
ROULETTE → RouletteExercise
BLACKJACK → BlackjackExercise
POKER → PokerExercise
```

---

# 37. После выполнения

Кратко сообщи:

1. где раньше находилась логика Spin;
2. что было вынесено для повторного использования;
3. какая функция теперь генерирует Roulette Exercise;
4. структуру RouletteExercise;
5. какие данные результата Spin сохраняются;
6. какой localStorage key используется;
7. как Exercise связан с Assignment;
8. как предотвращается повторная генерация;
9. как создаются Exercises для нескольких дилеров;
10. что происходит при добавлении нового дилера;
11. что происходит при удалении дилера;
12. что происходит при изменении настроек;
13. что происходит при удалении аттестации;
14. подтверждение, что Assignment после генерации остаётся CREATED;
15. подтверждение, что обычный Roulette Spin работает как раньше;
16. подтверждение, что алгоритмы ставок не переписывались.

Выполни только этот этап.

НЕ переходи самостоятельно к кабинету дилера, запуску аттестации, ответам или результатам.
