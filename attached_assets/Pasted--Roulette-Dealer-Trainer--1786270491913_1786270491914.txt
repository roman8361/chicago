Продолжаем развитие Roulette Dealer Trainer.

Сейчас уже есть:

* кабинет дилера;
* список `Мои аттестации`;
* страница конкретного TrainingAssignment;
* статусы:

  * CREATED;
  * IN_PROGRESS;
  * COMPLETED;
* заранее созданный RouletteExercise для каждого Assignment;
* существующая рабочая Roulette;
* существующий Roulette UI и игровая логика.

Следующий этап:

# Запуск аттестации дилером

Нужно реализовать переход:

`Начать аттестацию`
→ `CREATED → IN_PROGRESS`
→ открыть существующую Roulette
→ загрузить сохранённый RouletteExercise

На этом этапе пока НЕ реализовывать финальное завершение и результаты.

## 1. Кнопка "Начать аттестацию"

На странице:

`/dealer/attestations/:assignmentId`

для Assignment со статусом:

`CREATED`

кнопка:

`Начать аттестацию`

должна стать рабочей.

При нажатии:

1. проверить Assignment;
2. проверить, что он принадлежит currentDealerId;
3. проверить TrainingTemplate;
4. проверить наличие RouletteExercise;
5. изменить статус Assignment:
   `CREATED → IN_PROGRESS`;
6. открыть экран прохождения Roulette.

## 2. Новый маршрут прохождения

Добавить маршрут, например:

`/dealer/attestations/:assignmentId/play`

или аналогичный в текущем routing style.

Этот маршрут должен открывать существующую Roulette в режиме аттестации.

## 3. Не создавать новую Roulette

Очень важно:

НЕ создавать:

* DealerRoulette;
* AttestationRoulette;
* TrainingRoulette;

как отдельные копии существующего игрового экрана.

Нужно переиспользовать существующий компонент Roulette.

Архитектура должна быть примерно:

```text
Roulette
  |
  ├── обычный режим
  |
  └── режим аттестации
```

Можно использовать props/config/mode.

Например концептуально:

```ts
<Roulette
  mode="ATTESTATION"
  exercise={savedExercise}
/>
```

Названия адаптировать под текущую архитектуру.

## 4. Режимы Roulette

Можно ввести минимальный тип:

```ts
type RouletteMode =
  | "PRACTICE"
  | "ATTESTATION";
```

или аналогичный.

Не строить сложную систему режимов.

Главное — текущая Roulette должна понимать, откуда брать данные.

## 5. Обычный режим

Существующий Roulette должен продолжать работать как раньше:

```text
PRACTICE
↓
Settings
↓
Spin
↓
generateRouletteExercise()
```

Не ломать текущую кнопку Spin.

## 6. Режим аттестации

В режиме:

`ATTESTATION`

Roulette НЕ должна запускать генератор.

Она получает уже существующий:

`RouletteExercise`

и просто отображает его.

Схема:

```text
TrainingAssignment
       ↓
RouletteExercise
       ↓
Roulette mode=ATTESTATION
       ↓
отрисовка сохранённого задания
```

## 7. Запрещена повторная генерация

При открытии `/play` нельзя вызывать:

`generateRouletteExercise()`.

Ни:

* при render;
* при mount;
* в useEffect;
* при refresh.

Использовать исключительно сохранённый Exercise.

## 8. Refresh страницы

Если дилер:

1. начал аттестацию;
2. увидел Roulette;
3. обновил браузер;

должен загрузиться тот же Exercise.

То есть:

* тот же id;
* тот же winningNumber;
* те же ставки;
* те же суммы;
* те же вопросы.

## 9. Статус CREATED → IN_PROGRESS

Статус менять только после успешной проверки всех необходимых данных.

Нельзя сначала поставить IN_PROGRESS, а потом обнаружить, что Exercise отсутствует.

Логически:

```text
найти Assignment
↓
проверить ownership
↓
найти Template
↓
найти Exercise
↓
всё корректно
↓
status = IN_PROGRESS
↓
открыть Roulette
```

## 10. startedAt

Теперь появляется реальное событие начала прохождения.

Поэтому расширить TrainingAssignment:

```ts
startedAt?: string;
```

При первом переходе:

`CREATED → IN_PROGRESS`

записать текущее время.

Полный timestamp можно хранить как ISO.

В UI показывать:

`DD.MM.YYYY HH:mm`

без секунд.

## 11. startedAt записывается один раз

Если дилер позже нажимает:

`Продолжить аттестацию`

нельзя менять startedAt.

То есть:

```text
CREATED
→ IN_PROGRESS
→ startedAt записан

IN_PROGRESS
→ Продолжить
→ startedAt остаётся прежним
```

## 12. Продолжить аттестацию

Для Assignment:

`IN_PROGRESS`

на странице назначения кнопка:

`Продолжить аттестацию`

должна открывать тот же:

`/dealer/attestations/:assignmentId/play`

без изменения status и startedAt.

## 13. COMPLETED

Если статус:

`COMPLETED`

игровой экран пока не открывать для повторного прохождения.

На странице назначения показывать:

`Аттестация завершена`.

Результаты будут отдельным этапом.

## 14. Проверка RouletteExercise

Если Exercise отсутствует:

не генерировать новый автоматически.

Показать:

`Задание не подготовлено. Обратитесь к руководителю.`

Статус оставить без изменений.

Это важно, чтобы скрытая ошибка данных не создала дилеру новое случайное задание.

## 15. Проверка gameType

Сейчас реализована только Roulette.

Если:

`template.gameType === "ROULETTE"`

открывать Roulette.

Для неизвестного/неподдерживаемого gameType показать:

`Эта игра пока не поддерживается.`

Не пытаться открыть Roulette для любой игры.

## 16. Какие данные передать Roulette

Передавать именно сохранённые данные Exercise.

Не подменять их:

* глобальными RouletteSettings;
* текущим результатом Spin;
* случайной генерацией;
* состоянием предыдущей игровой сессии.

## 17. Настройки Roulette в режиме аттестации

В режиме аттестации дилер НЕ должен иметь доступ к настройкам.

Скрыть/disabled:

`Настройки`.

Также не показывать возможность изменить:

* min/max;
* серии;
* соседи;
* комплиты;
* cash;
* color;
* любые параметры генерации.

## 18. Кнопка Spin

В режиме аттестации дилер не должен иметь возможность получить другой Spin.

Поэтому существующую кнопку:

`Spin`

в режиме ATTESTATION:

* скрыть;
  или
* сделать disabled.

Предпочтительно скрыть, если это не ломает layout.

## 19. Нельзя регенерировать задание другими действиями

Проверь, что в режиме ATTESTATION нет действий:

* Новый Spin;
* Сбросить;
* Перегенерировать;
* Randomize;

которые способны изменить Exercise.

Если такие элементы существуют для обычного режима — отключить только в режиме аттестации.

## 20. Игровой экран должен выглядеть как существующий

Не менять:

* поле;
* racetrack;
* ставки;
* цвета;
* размеры;
* шрифты;
* звуки;
* визуальное расположение.

Дилер должен видеть привычный игровой экран Roulette.

## 21. Звуки

Если существующий Roulette при отображении задания использует звуки, не ломать их.

Но не запускать случайный Spin только ради звука.

На этом этапе сохранить текущее поведение настолько, насколько возможно.

## 22. Вопросы

Если существующие вопросы уже являются частью рабочего Roulette после Spin, в режиме аттестации они должны использовать данные сохранённого Exercise.

Не генерировать новый набор вопросов.

Если для подключения вопросов потребуется отдельный большой рефакторинг — не делать его сейчас полностью.

Главное на этом этапе:

загрузить и корректно отобразить сохранённый Spin.

## 23. Кнопка возврата

На игровом экране добавить/сохранить возможность вернуться:

`Назад к аттестации`

→ `/dealer/attestations/:assignmentId`

Возврат не должен:

* сбрасывать status;
* менять Exercise;
* менять startedAt.

Assignment остаётся:

`IN_PROGRESS`.

## 24. Незавершённая аттестация

Если дилер вышел из Roulette до завершения:

статус остаётся:

`IN_PROGRESS`.

В кабинете:

`Статус: В процессе`

и кнопка:

`Продолжить аттестацию`.

## 25. Руководитель должен увидеть новый статус

После того как дилер нажал `Начать аттестацию`, в кабинете руководителя для этого Assignment должно отображаться:

`В процессе`.

Не создавать отдельный status для dealer UI.

Использовать тот же TrainingAssignment.

## 26. После начала нельзя изменить настройки

Уже реализованное правило должно продолжать работать:

если хотя бы один Assignment:

`IN_PROGRESS`

то руководитель не может изменить `TrainingTemplate.config`.

Не обходить эту проверку.

## 27. После начала нельзя удалить Assignment

Уже реализованное правило:

IN_PROGRESS/COMPLETED Assignment нельзя убрать из аттестации.

После реального старта проверить, что это действительно работает.

## 28. После начала нельзя удалить аттестацию

Если хотя бы один Assignment IN_PROGRESS, удалить всю аттестацию нельзя.

Существующее правило должно продолжить работать.

## 29. Не завершать аттестацию

На этом этапе НЕ переводить:

`IN_PROGRESS → COMPLETED`.

Не добавлять:

* completedAt;
* оценку;
* итог;
* процент;
* результаты.

Это будет отдельным этапом после работы с вопросами.

## 30. Не сохранять ответы пока

Не создавать пока:

* DealerAnswer;
* AnswerResult;
* Score;
* mistakes;
* report.

## 31. Проверка основного сценария

Создать аттестацию Roulette для Иванова.

Assignment:

`CREATED`.

Exercise уже существует.

Войти Ивановым.

Проверить:

1. В кабинете статус `Не начата`.
2. Открыть аттестацию.
3. Нажать `Начать аттестацию`.
4. Assignment становится IN_PROGRESS.
5. startedAt установлен.
6. Открывается Roulette.
7. Отображается сохранённый Exercise.
8. Spin отсутствует/недоступен.
9. Settings отсутствуют/недоступны.
10. winningNumber совпадает с сохранённым Exercise.
11. Ставки совпадают с сохранённым Exercise.

## 32. Проверка refresh

На Roulette выполнить refresh.

После refresh:

* Assignment всё ещё IN_PROGRESS;
* startedAt тот же;
* Exercise id тот же;
* winningNumber тот же;
* ставки те же.

## 33. Проверка выхода и возврата

Нажать:

`Назад к аттестации`.

Статус:

`В процессе`.

Кнопка:

`Продолжить аттестацию`.

Нажать её.

Открывается тот же Exercise.

## 34. Проверка второго дилера

Одна аттестация назначена:

Иванову и Петрову.

У каждого свой Exercise.

Иванов начинает.

Должно стать:

```text
Иванов → IN_PROGRESS
Петров → CREATED
```

Exercise Петрова не меняется.

## 35. Проверка отсутствующего Exercise

Для теста удалить Exercise конкретного Assignment.

Нажать `Начать аттестацию`.

Ожидается:

`Задание не подготовлено. Обратитесь к руководителю.`

Assignment остаётся CREATED.

## 36. Regression обычной Roulette

Обязательно проверить обычный режим.

Там по-прежнему:

* есть Settings;
* есть Spin;
* Spin генерирует новый результат;
* работают все ставки;
* работают вопросы;
* работают звуки.

Режим ATTESTATION не должен изменить поведение PRACTICE.

## 37. После выполнения

Кратко сообщи:

1. какой маршрут используется для прохождения;
2. как существующая Roulette переиспользуется;
3. как определяется режим PRACTICE/ATTESTATION;
4. как загружается RouletteExercise;
5. как исключена повторная генерация;
6. когда status меняется на IN_PROGRESS;
7. как хранится startedAt;
8. почему startedAt не меняется при продолжении;
9. что происходит при отсутствии Exercise;
10. как отключены Settings;
11. как отключён Spin;
12. как работает `Продолжить аттестацию`;
13. подтверждение, что COMPLETED пока не реализуется;
14. подтверждение, что обычная Roulette продолжает работать как раньше.

Выполни только этот этап.

Не переходи самостоятельно к завершению аттестации, сохранению ответов или результатам.
