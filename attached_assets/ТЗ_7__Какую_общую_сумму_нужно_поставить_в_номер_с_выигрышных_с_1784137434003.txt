РАСПОЛОЖЕНИЕ ВОПРОСА

Новый вопрос должен идти сразу после вопроса:

«Посчитайте сдачу с пересечений ставок «комплит» со ставками на треке.»

Нумерация должна оставаться полностью динамической.

Не использовать фиксированный номер вопроса.

Если предыдущие вопросы были пропущены, новый вопрос должен получить следующий порядковый номер без пропусков.

---

УСЛОВИЕ ПОКАЗА

Вопрос задавать только в том случае, если в текущем раунде присутствует хотя бы один комплит:

- комплит номера;
- либо комплит дюжины.

Если комплитов нет — вопрос не задавать.

---

ВОПРОС

Пользователь отвечает одним числом.

Вопрос:

«Какую общую сумму нужно поставить в номер с выигрышных ставок «комплит»?»

---

ВАЖНО

Это НЕ сумма выигравших ставок на поле.

Это НЕ сумма выплат.

Это сумма, которую дилер должен поставить в выпавший номер методом «касаний».

---

ЛОГИКА «КАСАНИЙ»

При расчёте нельзя использовать текущую визуализацию поля.

Нужно определить все выигравшие позиции каждого комплита.

Каждая выигравшая позиция считается одним "касанием".

Каждое касание переносится в выпавший номер.

При этом в выпавший номер переносится не фактическая ставка позиции, а значение, по которому играет комплит.

Исключение составляет случай, когда выигравшая позиция уже играет по максимуму из-за пересечения нескольких комплитов.

Такие случаи описаны ниже.

---

КАК ОПРЕДЕЛИТЬ ПО ЧЕМ ИГРАЕТ КОМПЛИТ

Для каждого комплита использовать уже существующую логику.

Например:

Комплит №4

7895

Максимум рулетки = 300

Кратность =100

↓

Комплит играет по:

200

---

ПРАВИЛО

Если выигравшая позиция не превышает максимум,

касание считается по величине,

по которой играет соответствующий комплит.

Если выигравшая позиция уже достигла максимума,

касание считается по максимальному разрешенному значению позиции.

То есть использовать фактически принятую ставку после всех ограничений.

КОМПЛИТ ДЮЖИНЫ

Абсолютно такая же логика должна работать и для комплита дюжины.

Необходимо:

1.

Разложить комплит дюжины по позициям согласно

rouletteRules.json

2.

Определить выигравшие позиции.

3.

Посчитать количество касаний.

4.

Если позиции пересекаются с другими комплитами,

использовать фактически принятую ставку после ограничения максимумом.

5.

Добавить результат к общей сумме.

Никакой отдельной логики для комплита дюжины создавать не нужно.

Он должен участвовать в расчете абсолютно так же, как и комплиты номеров.

---

АЛГОРИТМ

Для каждого комплита:

1.

Определить

playPerUnit

после округления по кратности.

2.

Разложить ставки по позициям согласно JSON.

3.

Определить только выигравшие позиции.

4.

Для каждой выигравшей позиции определить фактическую принятую ставку.

Если позиция не была ограничена —

использовать

playPerUnit.

Если позиция была ограничена максимумом —

использовать фактически принятую ставку.

5.

Каждую выигравшую позицию считать одним касанием.

6.

Добавить стоимость каждого касания к общей сумме.

7.

После обработки всех комплитов вывести общую сумму.

---

ВАЖНО

Не менять существующую генерацию поля.

Не менять расчеты выплаты.

Не менять отображение.

Изменяется только логика расчета правильного ответа на новый вопрос.

---

ОГРАНИЧЕНИЯ

- Не менять предыдущие вопросы.
- Не менять rouletteRules.json.
- Не менять алгоритм генерации комплитов.
- Не менять расчет кратности.
- Не менять расчет сдачи.
- Использовать уже рассчитанные ограничения максимумов.
- Использовать существующие данные о фактически принятых ставках.

---

КРИТЕРИИ ГОТОВНОСТИ

- Новый вопрос появляется сразу после вопроса о пересечениях комплитов со ставками трека.
- Нумерация остается динамической.
- Вопрос отображается только при наличии комплитов.
- Используется логика «касаний».
- Комплиты номеров работают корректно.
- Комплит дюжины участвует в расчете по той же логике.
- Пересечения комплитов учитываются.
- Если позиция уже играет по максимуму, используется фактически принятая ставка.
- При неправильном ответе отображается подробный пошаговый расчет.
