Продолжаем развитие Roulette Dealer Trainer.

Сейчас wizard уже проходит полный путь:

Создать аттестацию
→ Выбрать игру
→ Настроить игру
→ Выбрать дилеров
→ Review

На Review уже отображаются:

* выбранная игра;
* настройки;
* выбранные дилеры;
* кнопка `Создать аттестацию`.

Сейчас нужно реализовать только финальное сохранение аттестации.

## 1. Главная идея

Не создавать отдельную полную копию настроек для каждого дилера.

Нужно разделить:

1. `TrainingTemplate` — общая конфигурация аттестации;
2. `TrainingAssignment` — назначение этой аттестации конкретному дилеру.

Если выбрано три дилера:

Иванов
Петров
Сидоров

должен быть создан:

1 TrainingTemplate

и:

3 TrainingAssignment

## 2. Модель TrainingTemplate

Создай отдельный тип.

Концептуально:

```ts
type TrainingTemplate = {
  id: string;
  gameType: GameType;
  config: RouletteSettings;
  createdAt: string;
  updatedAt: string;
};
```

Если для поддержки будущих игр текущая типизация требует union/generic — используй простой подход, который соответствует проекту.

Главное:

`TrainingTemplate` содержит настройки игры, но НЕ содержит `dealerId`.

## 3. Модель TrainingAssignment

Создай отдельный тип:

```ts
type TrainingAssignmentStatus = "CREATED";

type TrainingAssignment = {
  id: string;
  trainingTemplateId: string;
  dealerId: string;
  status: TrainingAssignmentStatus;
  createdAt: string;
};
```

На этом этапе только статус:

`CREATED`

## 4. Связь сущностей

Должна получиться структура:

```text
TrainingTemplate
      |
      | id
      |
      +------------------+
      |                  |
TrainingAssignment   TrainingAssignment
      |                  |
   dealerId           dealerId
      |                  |
   Иванов             Петров
```

Не дублировать `config` внутри каждого Assignment.

Источник настроек — `TrainingTemplate`.

## 5. Хранение

Пока использовать `localStorage`.

Создать отдельные ключи для:

* TrainingTemplate;
* TrainingAssignment.

Например:

`roulette-trainer-training-templates`

`roulette-trainer-training-assignments`

Названия можно адаптировать под существующий naming style проекта.

Не хранить обе сущности одним массивом, если это усложнит дальнейшую миграцию на backend.

## 6. Storage-модули

Создай минимальные функции.

Например для template:

```ts
getTrainingTemplates()
getTrainingTemplateById()
addTrainingTemplate()
updateTrainingTemplate()
deleteTrainingTemplate()
```

Для assignment:

```ts
getTrainingAssignments()
getAssignmentsByTemplateId()
getAssignmentsByDealerId()
addTrainingAssignment()
deleteTrainingAssignment()
```

Не создавать сложный repository/service framework.

## 7. Нажатие "Создать аттестацию"

На Review при нажатии:

`Создать аттестацию`

нужно:

1. проверить наличие `gameType`;
2. проверить наличие `gameConfig`;
3. проверить наличие хотя бы одного `dealerId`;
4. создать `TrainingTemplate`;
5. сохранить его;
6. для каждого выбранного dealerId создать `TrainingAssignment`;
7. сохранить назначения.

Например выбраны:

```ts
dealerIds = [
  "dealer-1",
  "dealer-2",
  "dealer-3"
]
```

создаётся:

```text
Template #100
```

и:

```text
Assignment #1 → template #100 → dealer-1
Assignment #2 → template #100 → dealer-2
Assignment #3 → template #100 → dealer-3
```

## 8. Снимок настроек

Очень важно:

`TrainingTemplate.config` должен хранить копию `gameConfig` на момент создания.

Не сохраняй ссылку на mutable state таким образом, чтобы дальнейшее изменение wizard или обычных Roulette Settings могло изменить уже созданный Template.

Созданная аттестация должна быть стабильной.

## 9. После успешного создания

После сохранения:

1. очистить текущий wizard;
2. перейти на страницу созданной аттестации.

Добавь маршрут примерно:

`/manager/attestations/:templateId`

или:

`/manager/trainings/:templateId`

В пользовательском интерфейсе предпочтительно использовать термин:

`Аттестация`.

Технические сущности `TrainingTemplate` и `TrainingAssignment` можно оставить без переименования.

## 10. Страница созданной аттестации

Создай минимальную страницу просмотра.

Например:

```text
Аттестация

Игра:
Roulette

Создана:
09.08.2026

Статус:
Создана

Дилеры:
Иванов Иван Иванович
Петров Пётр Сергеевич
Сидоров Алексей Андреевич

Настройки:
[ краткое отображение RouletteSettings ]

[ Изменить настройки ]
[ Изменить дилеров ]
[ Удалить аттестацию ]

[ Назад ]
```

На этом этапе кнопки редактирования можно пока оставить без реализации или подготовить маршруты.

Их функциональность будет отдельными следующими этапами.

## 11. Получение дилеров

На странице аттестации:

1. найти все Assignment по `trainingTemplateId`;
2. получить их `dealerId`;
3. найти соответствующих Dealer;
4. показать ФИО.

Не сохранять ФИО внутри Assignment.

## 12. Отображение настроек

Используй уже созданный:

`RouletteSettingsSummary`

или существующий read-only механизм.

Не создавать ещё один вариант отображения настроек.

## 13. Общий список аттестаций руководителя

Добавь на `/manager` или в отдельный раздел минимальный список созданных аттестаций.

Лучше отдельный блок:

```text
Аттестации

Roulette
3 дилера
09.08.2026

[ Открыть ]
```

Если архитектура кабинета уже предполагает отдельную страницу, можно сделать:

`/manager/attestations`

и кнопку на главной:

`Аттестации`

Но не делай большой редизайн.

Главное — после создания аттестацию можно снова найти и открыть.

## 14. Счётчик дилеров

Для Template количество дилеров вычислять через Assignment.

Не добавлять:

```ts
dealerCount
```

как отдельное сохраняемое поле в TrainingTemplate.

Использовать:

```text
assignments.length
```

чтобы не возникло рассинхронизации.

## 15. Не создавать Spin

На этом этапе аттестация только создаётся и назначается.

НЕ генерировать:

* winningNumber;
* Spin;
* ставки;
* вопросы;
* результаты.

То есть:

```text
TrainingTemplate
+
TrainingAssignments
```

но ещё нет:

```text
GeneratedExercise
```

## 16. Пока не реализовывать редактирование

Кнопки:

`Изменить настройки`

и:

`Изменить дилеров`

можно показать, но функциональность будет следующими этапами.

Не реализовывай их в этом промте.

## 17. Пока не реализовывать удаление

Кнопку:

`Удалить аттестацию`

можно вывести на страницу, но само каскадное удаление Template + Assignments пока оставить следующему этапу.

Если удаление уже было частично реализовано старой моделью Training — не пытайся смешивать его с новой архитектурой.

## 18. Защита от повторного создания

После нажатия `Создать аттестацию` не должно случайно создаваться несколько Template из-за двойного клика.

На время сохранения:

* disable кнопку;
* либо используй существующий простой guard.

Backend пока нет, поэтому сложная защита не требуется.

## 19. Поведение после перезагрузки

После создания и обновления браузера должны сохраниться:

* TrainingTemplate;
* TrainingAssignment;
* связи с дилерами;
* настройки;
* дата создания.

Страница созданной аттестации должна открываться напрямую по URL.

## 20. Если Template не найден

Если пользователь открывает неизвестный `templateId`, показать:

```text
Аттестация не найдена

[ Вернуться в кабинет ]
```

Не допускать runtime error.

## 21. Если дилер был удалён

Поскольку сейчас Dealer можно удалить отдельно, возможна ситуация:

Assignment существует, а Dealer уже удалён.

Страница аттестации не должна падать.

Для такого Assignment можно временно показывать:

`Дилер удалён`

Не пытаться автоматически удалять Assignment.

Правила целостности появятся после backend.

## 22. Проверка

Проверь сценарий:

1. Открываю `/manager`.
2. Нажимаю `Создать аттестацию`.
3. Выбираю Roulette.
4. Настраиваю игру.
5. Выбираю трёх дилеров.
6. Проверяю Review.
7. Нажимаю `Создать аттестацию`.
8. Создаётся ровно один TrainingTemplate.
9. Создаются три TrainingAssignment.
10. Все Assignment ссылаются на один templateId.
11. Открывается страница аттестации.
12. Вижу игру.
13. Вижу настройки.
14. Вижу трёх выбранных дилеров.
15. Обновляю браузер.
16. Аттестация остаётся.
17. Возвращаюсь в кабинет.
18. Вижу созданную аттестацию в списке.
19. Открываю её повторно.
20. Данные совпадают.
21. Wizard после создания очищен.

## 23. Проверка модели данных

Отдельно убедись, что НЕ получилось:

```text
Template Иванов
Template Петров
Template Сидоров
```

с одинаковыми настройками.

Правильный результат:

```text
Template #1

Assignment Иванов → #1
Assignment Петров → #1
Assignment Сидоров → #1
```

## 24. Не менять Roulette

Не изменять:

* Roulette;
* Spin;
* генераторы ставок;
* Settings;
* racetrack;
* вопросы;
* звуки;
* игровое поле.

Этот этап касается только сохранения аттестации и назначений.

## 25. После выполнения

Кратко сообщи:

1. какие файлы созданы;
2. какие файлы изменены;
3. структуру TrainingTemplate;
4. структуру TrainingAssignment;
5. какие localStorage keys используются;
6. как создаются Assignment для нескольких дилеров;
7. как Template связывается с Assignment;
8. какой маршрут используется для страницы аттестации;
9. как вычисляется количество назначенных дилеров;
10. как обрабатывается неизвестный templateId;
11. что происходит с Assignment, если Dealer удалён;
12. подтверждение, что Spin пока не генерируется;
13. подтверждение, что Roulette не изменялась.

Выполни только этот этап.

Не переходи самостоятельно к редактированию, удалению или генерации Spin.
