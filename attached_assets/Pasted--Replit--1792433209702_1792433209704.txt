# Задание для Replit: двойные комбинации русского покера

Необходимо доработать существующий справочник комбинаций русского покера в проекте Roulette Dealer Trainer.

Сейчас работаем **только с русским покером**. Другие виды покера не добавлять.

Основная задача — создать отдельную вкладку «Двойные комбинации», перенести в JSON комбинации из Excel-файла **«Принцип построения базы бонусов.xlsx»**, сгруппировать их и подготовить данные для будущей случайной генерации раздач.

## 1. Новая вкладка «Двойные комбинации»

В существующем разделе:

Настройки карт → Русский покер → Комбинации

добавить вкладку:

**«Двойные комбинации»**

Не удалять и не изменять существующую страницу комбинаций.

Вкладка должна использовать тот же визуальный стиль Chicago / Art Deco, что и остальные разделы проекта.

## 2. Источник данных

Я приложу Excel-файл:

**Принцип построения базы бонусов.xlsx**

Использовать лист, содержащий двойные комбинации русского покера.

В таблице имеются:

- названия групп комбинаций;
- названия раздаваемых и бонусных комбинаций;
- наборы игральных карт;
- дополнительные значения, назначение которых мы уточним позднее.

Необходимо изучить структуру таблицы и корректно установить связь между названием группы, названием конкретной комбинации и соответствующими картами.

Сохранять все существенные сведения об исходной строке, чтобы позднее можно было сверить JSON с Excel.

Не считать пустую ячейку автоматическим окончанием группы, если по структуре таблицы она является продолжением предыдущего названия.

Не придумывать отсутствующие значения.

## 3. Группировка комбинаций

Главное требование — комбинации в JSON должны быть **сгруппированы по названиям из левой колонки Excel**.

Например:

- Two pairs
- Three of a kind
- Straight
- Flush
- Full House
- Four of a kind
- Straight Flush
- Royal Flush

Использовать реальные названия групп из файла, а не только перечисленные примеры.

Каждая группа должна содержать собственный массив доступных раздач.

Принцип:

Группа → раздачи этой группы → шесть карт конкретной раздачи.

В дальнейшем мы будем выбирать:

1. Случайную раздачу из определённой группы.
2. Либо случайную группу, а затем случайную раздачу внутри неё.

Поэтому JSON должен поддерживать удобную выборку по идентификатору группы.

**Не хранить все раздачи в одном общем массиве без группировки.**

## 4. Файл JSON

Для русского покера создать отдельный файл:

`double-combinations.json`

Рекомендуемое расположение:

`src/poker/games/russian-poker/double-combinations.json`

Если архитектура проекта предусматривает другое расположение, использовать существующую структуру.

Не смешивать двойные комбинации с обычными комбинациями.

Файл должен быть доступен для чтения приложением.

Предусмотреть возможность расширения JSON новыми группами, раздачами и свойствами без изменения уже существующих идентификаторов.

## 5. Рекомендуемая структура JSON

Пример структуры (демонстрационные карты, не реальные данные для импорта):

```json
{
  "version": 1,
  "gameId": "russian-poker",
  "type": "double-combinations",
  "groups": [
    {
      "id": "two-pairs",
      "name": "Two pairs",
      "deals": [
        {
          "id": "two-pairs-001",
          "sourceRow": 15,
          "cards": [
            "dj",
            "sk",
            "ck",
            "hj",
            "sq",
            "dq"
          ],
          "bonusCombinations": [
            "Two pairs (+KK)",
            "Two pairs (+2 pairs of picture)",
            "5 Pictures"
          ]
        }
      ]
    },
    {
      "id": "three-of-a-kind",
      "name": "Three of a kind",
      "deals": []
    }
  ]
}
```

Значения:

- `version` — версия структуры JSON.
- `gameId` — идентификатор игры.
- `type` — тип справочника.
- `groups` — массив групп комбинаций.
- `id` группы — стабильный технический идентификатор.
- `name` — оригинальное название группы из Excel.
- `deals` — массив раздач внутри группы.
- `id` раздачи — уникальный стабильный идентификатор.
- `sourceRow` — номер исходной строки Excel.
- `cards` — массив из шести карт.
- `bonusCombinations` — названия бонусных комбинаций, соответствующих конкретной раздаче.

Структуру можно аккуратно адаптировать под реальные особенности Excel.

Не терять сведения из колонки «Раздаваемые комбинации».

Если одной шестикарточной раздаче соответствуют несколько бонусных комбинаций, хранить их в массиве, не дублируя одинаковые раздачи без необходимости.

Дополнительные поля разрешается добавлять, если они имеют понятное назначение.

## 6. Кодирование карт

В проекте уже используются PNG игральных карт.

Существующая схема имён:

- `h` — черви;
- `d` — бубны;
- `c` — трефы;
- `s` — пики.

Достоинства:

`2, 3, 4, 5, 6, 7, 8, 9, 10, j, q, k, a`

Примеры:

- `hk` — король червей;
- `d10` — десятка бубен;
- `cj` — валет треф;
- `sa` — туз пик.

В JSON хранить коды без расширения `.png`.

Не создавать дополнительные изображения.

Использовать существующие карточные ресурсы.

## 7. Обязательное правило уникальности карт

Каждая раздача должна содержать **ровно шесть различных карт** из стандартной колоды из 52 карт.

Например, в одной раздаче недопустимо:

`["dk", "sk", "h7", "ck", "dk", "d7"]`

Здесь `dk` повторяется дважды.

Такая раздача не должна попадать в рабочий JSON без исправления.

Необходимо проверить все импортируемые раздачи.

Условия валидации:

1. Ровно шесть карт.
2. Все карты имеют допустимый код.
3. Все шесть карт уникальны.
4. Каждая карта существует в используемой колоде.
5. Идентификаторы раздач не повторяются.
6. Каждая раздача принадлежит корректной группе.

## 8. Согласованные исправления исходного Excel

Ранее были обнаружены повторяющиеся карты.

Мы согласовали следующие замены:

| Строка Excel | Заменить повторяющуюся карту на | Код |
|---|---|---|
| 48 | Король треф | `ck` |
| 58 | Десятка бубен | `d10` |
| 108 | Король червей | `hk` |
| 110 | Король треф | `ck` |
| 112 | Король червей | `hk` |
| 117 | Четвёрка червей | `h4` |
| 142 | Валет треф | `cj` |

Обратить внимание: исправление четвёрки относится к **строке 117, не 114**.

Исправления применить при формировании JSON.

Нужно заменять конкретную повторяющуюся карту в соответствующей строке, сохраняя остальные пять карт без изменений.

После применения исправлений повторно проверить всю базу.

Если новая карта уже присутствует в той же раздаче или обнаружены другие конфликты, не подбирать новую карту самостоятельно — сообщить о проблеме.

**Оригинальный Excel не изменять.**

## 9. Отображение вкладки

Вкладка «Двойные комбинации» должна читать данные из JSON.

Сверху показать доступные группы комбинаций.

Например:

Two pairs | Three of a kind | Straight | Flush | Full House ...

При выборе группы отображать все раздачи, которые относятся к ней.

Для каждой раздачи показывать:

- название группы;
- название или список соответствующих бонусных комбинаций;
- шесть карт;
- идентификатор раздачи.

Карты желательно отображать с использованием существующих PNG.

Если карточные изображения использовать неудобно на первом этапе, допускается временно отображать коды карт, но структура должна быть подготовлена для настоящих PNG.

Не добавлять игровые действия на странице просмотра.

Пока это только справочник.

## 10. Подготовка к будущей случайной генерации

Сейчас генерацию раздач НЕ подключать к кнопке «Старт».

Однако данные должны быть организованы так, чтобы в дальнейшем можно было реализовать функции следующего назначения:

`getDealsByGroup(groupId)`

Получить все раздачи определённой группы.

`getRandomDealByGroup(groupId)`

Получить случайную раздачу из группы.

`getDealById(dealId)`

Получить конкретную раздачу по идентификатору.

Это требования к будущим возможностям работы с данными, а не обязательные новые игровые действия.

Если функции создаются сейчас, они не должны влиять на существующий процесс раздачи карт.

При случайном выборе каждая запись внутри группы изначально должна иметь одинаковую вероятность выбора. В дальнейшем мы можем добавить веса и ограничения.

## 11. Возможность расширения JSON

Позже мы можем захотеть хранить дополнительные данные:

- описание комбинации;
- приоритет;
- категорию сложности;
- вероятность выбора;
- ограничения генерации;
- дополнительные карты или варианты;
- условия совместимости с другими комбинациями.

Сейчас не нужно заполнять эти поля выдуманными значениями.

Главное — выбрать понятную структуру, которую можно расширять без полного переписывания существующих данных.

Стабильные ID групп и раздач необходимо сохранять.

## 12. Дополнительные колонки Excel

Если в исходном листе имеются дополнительные значения справа от основного набора из шести карт (например, колонки L–Q), пока не включать их в массив `cards` автоматически.

Сначала нужно определить их смысл.

Не превращать их в дополнительные раздачи и не интерпретировать как альтернативные карты без согласования.

Если эти данные содержат значимую информацию, сохранить возможность вернуться к ним через `sourceRow` и исходный Excel.

В итоговом отчёте отдельно сообщить, какие колонки были использованы, а какие пока не импортированы.

## 14. Проверка результата

После импорта обязательно проверить:

1. Все распознанные группы из Excel присутствуют в JSON.
2. Все корректные раздачи распределены по группам.
3. Каждая раздача содержит ровно шесть уникальных карт.
4. Семь согласованных исправлений применены правильно.
5. В JSON нет одинаковых идентификаторов.
6. Нет неизвестных карт.
7. Пустые или объединённые ячейки Excel не привели к потере групп.
8. Названия бонусных комбинаций перенесены корректно.
9. Вкладка «Двойные комбинации» отображает данные из JSON.
10. Переключение между группами работает.
11. Возврат в настройки работает.
12. Существующая раздача русского покера работает без изменений.

Ошибочные или неоднозначные строки не исправлять автоматически, а выводить в отдельный отчёт.
