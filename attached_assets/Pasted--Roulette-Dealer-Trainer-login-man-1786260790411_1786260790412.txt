Продолжаем развитие Roulette Dealer Trainer небольшими этапами.

Уже выполнено:

* `/login`;
* `/manager`;
* `/dealer`;
* список дилеров;
* добавление дилеров;
* хранение дилеров в localStorage;
* страница конкретного дилера `/manager/dealers/:dealerId`;
* существующая Roulette и её Settings работают.

Сейчас нужно реализовать создание тренировок для конкретного дилера.

Есть два важных требования:

1. Экран `Создание тренировки` должен содержать тот же функционал и те же параметры, которые сейчас есть в существующем разделе `Настройки` Roulette.
2. После создания тренировки руководитель должен иметь возможность удалить её.

## 1. Перед изменениями

Сначала внимательно проанализируй существующий экран/компонент `Настройки` Roulette.

Найди:

* все существующие поля;
* переключатели;
* числовые параметры;
* значения по умолчанию;
* ограничения;
* существующий тип/структуру settings;
* где эти настройки сейчас хранятся;
* как они передаются генератору Roulette.

ВАЖНО:

Не придумывай новый сокращённый набор настроек.

Экран создания тренировки должен основываться на РЕАЛЬНО существующих настройках Roulette в текущем проекте.

## 2. Новый маршрут

Добавь:

`/manager/dealers/:dealerId/training/new`

Кнопка `Создать тренировку` на странице выбранного дилера должна открывать этот маршрут.

## 3. Экран создания тренировки

Создай страницу, например:

`CreateTrainingPage`.

В верхней части:

```text
Новая тренировка

Дилер:
Иванов Иван Иванович

Игра:
Roulette
```

Пока доступна только Roulette.

## 4. Настройки тренировки

Главное требование:

Раздел настроек новой тренировки должен иметь тот же набор параметров, который сейчас находится в существующих `Настройках` Roulette.

То есть руководитель при создании тренировки должен фактически получить текущие настройки Roulette.

Не создавай отдельный упрощённый набор:

* neighborsCount;
* completesCount;
* seriesCount;
* colorCount;
* cashAmount;

если существующий Settings содержит больше параметров.

Нужно использовать полный актуальный набор параметров существующего Settings.

## 5. Не дублировать модель настроек

Если в проекте уже существует тип вроде:

```ts
RouletteSettings
```

или аналогичная структура настроек — используй её.

Не создавай параллельно:

```ts
TrainingConfig
```

с теми же полями вручную.

Желательная архитектура:

```text
RouletteSettings
        ↑
        |
Training.config
```

То есть конфигурация Roulette-тренировки должна использовать существующую модель настроек Roulette.

Например:

```ts
type Training = {
  id: string;
  dealerId: string;
  gameType: "ROULETTE";
  status: "CREATED";
  config: RouletteSettings;
  createdAt: string;
};
```

Названия адаптируй под существующий проект.

## 6. По возможности переиспользовать UI Settings

Проверь, можно ли существующий UI настроек Roulette вынести/использовать как переиспользуемый компонент.

Например концептуально:

```tsx
<RouletteSettingsForm
    value={settings}
    onChange={setSettings}
/>
```

Тогда этот компонент можно будет использовать:

```text
Roulette → Настройки
```

и:

```text
Manager → Создать тренировку
```

Но:

НЕ делай большой рефакторинг существующей Roulette.

Если безопасное переиспользование требует серьёзного изменения рабочего Roulette-кода, лучше минимально вынести только форму настроек.

Главное — не создавать две независимые реализации одних и тех же настроек, которые потом начнут отличаться друг от друга.

## 7. Значения по умолчанию

При создании новой тренировки используй те же значения по умолчанию, которые сейчас используются в Settings Roulette.

Не придумывай новые defaults.

## 8. Создание Training

После нажатия:

`Создать тренировку`

создать отдельный объект Training.

Пример структуры:

```ts
type Training = {
  id: string;
  dealerId: string;
  gameType: "ROULETTE";
  status: "CREATED";
  config: RouletteSettings;
  createdAt: string;
};
```

Training связывается с дилером через:

```text
dealerId
```

Не хранить массив тренировок внутри объекта Dealer.

## 9. Пока не генерировать Spin

Очень важно разделить:

```text
Создать тренировку
```

и:

```text
Сгенерировать Spin
```

На этом этапе кнопка `Создать тренировку` только сохраняет Training и выбранные настройки.

Она НЕ должна пока генерировать:

* выигрышный номер;
* соседей;
* серии;
* комплиты;
* цвет;
* кэш;
* позиции ставок;
* вопросы.

Генерация будет следующим отдельным этапом.

## 10. Хранение Training

Пока использовать localStorage.

Создай отдельное хранилище тренировок, например:

`trainingStorage.ts`

с минимальными операциями:

```ts
getTrainings()
getTrainingById()
getTrainingsByDealerId()
addTraining()
deleteTraining()
```

Используй отдельный ключ localStorage.

Не хранить тренировки вместе с дилерами.

## 11. Страница дилера после создания

После создания Training вернуть руководителя на:

`/manager/dealers/:dealerId`

На странице теперь должно отображаться реальное количество тренировок.

Например:

```text
Иванов Иван Иванович

Тренировок: 2

[ Создать тренировку ]


Тренировки

Roulette
Статус: Создана
09.08.2026

[ Удалить ]


Roulette
Статус: Создана
08.08.2026

[ Удалить ]
```

## 12. Удаление тренировки

У каждой созданной тренировки добавить кнопку:

`Удалить`

После нажатия обязательно запросить подтверждение.

Например:

```text
Удалить тренировку?

Это действие нельзя отменить.

[ Удалить ]
[ Отмена ]
```

Можно использовать существующий Dialog/Modal проекта или простой подход, соответствующий текущему UI.

## 13. Поведение удаления

После подтверждения:

1. удалить Training из хранилища;
2. обновить список;
3. обновить количество тренировок.

Например было:

`Тренировок: 3`

после удаления:

`Тренировок: 2`

Удаляться должна только выбранная Training по её `id`.

Другие тренировки и дилеры не должны изменяться.

## 14. Отмена удаления

Если руководитель нажимает:

`Отмена`

ничего не удалять.

## 15. Сейчас Training можно удалять независимо от статуса

Пока существует только статус:

`CREATED`

поэтому удаление разрешено.

Позже, когда появятся:

```text
ASSIGNED
IN_PROGRESS
COMPLETED
```

мы отдельно определим правила удаления/архивирования.

Сейчас эту логику не добавлять.

## 16. Важная архитектура настроек

Нужно прийти к следующей схеме:

```text
              RouletteSettings
                     |
          ┌──────────┴──────────┐
          ↓                     ↓
Existing Roulette         Training.config
Settings screen
```

То есть должен существовать единый формат настроек Roulette.

Не должно получиться:

```text
RouletteSettings
```

и отдельно другой:

```text
ManagerTrainingSettings
```

с дублирующими полями.

Это необходимо, потому что следующим этапом сохранённый `Training.config` будет передаваться непосредственно в генератор существующей Roulette.

## 17. Existing Roulette

Не менять игровую механику существующей Roulette.

Нельзя менять:

* Spin;
* генераторы;
* алгоритм ставок;
* расчёты;
* racetrack;
* игровое поле;
* вопросы;
* звуки;
* визуальный дизайн.

Допускается только минимальный рефакторинг Settings, если он действительно необходим для безопасного переиспользования формы/типа настроек.

## 18. Пока НЕ делать

Не нужно:

* генерировать Spin;
* открывать Roulette после создания Training;
* создавать GeneratedSpin;
* создавать кабинет дилера для Training;
* делать login/password;
* делать настоящий RBAC;
* делать backend;
* делать API;
* подключать PostgreSQL;
* добавлять Poker;
* добавлять Blackjack;
* делать результаты тренировки.

## 19. Проверка создания

Проверь:

1. Открываю `/manager`.
2. Выбираю дилера.
3. Нажимаю `Создать тренировку`.
4. Открывается форма.
5. Форма содержит тот же функционал настроек, что существующий Settings Roulette.
6. Значения по умолчанию соответствуют существующим настройкам.
7. Меняю несколько параметров.
8. Нажимаю `Создать тренировку`.
9. Training сохраняется.
10. Возвращаюсь на страницу дилера.
11. Количество тренировок увеличивается.
12. После обновления браузера Training остаётся.
13. Training содержит сохранённую копию настроек.

ВАЖНО:

Если после создания Training пользователь позже изменит глобальные/текущие Settings Roulette, уже созданная Training не должна самопроизвольно менять свою конфигурацию.

Training должна хранить снимок настроек на момент создания.

## 20. Проверка удаления

Проверь:

1. У созданной Training есть кнопка `Удалить`.
2. Нажимаю её.
3. Появляется подтверждение.
4. Нажимаю `Отмена` — Training остаётся.
5. Повторно нажимаю `Удалить`.
6. Подтверждаю.
7. Удаляется только выбранная Training.
8. Счётчик тренировок уменьшается.
9. После обновления страницы удалённая Training не появляется.
10. Тренировки других дилеров не изменяются.

## 21. После выполнения

Кратко сообщи:

1. какие файлы созданы;
2. какие файлы изменены;
3. какой существующий тип настроек Roulette используется;
4. удалось ли переиспользовать существующий UI Settings;
5. если Settings был немного отрефакторен — что именно изменилось;
6. какая структура Training используется;
7. какой localStorage key используется;
8. как реализовано удаление;
9. как подтверждается удаление;
10. подтверждение, что Spin, генераторы, игровое поле и звуки Roulette не изменялись.

Выполни только этот этап.

Не переходи самостоятельно к генерации Spin или кабинету дилера.
