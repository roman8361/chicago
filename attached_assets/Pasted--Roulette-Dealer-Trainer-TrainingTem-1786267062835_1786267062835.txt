Продолжаем развитие Roulette Dealer Trainer.

Сейчас уже есть:

* создание аттестации;
* TrainingTemplate;
* TrainingAssignment;
* страница отдельной аттестации;
* изменение дилеров;
* изменение настроек;
* удаление аттестации;
* отображение даты и времени создания.

Нужно реализовать только следующий этап:

**отдельный раздел "Аттестации" в личном кабинете руководителя.**

## 1. Кнопка "Аттестации"

На странице:

`/manager`

добавить отдельную кнопку:

`Аттестации`

Итоговый главный экран руководителя должен содержать основные действия:

```text
Личный кабинет руководителя

[ Добавить дилера ]

[ Создать аттестацию ]

[ Аттестации ]
```

Не нужно выводить полный список всех аттестаций непосредственно на главной странице.

## 2. Маршрут

Кнопка:

`Аттестации`

должна открывать:

`/manager/attestations`

Создай отдельную страницу, например:

`ManagerAttestationsPage`

или используй подходящее текущее именование проекта.

## 3. Список всех аттестаций

Страница должна отображать все существующие `TrainingTemplate`.

Для каждого Template получить связанные `TrainingAssignment` и вычислить количество назначенных дилеров.

Пример:

```text
Аттестации

Roulette
Создана: 09.08.2026 12:12
Дилеров: 3

[ Открыть ]

----------------

Roulette
Создана: 08.08.2026 17:45
Дилеров: 1

[ Открыть ]

[ Назад ]
```

## 4. Данные брать из существующего storage

Не создавать отдельную копию списка аттестаций.

Источник истины:

* TrainingTemplate storage;
* TrainingAssignment storage.

Для каждой строки:

`gameType` → из TrainingTemplate

`createdAt` → из TrainingTemplate

`dealerCount` → количество Assignment по templateId

## 5. Количество дилеров не хранить

Не добавлять в TrainingTemplate:

```ts
dealerCount
```

Количество всегда вычислять через:

```text
assignments.length
```

Это важно, потому что список дилеров уже можно редактировать.

После добавления или удаления дилера число в списке аттестаций должно автоматически отражать актуальное состояние.

## 6. Формат даты

Использовать уже сделанный общий formatter.

Показывать:

`DD.MM.YYYY HH:mm`

Например:

`09.08.2026 12:12`

Без секунд.

Не создавать отдельный formatter для этой страницы.

## 7. Открытие аттестации

Кнопка:

`Открыть`

или клик по карточке должен вести на существующую страницу:

`/manager/attestations/:templateId`

Не создавать новую страницу просмотра аттестации.

## 8. Сортировка

Список аттестаций сортировать по дате создания:

**самые новые сверху.**

То есть сначала последняя созданная аттестация.

Не нужно пока добавлять пользовательские настройки сортировки.

## 9. Пустой список

Если аттестаций ещё нет, показать:

```text
Аттестаций пока нет.

[ Создать аттестацию ]
```

Кнопка должна запускать существующий wizard создания аттестации:

`/manager/training/new/game`

или фактический текущий маршрут проекта.

## 10. Название игры

Пользователю показывать нормальное название игры:

`Roulette`

а не техническое:

`ROULETTE`.

Использовать существующий game registry, если он уже позволяет получить title по gameType.

Не создавать отдельный map только для этой страницы, если registry уже существует.

## 11. Минимальная информация в карточке

На этом этапе достаточно показывать:

* игра;
* дата и время создания;
* количество дилеров;
* кнопка `Открыть`.

Не выводить пока огромный summary настроек в общем списке.

Подробности уже есть внутри страницы конкретной аттестации.

## 12. Статус

Если в текущей модели у аттестации ещё нет собственного статуса, не придумывай его на этом этапе.

Не выводить фиктивное:

`Статус: Создана`

если это не хранится в модели.

Статусы будут следующим отдельным этапом.

Если текущая реализация уже использует реальный status — можно его отображать, но не расширять lifecycle сейчас.

## 13. Обновление после удаления

После удаления аттестации и перехода обратно на:

`/manager/attestations`

удалённая запись должна сразу отсутствовать.

Не требовать ручного refresh браузера.

## 14. Обновление после изменения дилеров

Сценарий:

1. Аттестация назначена двум дилерам.
2. В общем списке:
   `Дилеров: 2`.
3. Открываем аттестацию.
4. Добавляем ещё одного дилера.
5. Возвращаемся в список.
6. Должно быть:
   `Дилеров: 3`.

Не сохранять старый count в UI state таким образом, чтобы он устаревал.

## 15. Возврат

Кнопка:

`Назад`

на странице `/manager/attestations`

должна возвращать:

`/manager`.

## 16. Не смешивать с управлением дилерами

Раздел:

`Аттестации`

не должен превращаться в страницу управления дилерами.

Для дилеров уже существует:

`/manager/dealers`.

Здесь только информация об аттестациях.

## 17. Не добавлять поиск и фильтры

Пока НЕ делать:

* поиск;
* фильтр по дилеру;
* фильтр по игре;
* фильтр по статусу;
* пагинацию.

Сначала нужен простой рабочий список.

Эти функции можно добавить позже, когда данных станет больше.

## 18. Не менять создание аттестации

Не менять существующий процесс:

```text
Создать аттестацию
→ Выбрать игру
→ Настройки
→ Дилеры
→ Review
→ Создать
```

Текущий wizard должен продолжить работать без изменений.

## 19. Не менять Roulette

Не изменять:

* Roulette;
* Settings;
* Spin;
* генераторы;
* racetrack;
* вопросы;
* звуки.

## 20. Проверка

Проверь:

1. Открываю `/manager`.
2. Вижу кнопку `Аттестации`.
3. Нажимаю.
4. Открывается `/manager/attestations`.
5. Вижу все созданные TrainingTemplate.
6. Новые находятся сверху.
7. У каждой отображается игра.
8. Дата имеет формат `DD.MM.YYYY HH:mm`.
9. Секунд нет.
10. Количество дилеров вычисляется по Assignment.
11. Нажимаю `Открыть`.
12. Открывается существующая страница аттестации.
13. Меняю список дилеров.
14. Возвращаюсь в список.
15. Количество изменилось.
16. Удаляю аттестацию.
17. Она исчезает из списка.
18. Обновляю браузер.
19. Данные остаются корректными.
20. Если аттестаций нет — вижу кнопку `Создать аттестацию`.

## 21. После выполнения

Кратко сообщи:

1. какие файлы созданы;
2. какие файлы изменены;
3. какой маршрут используется;
4. откуда загружаются Templates;
5. как вычисляется dealerCount;
6. как работает сортировка;
7. как форматируется createdAt;
8. как определяется название игры;
9. куда ведёт `Открыть`;
10. как работает пустое состояние;
11. подтверждение, что wizard не изменялся;
12. подтверждение, что Roulette не изменялась.

Выполни только этот этап.

Не переходи самостоятельно к статусам, генерации Spin или кабинету дилера.
