Продолжаем развитие Roulette Dealer Trainer.

Сейчас уже есть:

* кабинет дилера;
* список его аттестаций;
* запуск аттестации;
* статус `CREATED → IN_PROGRESS`;
* `startedAt`;
* существующая Roulette в режиме аттестации;
* сохранённый RouletteExercise;
* возможность продолжить ту же аттестацию без нового Spin.

Следующий этап:

# Ответы дилера, завершение аттестации и сохранение результата

На этом этапе нужно использовать уже существующий механизм вопросов Roulette и сохранить итог прохождения.

## 1. Главный сценарий

Дилер проходит:

`RouletteExercise`

после чего отвечает на существующие вопросы.

После завершения:

```text
IN_PROGRESS
      ↓
COMPLETED
```

и сохраняется результат конкретного TrainingAssignment.

## 2. Не создавать второй набор вопросов

Очень важно:

в проекте уже существует логика вопросов после Spin.

Не создавать отдельные `AttestationQuestions`, если можно переиспользовать существующие вопросы Roulette.

Нужно использовать тот же механизм вопросов и проверки ответов, который уже работает в обычной Roulette.

Перед изменениями проанализируй:

* где формируется список вопросов;
* где хранится правильный ответ;
* как принимается ответ дилера;
* как проверяется ответ;
* как определяется ошибка;
* какие расчёты выполняются;
* где формируется итог/отчёт.

Не переписывай существующие правила проверки.

## 3. Источник вопросов

В режиме аттестации вопросы должны соответствовать сохранённому:

`RouletteExercise`.

Нельзя повторно генерировать Spin или новое игровое состояние для построения вопросов.

Если вопросы можно детерминированно восстановить из Exercise — использовать это.

Если часть вопросных данных уже была сохранена внутри Exercise — использовать сохранённые данные.

## 4. Сохранение результата

Создать отдельную сущность результата прохождения.

Например:

```ts
type TrainingResult = {
  id: string;
  assignmentId: string;
  answers: TrainingAnswer[];
  totalQuestions: number;
  correctAnswers: number;
  completedAt: string;
};
```

Название можно адаптировать к текущему проекту.

Главный принцип:

`TrainingResult` принадлежит конкретному `TrainingAssignment`.

## 5. Ответ

Можно использовать модель концептуально:

```ts
type TrainingAnswer = {
  questionId: string;
  answer: string | number;
  correct: boolean;
};
```

Но сначала посмотри реальные структуры существующих вопросов.

Не придумывай новую сложную модель, если текущая Roulette уже имеет подходящие типы.

Сохранять необходимо достаточно данных, чтобы потом руководитель мог увидеть:

* вопрос;
* ответ дилера;
* правильный ответ;
* правильно/неправильно.

## 6. Один Assignment — один Result

На текущем этапе:

```text
1 TrainingAssignment
=
1 RouletteExercise
=
1 TrainingResult
```

Не создавать несколько результатов одного прохождения.

## 7. localStorage

Пока результат хранить в localStorage.

Создать отдельный storage, например:

`roulette-trainer-training-results`

или в текущем naming style проекта.

Минимальные операции:

```ts
getTrainingResults()
getTrainingResultByAssignmentId()
addTrainingResult()
```

Если понадобится — `updateTrainingResult()`.

Не хранить результат внутри Dealer или TrainingTemplate.

## 8. Завершение

Последний существующий шаг вопросов должен позволить выполнить:

`Завершить аттестацию`.

Перед завершением проверить, что все обязательные вопросы имеют ответы.

После подтверждения:

1. вычислить результат;
2. сохранить TrainingResult;
3. изменить Assignment:
   `IN_PROGRESS → COMPLETED`;
4. записать:
   `completedAt`;
5. открыть экран результата дилера.

## 9. completedAt

Расширить TrainingAssignment:

```ts
completedAt?: string;
```

Записывать только при первом успешном завершении.

Хранить полный timestamp.

В UI показывать:

`DD.MM.YYYY HH:mm`

без секунд.

## 10. Не менять startedAt

При завершении:

`startedAt`

должен остаться тем временем, когда дилер впервые начал аттестацию.

Не перезаписывать его.

## 11. Результат в процентах

Если существующая логика вопросов позволяет однозначно считать правильные ответы, вычислить:

```text
correctAnswers / totalQuestions
```

и отображать процент.

Например:

```text
Правильных ответов: 8 из 10
Результат: 80%
```

Не придумывать проходной балл.

Пока только фактический результат.

## 12. Если вопросы имеют не бинарную оценку

Если текущая Roulette уже использует более сложную оценку, не заменять её искусственно на простой boolean.

Переиспользовать существующую проверку.

Главное — сохранить фактический итог текущей игровой логики.

## 13. Экран результата дилера

После завершения открыть, например:

`/dealer/attestations/:assignmentId/result`

На странице:

```text
Аттестация завершена

Игра:
Roulette

Начало:
09.08.2026 12:20

Завершение:
09.08.2026 12:35

Правильных ответов:
8 из 10

Результат:
80%

[ Вернуться в кабинет ]
```

## 14. Нужно ли показывать ошибки дилеру

На этом этапе можно показать краткий результат и существующий отчёт по ошибкам, если он уже является частью Roulette.

Не делай новый сложный аналитический отчёт.

Если текущая Roulette после ответов уже показывает:

* правильный расчёт;
* ошибку;
* пример;

переиспользуй этот экран/механизм.

## 15. После COMPLETED нельзя проходить заново

Если Assignment уже:

`COMPLETED`

кнопка `Начать` или `Продолжить` не должна открывать повторное прохождение.

В кабинете дилера:

```text
Статус: Завершена

[ Посмотреть результат ]
```

## 16. Кнопка "Посмотреть результат"

Для COMPLETED Assignment открыть:

`/dealer/attestations/:assignmentId/result`.

Не открывать Roulette повторно.

## 17. Refresh страницы результата

После refresh:

* статус остаётся COMPLETED;
* completedAt остаётся прежним;
* результат остаётся прежним;
* ответы остаются прежними.

Ничего не пересчитывать случайным образом.

## 18. Защита результата

Как и для страницы Assignment:

дилер должен иметь доступ только к результату своего Assignment.

Проверить:

```text
assignment.dealerId === currentDealerId
```

Чужой result не показывать.

## 19. Если Result отсутствует при COMPLETED

Если данные повреждены:

Assignment = COMPLETED

но TrainingResult отсутствует.

Не падать.

Показать:

`Результат аттестации недоступен.`

Не генерировать фиктивный результат.

## 20. Если пользователь покинул вопросы раньше

Если дилер не нажал `Завершить аттестацию`:

Assignment остаётся:

`IN_PROGRESS`.

TrainingResult финальным не считается.

При повторном входе должна быть возможность продолжить.

Если существующая система вопросов уже хранит промежуточные ответы только в React state и они теряются при refresh — не делай сейчас большой autosave, если это требует серьёзного рефакторинга.

Но по возможности сохрани текущие ответы в рамках Exercise/session, чтобы `Продолжить` было логичным.

Если это большой отдельный блок работы, явно сообщи об этом после выполнения.

## 21. Не создавать новый Exercise

При ответах и завершении использовать существующий RouletteExercise.

Никогда не генерировать новый Spin.

## 22. Руководитель должен увидеть COMPLETED

После завершения дилером существующий кабинет руководителя должен автоматически показывать:

```text
Иванов
Завершена
```

потому что изменяется тот же TrainingAssignment.

## 23. Существующие ограничения

После COMPLETED:

* дилера нельзя убрать из аттестации;
* настройки нельзя менять;
* аттестацию нельзя удалить.

Существующая статусная логика должна продолжить работать.

## 24. Не делать проходной/непроходной результат

Пока НЕ вводить:

* Сдал;
* Не сдал;
* pass/fail;
* минимальный процент;
* попытки;
* пересдачу.

Сейчас сохраняется только объективный результат.

## 25. Не делать несколько попыток

Не добавлять:

* attemptNumber;
* retry;
* reset;
* пересоздание Exercise.

Одна Assignment = одно прохождение.

## 26. Проверка

Проверить:

1. Иванов имеет Assignment = CREATED.
2. Нажимает `Начать`.
3. Assignment → IN_PROGRESS.
4. Проходит Roulette.
5. Отвечает на вопросы.
6. Нажимает `Завершить аттестацию`.
7. Создаётся TrainingResult.
8. Assignment → COMPLETED.
9. Записывается completedAt.
10. startedAt не изменяется.
11. Открывается экран результата.
12. Отображается количество правильных ответов.
13. Отображается процент.
14. После refresh всё сохраняется.
15. В кабинете появляется `Завершена`.
16. Вместо `Продолжить` появляется `Посмотреть результат`.
17. Повторное прохождение невозможно.

## 27. Проверка нескольких дилеров

Аттестация назначена Иванову и Петрову.

Иванов завершил:

```text
Иванов → COMPLETED
Петров → CREATED
```

Результат существует только для Иванова.

Петров может независимо начать свой Exercise.

Данные Иванова не должны влиять на Петрова.

## 28. Regression Roulette

Обычный PRACTICE режим должен продолжить работать как раньше.

Не менять:

* алгоритмы вопросов;
* генерацию;
* выплаты;
* Spin;
* Settings;
* звуки;
* игровой UI.

## 29. После выполнения

Кратко сообщи:

1. где раньше была логика ответов;
2. что было переиспользовано;
3. структуру TrainingResult;
4. структуру сохранённых ответов;
5. какой storage используется;
6. как считается итог;
7. когда Assignment становится COMPLETED;
8. как записывается completedAt;
9. какой маршрут используется для результата;
10. как работает `Посмотреть результат`;
11. как защищены чужие результаты;
12. что происходит при COMPLETED без Result;
13. сохраняются ли промежуточные ответы при выходе;
14. подтверждение, что Exercise не регенерируется;
15. подтверждение, что обычная Roulette не изменилась.

Выполни только этот этап.

Не переходи самостоятельно к отчёту руководителя, пересдачам, backend или авторизации.
