Продолжаем развитие кабинета руководителя.

Сейчас руководитель может открыть аттестацию и выбрать конкретного дилера.

Нужно доработать страницу результата конкретного дилера.

Главное требование:

# Руководитель должен видеть полный финальный отчёт дилера

То есть практически тот же отчёт, который видит сам дилер после завершения последнего вопроса.

Не создавать отдельный упрощённый manager-report.

Нужно максимально переиспользовать уже существующий финальный отчёт Roulette.

---

# 1. Сценарий

Руководитель:

```text
Аттестации
→ открывает конкретную аттестацию
→ выбирает завершившего дилера
→ Посмотреть результат
```

После этого открывается полный отчёт прохождения.

---

# 2. В верхней части показать исходную Roulette

На странице результата должна отображаться первоначальная Roulette именно этого дилера.

То есть нужно загрузить:

`RouletteExercise`

по:

`assignmentId`

и показать сохранённое игровое состояние.

Это должна быть та же Roulette, которую дилер получил в начале аттестации.

Показать:

* winningNumber;
* все исходные ставки;
* соседей;
* серии;
* комплиты;
* комплит дюжины;
* цветные ставки;
* cash;
* остальные существующие виды ставок.

Если какой-либо тип ставки отсутствовал в Exercise — естественно его не показывать.

---

# 3. Ничего не генерировать заново

Критически важно:

на странице результата руководителя нельзя вызывать:

`generateRouletteExercise()`

или обычный Spin.

Используется только сохранённый:

`RouletteExercise`

конкретного Assignment.

Например:

```text
TrainingAssignment
      ↓
assignmentId
      ↓
RouletteExercise
```

Именно этот Exercise является исходным заданием дилера.

---

# 4. Roulette должна быть read-only

На странице результата руководителя Roulette используется только для просмотра.

Нельзя показывать или активировать:

* Spin;
* Settings;
* новую генерацию;
* reset;
* изменение ставок;
* какие-либо игровые controls.

Руководитель только видит исходную ситуацию.

---

# 5. Не запускать Spin-анимацию

При открытии результата не нужно снова крутить барабан и запускать звук.

Сразу показать финальное сохранённое игровое состояние.

Это исторический отчёт, а не новое прохождение.

---

# 6. Переиспользовать существующий Roulette UI

Не делать отдельную картинку или новый компонент поля только для отчёта.

Если текущая Roulette уже умеет работать в режиме ATTESTATION с сохранённым Exercise, расширить существующий подход ещё одним read-only вариантом, например концептуально:

```text
PRACTICE
ATTESTATION
REPORT
```

или другим минимальным способом в текущей архитектуре.

Главное:

один и тот же визуальный компонент Roulette должен уметь показать сохранённый Exercise без генерации.

---

# 7. После Roulette показать полный отчёт

Ниже игрового поля руководитель должен видеть тот же полный итоговый отчёт, который формируется дилеру после последнего вопроса.

В нём должны быть:

* все вопросы;
* фактический ответ дилера;
* правильный ответ;
* фактический расчёт;
* правильный расчёт;
* ошибка/верно;
* существующие пояснения;
* существующие примеры, если они уже показываются при ошибке.

Не сокращать отчёт до:

`8 из 10 — 80%`.

Это только summary.

Нужен полный детальный report.

---

# 8. Переиспользовать существующий финальный отчёт дилера

Сначала найти, какой компонент сейчас показывает дилеру отчёт после последнего вопроса.

Например это может быть:

* Report;
* Results;
* QuizReport;
* SpinReport;
* DealerResult;
* ResultsModal;

или другое текущее название.

Не создавать копию этого компонента для руководителя, если его можно сделать reusable.

Концептуально желательно прийти к общему компоненту вроде:

```text
RouletteResultReport
```

который получает готовые данные и может использоваться:

```text
Dealer result
Manager result
```

Но не делать большой рефакторинг, если существующий компонент можно переиспользовать проще.

---

# 9. Источник данных отчёта

Для исторического результата использовать сохранённые данные:

```text
TrainingResult
+
TrainingResult.answers
+
RouletteExercise
```

Не запускать повторную проверку ответов.

Не пересчитывать, был ответ правильным или неправильным.

Это уже сохранено в TrainingResult.

---

# 10. Фактические расчёты

Особенно важно сохранить существующие расчёты Roulette.

Если итоговый отчёт дилера сейчас показывает, например:

```text
Фактический расчёт:
18825 / 100 = 188.25
кратность 25
играет по 175

Ответ дилера:
150

Правильный ответ:
175

Ошибка
```

руководитель должен видеть именно такую же информацию.

То же касается:

* серий;
* комплитов;
* сдачи;
* выплат;
* соседей;
* cash;
* остальных типов вопросов.

Не придумывать новый формат расчётов вручную.

Использовать существующий report model/logic.

---

# 11. Если в TrainingResult сейчас сохранено недостаточно данных

Возможна ситуация:

дилер сразу после прохождения видит подробный отчёт, потому что расчёты ещё находятся в React state, но в TrainingResult сохраняются только:

```text
questionText
dealerAnswer
correctAnswer
correct
```

Тогда после refresh руководитель не сможет восстановить полный отчёт.

В этом случае нужно аккуратно расширить `TrainingAnswer` / `TrainingResult`, чтобы сохранялись данные, необходимые для полного отчёта.

ВАЖНО:

не сохранять JSX/DOM.

Сохранять только business/report data.

Например, если реально требуется:

```ts
type TrainingAnswer = {
  questionId: string;
  questionType: string;
  questionText: string;

  dealerAnswer: ...;
  correctAnswer: ...;
  correct: boolean;

  calculation?: ...;
  explanation?: ...;
  example?: ...;
}
```

Но структуру определить после анализа текущего отчёта.

---

# 12. Не генерировать calculation заново при просмотре

Предпочтительный вариант:

данные, которые были показаны дилеру в финальном отчёте, сохраняются в Result.

Тогда manager-report является историческим snapshot.

Если вычисления полностью детерминированы и проект уже имеет единый formatter отчёта, допускается использовать сохранённый Exercise + Result для отображения.

Но нельзя создавать вторую независимую бизнес-логику расчётов.

---

# 13. Итоговая структура страницы

Пример:

```text
Результат аттестации

Дилер:
Иванов Иван Иванович

Игра:
Roulette

Начало:
09.08.2026 14:20

Завершение:
09.08.2026 14:34

Результат:
8 из 10 — 80%


ИСХОДНОЕ ЗАДАНИЕ

[ Roulette table ]
[ Racetrack ]
[ все первоначальные ставки ]
[ winning number ]


ПОЛНЫЙ ОТЧЁТ

Вопрос 1
...

Фактический расчёт:
...

Ответ дилера:
...

Правильный ответ:
...

Верно / Ошибка


Вопрос 2
...
```

---

# 14. Исходные ставки должны быть именно первоначальными

Очень важно проверить, что на report page используются ставки из сохранённого RouletteExercise.

Не брать текущий state `/roulette`.

Не брать последнюю тренировку.

Не брать новый random.

Не брать Exercise другого дилера.

Связь только:

```text
templateId
↓
assignmentId
↓
RouletteExercise.assignmentId
```

---

# 15. Assignment ownership внутри Template

Перед показом проверить:

```text
assignment.trainingTemplateId === templateId
```

И только после этого загружать Result и Exercise.

---

# 16. Если Exercise отсутствует

Если:

```text
Assignment COMPLETED
TrainingResult есть
RouletteExercise отсутствует
```

страница не должна падать.

Показать summary + полный доступный отчёт и сообщение:

`Исходное игровое поле недоступно.`

Не генерировать replacement Exercise.

---

# 17. Если Result отсутствует

Если Assignment COMPLETED, но TrainingResult отсутствует:

показать:

`Результат аттестации недоступен.`

Не строить фиктивный отчёт только из RouletteExercise.

---

# 18. Если Dealer удалён

Если Dealer больше нет, но исторические данные существуют:

```text
Дилер:
Дилер удалён
```

При этом Result и RouletteExercise всё равно показать.

---

# 19. Руководитель ничего не редактирует

Report полностью read-only.

Нельзя:

* менять ответы;
* исправлять результат;
* менять ставки;
* повторять Spin;
* перезапускать аттестацию;
* менять correctAnswer.

---

# 20. Экран дилера не сломать

После рефакторинга дилер после завершения должен продолжать видеть свой существующий полный отчёт.

Нельзя ухудшить его текущий функционал ради Manager page.

Желательно:

```text
Dealer
        ┐
        ├─> общий Roulette final report
Manager ┘
```

---

# 21. Refresh manager result

Открыть результат завершённого дилера.

Сделать refresh.

После refresh должны снова появиться:

* исходная Roulette;
* те же ставки;
* тот же winningNumber;
* те же ответы;
* те же расчёты;
* те же ошибки;
* тот же итог.

Никакой runtime state прошлого прохождения не должен быть обязательным.

---

# 22. Проверка двух дилеров

Одна TrainingTemplate:

```text
Иванов → Exercise A → Result A
Петров → Exercise B → Result B
```

Открываем Иванова:

показывается только:

```text
Exercise A
Result A
```

Открываем Петрова:

```text
Exercise B
Result B
```

Нельзя использовать template-level Exercise.

---

# 23. Проверка первоначальных ставок

Сравнить:

что дилер видел сразу после Spin-анимации при начале аттестации

с тем, что руководитель видит позже в отчёте.

Должны совпадать:

* winningNumber;
* complete bets;
* dozen complete;
* neighbors;
* series;
* colored bets;
* cash bets;
* суммы;
* позиции.

---

# 24. Не менять игровую генерацию

Не трогать алгоритмы:

* neighbors;
* series;
* complete;
* color;
* cash;
* winningNumber.

Этот этап занимается только историческим отображением уже созданного задания и результата.

---

# 25. Не менять основной `/roulette`

Обычный тренировочный экран `/roulette` должен работать как раньше.

---

# 26. После выполнения

Кратко сообщи:

1. какой существующий компонент финального отчёта дилера найден;
2. удалось ли переиспользовать его для руководителя;
3. как загружается RouletteExercise;
4. как гарантируется связь через assignmentId;
5. как исходная Roulette отображается в read-only режиме;
6. какие controls скрыты;
7. откуда берутся первоначальные ставки;
8. откуда берутся фактические расчёты;
9. пришлось ли расширять TrainingAnswer/TrainingResult;
10. какие дополнительные report-поля были сохранены;
11. как работает refresh;
12. что происходит при отсутствии Exercise;
13. что происходит при отсутствии Result;
14. подтверждение, что дилерский финальный отчёт работает как раньше;
15. подтверждение, что генераторы Roulette не менялись.

Выполни только эту доработку кабинета руководителя.

Остальную UI-полировку Manager/Dealer пока не делать.
