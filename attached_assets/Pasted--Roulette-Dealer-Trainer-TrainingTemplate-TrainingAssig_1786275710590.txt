Продолжаем развитие Roulette Dealer Trainer.

Сейчас уже есть:

* TrainingTemplate;
* TrainingAssignment;
* RouletteExercise;
* TrainingResult;
* ответы дилера;
* статусы:

  * CREATED;
  * IN_PROGRESS;
  * COMPLETED;
* startedAt;
* completedAt;
* итоговое количество правильных ответов;
* процент результата;
* экран результата в кабинете дилера.

Следующий этап:

# Результаты дилеров в карточке аттестации руководителя

Нужно доработать существующую страницу:

`/manager/attestations/:templateId`

чтобы руководитель видел состояние и результат каждого назначенного дилера.

---

# 1. Основной блок "Дилеры"

Сейчас страница уже показывает назначенных дилеров и их статус.

Нужно расширить этот блок.

Пример:

```text
Дилеры

Иванов Иван Иванович
Статус: Завершена
Результат: 80%
[ Посмотреть результат ]

Петров Пётр Сергеевич
Статус: В процессе
Начал: 09.08.2026 14:20

Сидоров Алексей Андреевич
Статус: Не начата
```

---

# 2. Данные получать по Assignment

Для каждого `TrainingAssignment` текущего Template:

1. найти Dealer по `dealerId`;
2. получить status;
3. если есть startedAt — использовать его;
4. если COMPLETED — найти TrainingResult по assignmentId;
5. вывести соответствующую информацию.

Не сохранять результат внутри TrainingTemplate.

---

# 3. CREATED

Для:

`status = CREATED`

показывать:

```text
Иванов Иван Иванович

Статус:
Не начата
```

Не показывать:

* процент;
* startedAt;
* completedAt;
* кнопку результата.

---

# 4. IN_PROGRESS

Для:

`status = IN_PROGRESS`

показывать:

```text
Петров Пётр Сергеевич

Статус:
В процессе

Начал:
09.08.2026 14:20
```

Использовать существующий formatter:

`DD.MM.YYYY HH:mm`

без секунд.

Не показывать фиктивный процент.

---

# 5. COMPLETED

Для:

`status = COMPLETED`

найти:

`TrainingResult`

по:

`assignmentId`.

Показывать:

```text
Иванов Иван Иванович

Статус:
Завершена

Начал:
09.08.2026 14:20

Завершил:
09.08.2026 14:34

Правильных ответов:
8 из 10

Результат:
80%

[ Посмотреть результат ]
```

---

# 6. Не пересчитывать результат заново

Процент и количество правильных ответов брать из сохранённого `TrainingResult`.

Не запускать повторную проверку вопросов.

Не использовать RouletteExercise для повторного подсчёта результата.

Источник истины:

`TrainingResult`.

---

# 7. Если COMPLETED без Result

Возможна повреждённая запись:

```text
Assignment = COMPLETED
TrainingResult отсутствует
```

Страница не должна падать.

Показывать:

```text
Статус:
Завершена

Результат:
Недоступен
```

Кнопку:

`Посмотреть результат`

не показывать или сделать disabled.

Не создавать Result автоматически.

---

# 8. Кнопка "Посмотреть результат"

Для COMPLETED Assignment с существующим TrainingResult добавить:

`Посмотреть результат`

Она должна открыть отдельную страницу руководителя.

Маршрут, например:

`/manager/attestations/:templateId/results/:assignmentId`

или аналогичный текущему routing style.

---

# 9. Страница результата конкретного дилера

Создать страницу:

`ManagerDealerResultPage`

или аналогичную.

На ней показать:

```text
Результат аттестации

Дилер:
Иванов Иван Иванович

Игра:
Roulette

Начало:
09.08.2026 14:20

Завершение:
09.08.2026 14:34

Правильных ответов:
8 из 10

Результат:
80%
```

Ниже — подробные ответы.

---

# 10. Подробные ответы

Для каждого сохранённого TrainingAnswer показать:

```text
Вопрос 1

[текст существующего вопроса]

Ответ дилера:
...

Правильный ответ:
...

Результат:
Верно
```

или:

```text
Результат:
Ошибка
```

Использовать сохранённые данные TrainingAnswer.

---

# 11. Не строить вопросы заново

На странице результата руководителя нельзя заново создавать вопрос по RouletteExercise и вычислять ответы с нуля.

Для истории прохождения использовать сохранённый TrainingResult.answers.

Это важно, потому что Result является снимком фактического прохождения дилера.

---

# 12. Порядок вопросов

Ответы показывать в том же порядке, в котором дилер проходил вопросы.

Не сортировать их по тексту или questionType.

Если в TrainingAnswer сейчас нет порядка, использовать порядок элементов массива `answers`.

---

# 13. Отображение правильных ответов

Если существующая Roulette сохраняет числовой правильный ответ — показать его.

Например:

```text
Ответ дилера:
150

Правильный ответ:
175

Ошибка
```

Не изменять форматирование так, чтобы потерялась точность существующих расчётов.

---

# 14. Существующий отчёт ошибки

В Roulette уже существует логика, где при ошибке может показываться:

* правильный расчёт;
* пример;
* пояснение.

Если эти данные уже сохранены в TrainingAnswer или TrainingResult — вывести их руководителю.

Если они сейчас НЕ сохраняются, не перестраивать всю систему в этом этапе.

Минимум должен быть:

* вопрос;
* ответ дилера;
* правильный ответ;
* верно/ошибка.

Расширенный отчёт можно сделать следующим этапом.

---

# 15. Результат в общем списке аттестаций

На странице:

`/manager/attestations`

можно добавить краткий progress.

Для каждой аттестации вычислять:

```text
Всего дилеров: 5
Завершили: 2
В процессе: 1
Не начали: 2
```

Не сохранять эти числа в TrainingTemplate.

Вычислять по актуальным Assignment.

---

# 16. Пример карточки

Можно отображать:

```text
Roulette

Создана:
09.08.2026 12:12

Дилеров: 5

Завершили: 2
В процессе: 1
Не начали: 2

[ Открыть ]
```

Не нужно пока выводить средний балл.

---

# 17. Общий статус оставить вычисляемым

Существующая логика общего статуса аттестации должна остаться:

* все CREATED → Не начата;
* есть IN_PROGRESS/частично COMPLETED → В процессе;
* все COMPLETED → Завершена.

Не добавлять status в TrainingTemplate.

---

# 18. Проверка принадлежности Result

На странице:

`/manager/attestations/:templateId/results/:assignmentId`

обязательно проверить:

```text
assignment.trainingTemplateId === templateId
```

Нельзя открыть результат Assignment из другой аттестации, просто подставив id в URL.

---

# 19. Если Assignment не найден

Показать:

`Результат не найден`

и кнопку возврата к аттестации.

Не допускать runtime error.

---

# 20. Если Dealer удалён

Если Assignment и Result существуют, но Dealer удалён:

показать:

`Дилер удалён`

и всё равно показать сохранённый результат.

История прохождения не должна пропадать только из-за отсутствия Dealer.

---

# 21. Кнопка "Назад"

На странице результата:

`Назад к аттестации`

должна возвращать:

`/manager/attestations/:templateId`.

---

# 22. Никакого редактирования результата

Руководитель только просматривает Result.

Не добавлять:

* изменить ответ;
* исправить процент;
* изменить статус;
* удалить отдельный Result.

Результат прохождения read-only.

---

# 23. Не показывать секретные технические данные

Не выводить руководителю:

* assignmentId;
* templateId;
* exerciseId;
* localStorage key;
* внутренние JSON.

Показывать бизнес-информацию.

---

# 24. Не менять дилерский Result page

Существующий экран результата дилера продолжает работать.

Можно переиспользовать общие read-only компоненты, если это безопасно.

Например концептуально:

```text
TrainingResultSummary
TrainingAnswersSummary
```

их смогут использовать:

* DealerResultPage;
* ManagerDealerResultPage.

Но не делать большой рефакторинг ради этого.

---

# 25. Не менять Roulette

Не менять:

* Spin;
* анимацию;
* звук;
* генераторы;
* вопросы;
* Settings;
* RouletteExercise.

Этот этап только про отображение уже сохранённых результатов.

---

# 26. Проверка трёх дилеров

Есть одна аттестация:

```text
Иванов → COMPLETED → 80%
Петров → IN_PROGRESS
Сидоров → CREATED
```

Руководитель открывает аттестацию.

Должен увидеть:

```text
Иванов
Завершена
80%
[ Посмотреть результат ]

Петров
В процессе
Начал: ...

Сидоров
Не начата
```

---

# 27. Проверка подробного результата

Нажать у Иванова:

`Посмотреть результат`.

Проверить:

1. ФИО правильное.
2. Игра Roulette.
3. startedAt правильный.
4. completedAt правильный.
5. correctAnswers правильный.
6. totalQuestions правильный.
7. процент правильный.
8. отображаются все ответы.
9. правильность каждого ответа совпадает с сохранённым Result.
10. refresh не меняет данные.

---

# 28. Проверка двух аттестаций

Иванов участвовал в Template A и Template B.

При открытии результата в Template A нельзя случайно показать Result Иванова из Template B.

Связь должна идти через конкретный assignmentId.

---

# 29. Проверка общего списка

Для аттестации из 3 дилеров:

```text
1 COMPLETED
1 IN_PROGRESS
1 CREATED
```

в `/manager/attestations` должно быть:

```text
Дилеров: 3
Завершили: 1
В процессе: 1
Не начали: 1
```

---

# 30. После выполнения

Кратко сообщи:

1. какие файлы созданы;
2. какие изменены;
3. как TrainingResult связывается с дилером на странице руководителя;
4. какой маршрут используется для подробного результата;
5. что отображается для CREATED;
6. что отображается для IN_PROGRESS;
7. что отображается для COMPLETED;
8. как обрабатывается COMPLETED без Result;
9. как отображаются ответы;
10. как проверяется принадлежность Assignment конкретному Template;
11. как вычисляются количества завершивших/проходящих/не начавших;
12. подтверждение, что результаты read-only;
13. подтверждение, что Roulette не менялась.

Выполни только этот этап.

Не переходи самостоятельно к autosave промежуточных ответов, пересдачам, backend или авторизации.
