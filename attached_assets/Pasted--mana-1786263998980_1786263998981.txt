Нужно скорректировать структуру личного кабинета руководителя.

Сейчас в проекте уже есть:

* `/manager`;
* список дилеров;
* добавление дилеров;
* карточка дилера;
* wizard создания тренировки;
* экран выбора игры;
* настройки выбранной игры;
* выбор дилеров;
* существующая Roulette.

Нужно изменить только структуру кабинета руководителя и навигацию, максимально переиспользуя уже реализованный функционал.

## 1. Главная страница кабинета руководителя

На странице:

`/manager`

оставить заголовок:

`Личный кабинет руководителя`

Главными действиями должны стать две кнопки:

* `Добавить дилера`
* `Создать аттестацию`

Пример:

```text
Личный кабинет руководителя

[ Добавить дилера ]

[ Создать аттестацию ]
```

Текущий большой список дилеров на главной странице руководителя больше не является основным содержимым этой страницы.

Если он сейчас находится непосредственно на `/manager`, перенеси его в отдельный экран управления дилерами.

## 2. Кнопка "Добавить дилера"

Несмотря на название кнопки, после нажатия она должна открывать не сразу форму одного нового дилера, а отдельный раздел управления дилерами.

Маршрут можно сделать:

`/manager/dealers`

На странице:

`Управление дилерами`

руководитель должен видеть список всех созданных дилеров.

Пример:

```text
Управление дилерами

[ + Добавить дилера ]

Иванов Иван Иванович
[ Редактировать ]
[ Удалить ]

Петров Пётр Сергеевич
[ Редактировать ]
[ Удалить ]

[ Назад ]
```

Используй уже существующий список дилеров и существующий localStorage.

Не создавай второй независимый источник дилеров.

## 3. Добавление дилера

На странице `/manager/dealers` должна быть кнопка:

`+ Добавить дилера`

При нажатии использовать уже существующий функционал добавления дилера.

Если сейчас форма добавления находится на `/manager`, перенеси или переиспользуй её здесь.

Функциональность должна остаться прежней:

* поле ФИО;
* проверка на пустое значение;
* создание уникального id;
* сохранение в localStorage;
* новый дилер появляется в списке.

## 4. Редактирование дилера

Добавить возможность изменить ФИО существующего дилера.

У каждой записи:

`Редактировать`

После нажатия должна появляться простая форма:

```text
Редактировать дилера

ФИО
[ Иванов Иван Иванович ]

[ Сохранить ]
[ Отмена ]
```

После сохранения:

* изменяется только выбранный дилер;
* его `id` остаётся прежним;
* изменения сохраняются в localStorage;
* после обновления страницы новое ФИО сохраняется.

Не создавать нового дилера вместо старого при редактировании.

## 5. Удаление дилера

У каждого дилера должна быть кнопка:

`Удалить`

Перед удалением обязательно запросить подтверждение:

```text
Удалить дилера?

[ Удалить ]
[ Отмена ]
```

После подтверждения дилер удаляется из localStorage и исчезает из списка.

ВАЖНО:

Пока не реализовывать сложную бизнес-логику по связанным тренировкам/аттестациям.

Если у дилера уже существуют связанные черновые данные в текущей тестовой реализации, не пытайся делать сложное каскадное удаление.

На этом этапе удаляется только Dealer.

Позже для backend отдельно определим правила удаления пользователей и связанных аттестаций.

## 6. Карточка дилера

Если в проекте уже существует маршрут:

`/manager/dealers/:dealerId`

и страница конкретного дилера — не удаляй её.

Она может остаться доступной при клике по ФИО дилера.

То есть:

```text
Управление дилерами
      ↓
Иванов Иван
      ↓
/manager/dealers/:dealerId
```

Но основное управление добавлением/редактированием/удалением теперь находится на `/manager/dealers`.

## 7. Кнопка "Создать аттестацию"

На главной странице `/manager` добавить кнопку:

`Создать аттестацию`

Она должна запускать УЖЕ существующий wizard создания тренировки.

То есть после нажатия:

```text
Создать аттестацию
        ↓
Новая тренировка
        ↓
Выберите игру
```

Не создавай новый wizard.

Переиспользуй уже реализованный экран:

`SelectGamePage`

и существующий маршрут, например:

`/manager/training/new/game`

или фактический текущий маршрут проекта.

## 8. После выбора игры всё оставить как уже сделано

После:

`Новая тренировка → Выберите игру`

процесс должен продолжаться по текущей реализации:

```text
Выбор игры
      ↓
Настройки выбранной игры
      ↓
Выбор дилеров
      ↓
следующий шаг wizard
```

Не менять уже реализованные:

* Game Registry;
* GameType;
* RouletteSettingsForm;
* состояние wizard;
* выбор нескольких дилеров;
* переходы Назад/Далее.

Задача этого этапа — только дать этому процессу правильную точку входа из кабинета руководителя.

## 9. Терминология

В интерфейсе руководителя основное действие должно называться:

`Создать аттестацию`

При этом внутренние технические сущности и маршруты пока можно оставить с названиями:

* Training;
* TrainingWizard;
* training/new;
* GameSettingsPage.

Не нужно сейчас массово переименовывать технические типы Training → Attestation.

Это можно сделать позже отдельно, если решим, что в доменной модели термин `Attestation` должен полностью заменить `Training`.

Сейчас меняем пользовательский интерфейс, а не весь код проекта.

## 10. Главный экран после изменений

Желаемый результат:

```text
Личный кабинет руководителя

[ Добавить дилера ]

[ Создать аттестацию ]
```

`Добавить дилера` →

```text
/manager/dealers

Управление дилерами

[ + Добавить дилера ]

Список дилеров
Редактирование
Удаление
```

`Создать аттестацию` →

```text
Новая тренировка

Выберите игру

Roulette

[ Далее ]
```

и далее уже существующий wizard.

## 11. Навигация назад

На странице `/manager/dealers` должна быть кнопка:

`Назад`

→ `/manager`.

При отмене создания аттестации пользователь также должен возвращаться в кабинет руководителя `/manager`, если у wizard нет более подходящего текущего поведения.

## 12. Пока НЕ делать

Не нужно:

* создавать backend;
* создавать PostgreSQL;
* делать настоящую авторизацию;
* создавать login/password дилерам;
* создавать роли;
* менять структуру TrainingTemplate;
* создавать TrainingAssignment;
* генерировать Spin;
* менять Roulette;
* менять Settings Roulette;
* менять звуки;
* добавлять Blackjack или Poker.

## 13. Проверка

Проверь сценарий управления дилерами:

1. Открываю `/manager`.
2. Вижу `Добавить дилера`.
3. Нажимаю.
4. Открывается `/manager/dealers`.
5. Вижу список существующих дилеров.
6. Добавляю нового.
7. Новый дилер появляется.
8. Редактирую его ФИО.
9. После обновления браузера изменения сохраняются.
10. Нажимаю удалить.
11. Появляется подтверждение.
12. Отмена не удаляет дилера.
13. Подтверждение удаляет выбранного дилера.
14. Остальные дилеры не изменяются.

Проверь сценарий аттестации:

1. Открываю `/manager`.
2. Нажимаю `Создать аттестацию`.
3. Открывается существующий экран `Новая тренировка / Выберите игру`.
4. Выбираю Roulette.
5. Нажимаю Далее.
6. Открываются уже реализованные настройки Roulette.
7. Далее работает существующий выбор нескольких дилеров.
8. Данные wizard не теряются.
