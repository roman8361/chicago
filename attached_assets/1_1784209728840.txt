ЗАДАЧА

Убрать «кривые» сгенерированные суммы ставок «комплит».

После генерации сумма каждого комплита должна округляться до ближайшего значения, кратного настройке:

«Кратность комплита»

---

ОБЛАСТЬ ИЗМЕНЕНИЙ

Правило применять к:

- комплитам отдельных номеров;
- комплиту дюжины.

Не менять сам алгоритм случайной генерации исходной суммы.

Сначала сумма генерируется по существующей логике, после чего округляется до ближайшей кратности комплита.

---

ПРАВИЛО ОКРУГЛЕНИЯ

Использовать математическое округление до ближайшего значения, кратного `completeMultiplicity`.

Формула:

```ts
roundedAmount =
  Math.round(generatedAmount / completeMultiplicity) *
  completeMultiplicity;

Где:

generatedAmount — сумма, полученная текущим генератором;
completeMultiplicity — значение настройки «Кратность комплита»;
roundedAmount — итоговая сумма комплита, которая отображается и используется в раунде.

ПРИМЕРЫ ПРИ КРАТНОСТИ 100

Сгенерировано:

5755

Расчёт:

5755 / 100 = 57,55

Округляем до ближайшего целого:

58

Итог:

5800

Сгенерировано:

3605

Расчёт:

3605 / 100 = 36,05

Округляем до ближайшего целого:

36

Итог:

3600

Дополнительные примеры:

3549 → 3500
3550 → 3600
3649 → 3600
3650 → 3700
5811 → 5800
5860 → 5900

ВАЖНО

Это не округление всегда вниз.

Нужно округлять именно до ближайшей кратности:

если значение ближе к нижней границе — округлить вниз;
если ближе к верхней — округлить вверх;
если значение находится ровно посередине — округлить вверх, как работает Math.round.

ЗНАЧЕНИЕ КРАТНОСТИ

Не хардкодить число 100.

Использовать текущее значение настройки:

«Кратность комплита»

Примеры:

При кратности 25:

5755 → 5750
5763 → 5775

При кратности 50:

5755 → 5750
5775 → 5800

При кратности 100:

5755 → 5800

МИНИМАЛЬНАЯ ИТОГОВАЯ СУММА

После округления сумма не должна стать равной 0 для реально сгенерированного комплита.

Если:

roundedAmount <= 0

использовать минимальное положительное значение:

roundedAmount = completeMultiplicity;

УЧЁТ КОЛИЧЕСТВА ФИШЕК КОМПЛИТА

После округления итоговая сумма комплита по-прежнему может не делиться на chipsRequired без остатка.

Это нормально.

Например:

Комплит №30:

сумма = 5800;
chipsRequired = 30;
5800 / 30 = 193,33.

Существующий вопрос о сдаче с кратности приёма комплитов продолжает рассчитываться по прежней логике.

Новое правило округляет только общую отображаемую сумму комплита до значения, кратного настройке.

КОГДА ВЫПОЛНЯТЬ ОКРУГЛЕНИЕ

Округление должно происходить один раз при создании текущего спина:

генерация исходной суммы
→ округление по кратности комплита
→ сохранение итоговой суммы в состоянии раунда
→ отображение и дальнейшие расчёты

Не пересчитывать сумму:

при переходе между вопросами;
при повторном render;
при открытии «Отчёта по спину»;
при подготовке выигрышного поля.

ЕДИНЫЙ ИСТОЧНИК СУММЫ

После округления во всех частях приложения использовать только roundedAmount.

В том числе:

в данных текущего спина;
в расчёте сдачи;
в расчёте пересечений;
в вопросах аттестуемого;
в подробном отчёте;
в итоговой выплате;
в первоначальном snapshot ставок.

Не показывать пользователю первоначальное неокруглённое значение.

ПРИМЕР ОТОБРАЖЕНИЯ В ОТЧЁТЕ

Было:

Комплит №30: 5755 / 30 = 191.833

После изменения:

Комплит №30: 5800 / 30 = 193.333

При кратности комплита 100.

НЕ ПУТАТЬ ДВЕ КРАТНОСТИ

Есть два разных этапа:

Округление общей сгенерированной суммы комплита до настройки «Кратность комплита».
Расчёт фактической ставки одной фишки и сдачи с кратности приёма.

Не удалять второй этап.

Округлённая общая сумма всё равно участвует в существующем расчёте сдачи.

ОГРАНИЧЕНИЯ

Не менять диапазон случайной генерации.
Не менять chipsRequired.
Не менять состав ставок комплита.
Не менять rouletteRules.json.
Не менять формулы сдачи.
Не применять это правило к сериям или соседям.
Не хардкодить кратность 100.
Изменить только итоговую сумму сгенерированных комплитов.

КРИТЕРИИ ГОТОВНОСТИ

Суммы комплитов всегда кратны настройке «Кратность комплита».
При кратности 100 сумма 5755 становится 5800.
При кратности 100 сумма 3605 становится 3600.
Округление выполняется до ближайшей кратности.
Комплиты номеров и дюжины используют одинаковое правило.
В интерфейсе и отчёте не появляются исходные «кривые» суммы.
Существующий расчёт сдачи продолжает работать.
