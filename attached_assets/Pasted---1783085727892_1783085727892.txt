ЗАДАЧА

Нужно расширить уже существующую проверку дилера:

“Сдача с пересечения на поле комплитов”

Сейчас в этом вопросе учитывается только комплит дюжины.

Теперь нужно дополнительно учитывать:

* комплиты номеров;
* пересечения комплитов номеров между собой;
* пересечения комплитов номеров с комплитом дюжины;
* пересечения комплитов с уже стоящими ставками на поле.

---

УСЛОВИЕ ПОЯВЛЕНИЯ ВОПРОСА

Вопрос “Сдача с пересечения на поле комплитов” задавать только если включён хотя бы один тип комплита:

* Комплит в поле = Да
* или Комплит дюжины = Да

Если комплиты выключены, вопрос не задавать.

---

ИСТОЧНИК ДАННЫХ

Все правила комплитов брать только из `rouletteRules.json` через `rouletteRulesService`.

Для комплита дюжины использовать:

`dozenComplete.dozens[]`

Для комплитов номеров использовать:

`completeBets[]`

У каждого комплита номера уже есть:

* `number`
* `chipsRequired`
* `payoutInChips`
* `bets`

Внутри `bets` использовать группы:

* `straightUp`
* `splits`
* `streets`
* `corners`
* `sixLines`

---

ОБЩИЙ ПРИНЦИП

Все комплиты считаются приоритетными и ставятся первыми.

Если несколько комплитов ставятся на одну и ту же позицию, их суммы складываются.

После этого проверяется лимит позиции.

Если итоговая сумма комплитов + уже стоящие ставки поля превышает лимит позиции, превышение считается сдачей.

---

КАК СЧИТАТЬ “ПО ЧЁМ ИГРАЕТ” КОМПЛИТ

Для каждого комплита:

1. Взять сумму комплита:

`amount`

2. Взять количество фишек из JSON:

`chipsRequired`

3. Посчитать:

`rawPlay = amount / chipsRequired`

4. Если `rawPlay > maximum`, использовать максимум рулетки:

`playBase = maximum`

Иначе:

`playBase = rawPlay`

5. Округлить вниз до ближайшей кратности:

`playPerUnit = floor(playBase / multiplicity) * multiplicity`

---

ДЛЯ КОМПЛИТА ДЮЖИНЫ

Пример:

Комплит дюжины = 18825
chipsRequired = 100
Кратность = 25

18825 / 100 = 188.25
Округляем вниз до 175

Комплит дюжины играет по:

175

Каждая позиция из JSON умножается на 175.

---

ДЛЯ КОМПЛИТА НОМЕРА

Пример:

Комплит номера 5 = 5925
Из JSON:

`chipsRequired = 40`

Кратность = 25

5925 / 40 = 148.125
Округляем вниз до 125

Комплит номера 5 играет по:

125

Каждая позиция из JSON умножается на 125.

Пример:

Straight Up 5:

chips = 1
ставка комплита = 125 × 1 = 125

Split 4-5:

chips = 2
ставка комплита = 125 × 2 = 250

Corner 4-5-7-8:

chips = 4
ставка комплита = 125 × 4 = 500

Six-Line 4-5-6-7-8-9:

chips = 6
ставка комплита = 125 × 6 = 750

---

НОРМАЛИЗАЦИЯ ПОЗИЦИЙ

Чтобы корректно находить пересечения, одинаковые ставки должны иметь одинаковый ключ.

Для каждой позиции нужно формировать ключ:

`betType:numbers`

Где:

* `betType` = straightUp / split / street / corner / sixLine
* `numbers` = отсортированный список номеров через дефис

Примеры:

Straight Up 5:

`straightUp:5`

Split 4-5:

`split:4-5`

Corner 4-5-7-8:

`corner:4-5-7-8`

Six-Line 4-5-6-7-8-9:

`sixLine:4-5-6-7-8-9`

Важно:

`split:4-5` и `split:5-4` должны считаться одной и той же позицией.

---

АЛГОРИТМ РАСЧЁТА ПЕРЕСЕЧЕНИЙ

1. Создать общий словарь позиций:

`positionMap`

2. Добавить в него все ставки комплита дюжины, если он есть.

3. Добавить в него все ставки комплитов номеров, если они есть.

4. Если несколько комплитов попали на одну позицию, сложить суммы.

Пример:

Комплит дюжины ставит на Split 4-5:

350

Комплит номера 5 ставит на Split 4-5:

250

Итого комплиты на позиции:

600

5. Добавить существующие ставки поля:

* цветные фишки;
* кэш-фишки.

6. Для каждой позиции посчитать:

`totalAmount = completeAmount + fieldColorAmount + fieldCashAmount`

7. Посчитать лимит позиции.

8. Если `totalAmount > positionLimit`, сдача:

`change = totalAmount - positionLimit`

9. Общая сдача:

сумма всех `change` по всем позициям.

---

ЛИМИТЫ ПО ТИПАМ СТАВОК

Использовать максимум рулетки из настроек.

Если максимум = 200:

* Straight Up: 200
* Split: 400
* Street: 600
* Corner: 800
* Six-Line: 1000

Формула:

* Straight Up = maximum × 1
* Split = maximum × 2
* Street = maximum × 3
* Corner = maximum × 4
* Six-Line = maximum × 5

---

УЧЁТ ЦВЕТНЫХ ФИШЕК

Если на позиции есть цветная фишка:

`fieldColorAmount = chipsCount × colorNominal`

Где:

* `chipsCount` — количество цветных фишек на позиции;
* `colorNominal` — номинал цвета из настроек.

---

УЧЁТ КЭШ-ФИШЕК

Если на позиции есть кэш-фишка:

`fieldCashAmount = сумма кэша на этой позиции`

---

ВАЖНО ПРО ПРИОРИТЕТ

Комплиты считаются приоритетными.

Сдача считается как превышение лимита позиции.

То есть если комплиты + существующие ставки превысили лимит, excess возвращается как сдача.

---

ПРИМЕР ПЕРЕСЕЧЕНИЯ КОМПЛИТА ДЮЖИНЫ И КОМПЛИТА НОМЕРА

Максимум = 200
Кратность = 25

Комплит дюжины играет по 175.
На Split 4-5 он ставит:

175 × 2 = 350

Комплит номера 5 играет по 125.
На Split 4-5 он ставит:

125 × 2 = 250

Итого на Split 4-5:

350 + 250 = 600

Лимит Split:

200 × 2 = 400

Сдача:

600 - 400 = 200

---

ПРИМЕР С ПОЛЕМ

Максимум = 200
Кратность = 25

Комплит номера 5 играет по 125.
На Straight Up 5 он ставит:

125 × 1 = 125

На Straight Up 5 уже есть кэш:

100

Итого:

125 + 100 = 225

Лимит Straight Up:

200

Сдача:

225 - 200 = 25

---

ОТЧЁТ

В итоговом отчёте для вопроса:

“Сдача с пересечения на поле комплитов”

при ошибке показывать подробный расчёт.

Показывать только позиции, где есть сдача.

Для каждой такой позиции показать:

* позицию;
* лимит позиции;
* сумма от комплита дюжины, если есть;
* сумма от комплитов номеров, если есть;
* сумма цветных фишек поля, если есть;
* сумма кэша поля, если есть;
* итог на позиции;
* сдача.

Пример:

Split 4-5
Лимит: 400
Комплит дюжины: 350
Комплит №5: 250
Итого: 600
Сдача: 600 - 400 = 200

Straight Up 5
Лимит: 200
Комплит №5: 125
Кэш на поле: 100
Итого: 225
Сдача: 225 - 200 = 25

Итого сдача: 225

Если пользователь ответил правильно, подробный расчёт не показывать.

---

ЧТО НЕ ДЕЛАТЬ

На этом этапе не нужно:

* менять генерацию комплитов;
* менять отображение комплитов;
* менять генерацию кэша;
* менять генерацию цветных фишек;
* считать выигрыш по комплитам;
* добавлять отдельный вопрос по комплитам номеров;
* сохранять историю;
* добавлять БД.

---

ОГРАНИЧЕНИЯ

* Не менять `rouletteRules.json`.
* Не хардкодить ставки комплитов в коде.
* Все ставки комплитов брать из JSON.
* Не менять расчёт “Сдача кратности комплитов”.
* Не менять остальные вопросы дилера.
* Не менять геометрию поля.
* Не менять трек.
* Вносить минимально необходимые изменения.

---

КРИТЕРИИ ГОТОВНОСТИ

* Вопрос “Сдача с пересечения на поле комплитов” учитывает комплит дюжины.
* Вопрос учитывает комплиты номеров.
* Ставки комплитов номеров берутся из `rouletteRules.json`.
* Пересечения комплитов между собой учитываются.
* Пересечения комплитов с кэшем на поле учитываются.
* Пересечения комплитов с цветными фишками учитываются.
* Лимиты считаются по типу ставки.
* Общая сдача считается как сумма всех превышений.
* В отчёте при ошибке показываются только позиции, где была сдача.
