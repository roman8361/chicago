Нужно скорректировать запуск Roulette-аттестации дилером.

Сейчас:

`Начать аттестацию`
→ сразу открывается сохранённое игровое поле Roulette.

Нужно изменить UX.

При первом запуске аттестации дилером должна воспроизводиться такая же анимация и звук, как при нажатии кнопки `Spin` на обычном главном экране Roulette.

Главное требование:

**переиспользовать существующую анимацию Spin и существующий звук падающего/вращающегося шарика, но НЕ генерировать новый результат.**

# 1. Новый сценарий

Дилер нажимает:

`Начать аттестацию`

Дальше:

```text id="ejlg79"
проверить Assignment
        ↓
проверить сохранённый RouletteExercise
        ↓
Assignment → IN_PROGRESS
        ↓
открыть Roulette
        ↓
запустить анимацию барабана
        +
звук шарика
        ↓
после завершения анимации
показать уже сохранённый RouletteExercise
```

Визуально для дилера это должно выглядеть максимально так же, как обычный `Spin`.

# 2. Очень важно: НЕ вызывать генератор Spin

При запуске аттестации уже существует:

`RouletteExercise`.

Например в нём сохранён:

```text id="2uhs5r"
winningNumber = 17
```

При нажатии `Начать аттестацию` нельзя снова вызывать:

`generateRouletteExercise()`

или существующую функцию случайной генерации Spin.

После анимации должно выпасть именно:

`17`

из сохранённого Exercise.

То же относится ко всем ставкам.

# 3. Разделить Spin на две части

Если сейчас обработчик обычной кнопки `Spin` одновременно:

1. генерирует результат;
2. запускает анимацию;
3. запускает звук;
4. после анимации отображает результат;

нужно аккуратно разделить эти обязанности.

Концептуально должно получиться:

```text id="v0hr8n"
Обычный Spin

generate result
      ↓
playSpinAnimation(result)
      ↓
show result
```

А аттестация:

```text id="cm7r4b"
Saved RouletteExercise
      ↓
playSpinAnimation(savedResult)
      ↓
show saved result
```

То есть анимация должна быть переиспользуемой независимо от генерации.

# 4. Не переписывать существующую анимацию

Найди существующую реализацию, которая используется при нажатии:

`Spin`

и переиспользуй её.

Не создавать вторую отдельную копию:

`AttestationSpinAnimation`.

Если возможно, выделить существующую логику в функцию/hook, например концептуально:

```ts id="md69j4"
playRouletteSpinAnimation(...)
```

или использовать уже существующую функцию.

Название адаптировать под проект.

# 5. Звук шарика

Использовать ТОТ ЖЕ audio-файл и тот же механизм воспроизведения, который используется обычным Spin.

Не добавлять второй похожий звук.

При начале аттестации:

* начинается вращение;
* запускается существующий звук шарика;
* звук ведёт себя аналогично обычному Spin.

# 6. Анимация должна закончиться на сохранённом winningNumber

Если RouletteExercise содержит:

```text id="gz76xq"
winningNumber = 23
```

барабан/анимация должна визуально закончиться на:

`23`

если существующая анимация уже умеет визуально привязываться к выигрышному номеру.

Если текущая анимация является только декоративной, после неё всё равно должен отображаться именно сохранённый winningNumber = 23.

Никакой новый random winningNumber не использовать.

# 7. Ставки показывать после анимации

Желательное поведение:

при открытии Roulette в первый момент дилер видит игровое поле и процесс Spin.

Сохранённые ставки не должны мгновенно появляться раньше завершения анимации, если обычный Spin сейчас работает иначе.

Нужно повторить существующую последовательность обычного Spin.

Например:

```text id="0guxm9"
барабан вращается
+
звук
        ↓
определился выигрышный номер
        ↓
на поле появляются сохранённые ставки
        ↓
начинается существующий процесс вопросов
```

Но порядок должен максимально соответствовать уже существующему обычному Spin.

# 8. Первый запуск и "Продолжить" — разные сценарии

Очень важно различать:

### CREATED → Начать аттестацию

При первом запуске:

```text id="dsb8fn"
CREATED
→ IN_PROGRESS
→ play spin animation
→ play ball sound
→ показать Exercise
```

### IN_PROGRESS → Продолжить аттестацию

При нажатии:

`Продолжить аттестацию`

повторно крутить барабан НЕ нужно.

Нужно сразу восстановить текущий сохранённый Exercise и продолжить прохождение.

То есть анимация Spin проигрывается только один раз при фактическом начале аттестации.

# 9. Refresh во время IN_PROGRESS

Если дилер уже начал аттестацию и обновил страницу:

НЕ проигрывать Spin заново.

Поскольку Assignment уже:

`IN_PROGRESS`

нужно сразу показать сохранённое игровое состояние.

Refresh не является новым Spin.

# 10. startedAt

Поведение startedAt сохранить:

при первом:

`CREATED → IN_PROGRESS`

записывается startedAt.

Анимация не должна менять эту бизнес-логику.

При:

* refresh;
* `Продолжить`;
* повторном открытии

startedAt не менять.

# 11. Как передать признак первого запуска

Не нужно сохранять новый сложный флаг вроде:

`animationPlayed`

если статус Assignment уже позволяет определить сценарий.

Перед переходом можно передать в Roulette режим запуска, например:

```text id="k8vmd3"
startWithSpinAnimation = true
```

только при действии:

`CREATED → Начать`.

Для `IN_PROGRESS → Продолжить`:

```text id="c14an3"
startWithSpinAnimation = false
```

Выбери самый простой вариант в рамках текущего routing/state.

Важно, чтобы обычный refresh `/play` не запускал анимацию повторно.

# 12. Не хранить animation state в RouletteExercise

RouletteExercise должен по-прежнему содержать бизнес-данные задания.

Не добавлять туда поля вроде:

```ts id="d2cnrm"
animationPlayed
soundPlayed
wheelRotation
```

Это UI-state, а не данные задания.

# 13. PRACTICE режим

Обычный главный экран Roulette должен продолжать работать:

```text id="rnnq62"
Spin
↓
генерация нового Exercise
↓
анимация
↓
звук
↓
результат
```

Никакого изменения пользовательского поведения обычного Spin быть не должно.

# 14. ATTESTATION режим

В режиме аттестации:

```text id="j9irgg"
уже сохранённый Exercise
↓
анимация только при первом старте
↓
звук
↓
показать сохранённый результат
```

При этом:

* кнопки Spin нет;
* Settings нет;
* новый Exercise не создаётся.

# 15. Не проигрывать звук дважды

Проверь существующую реализацию.

Если sound сейчас запускается внутри функции генерации Spin, после рефакторинга не должно получиться:

```text id="mgsv62"
старый sound handler
+
новый sound handler
```

Иначе звук будет накладываться.

Должен использоваться один механизм проигрывания.

# 16. Не менять сам звук

Не менять:

* audio-файл;
* громкость;
* длительность;
* последовательность аудио,

если это не требуется технически.

Цель — повторить уже существующее ощущение обычного Spin.

# 17. Ошибка Exercise

Если сохранённого RouletteExercise нет:

анимацию НЕ запускать.

Показывать существующее:

`Задание не подготовлено. Обратитесь к руководителю.`

Assignment не переводить в IN_PROGRESS, если это уже предусмотрено текущей логикой.

# 18. Проверка

Проверить сценарий:

1. Создать аттестацию Roulette.
2. Exercise подготовлен заранее.
3. Войти дилером.
4. Assignment = CREATED.
5. Нажать `Начать аттестацию`.
6. Открывается Roulette.
7. Запускается та же анимация вращения барабана, что у обычного Spin.
8. Слышен тот же звук шарика.
9. Новый RouletteExercise НЕ создаётся.
10. После анимации отображается сохранённый winningNumber.
11. Отображаются сохранённые ставки.
12. Assignment = IN_PROGRESS.

Далее:

13. Выйти обратно в кабинет.
14. Нажать `Продолжить аттестацию`.
15. Roulette открывается сразу.
16. Барабан повторно НЕ крутится.
17. Звук Spin повторно НЕ запускается.
18. Exercise остаётся тем же.

Далее:

19. Сделать refresh.
20. Spin-анимация повторно НЕ запускается.
21. Exercise остаётся тем же.

# 19. Regression обычного Spin

Отдельно открыть обычную Roulette.

Нажать `Spin`.

Проверить:

* генерируется новое задание;
* барабан крутится;
* звук шарика работает;
* ставки появляются корректно;
* вопросы работают;
* никаких двойных звуков;
* визуальное поведение не изменилось.

# 20. После выполнения

Кратко сообщи:

1. где находилась существующая Spin-анимация;
2. где находилось воспроизведение звука;
3. что было выделено для переиспользования;
4. как PRACTICE запускает анимацию;
5. как ATTESTATION запускает ту же анимацию;
6. как гарантируется использование сохранённого winningNumber;
7. как исключена новая генерация;
8. почему `Продолжить` не проигрывает Spin заново;
9. почему refresh не проигрывает Spin заново;
10. подтверждение, что используется существующий звук шарика;
11. подтверждение, что обычный Spin продолжает работать как раньше.

Выполни только эту корректировку.

Не переходи к завершению аттестации или новым экранам.
