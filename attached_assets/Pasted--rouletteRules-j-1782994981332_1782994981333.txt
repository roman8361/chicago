ЗАДАЧА

Нужно расширить экран “Правила игры”.

Теперь он должен не только показывать rouletteRules.json, но и позволять редактировать правила из приложения.

---

ЦЕЛЬ

Сделать так, чтобы администратор мог менять правила рулетки без изменения кода.

Правила должны храниться в JSON-структуре и использоваться приложением в расчётах.

---

ТРЕБОВАНИЯ

На экране “Правила игры” добавить режимы:

1. Просмотр
2. Редактирование

В режиме редактирования пользователь может изменить значения правил.

---

ЧТО МОЖНО РЕДАКТИРОВАТЬ

На первом этапе разрешить редактировать:

1. Коэффициенты выплат:

* Straight Up
* Split
* Street
* Corner
* Six-Line

2. Серии:

* label
* divisor
* numbers
* settingKey
* displayZoneKey

3. Комплиты:

* chipsRequired
* payoutInChips

4. Соседи:

* пока оставить структуру, но дать возможность редактировать JSON вручную.

---

ФОРМАТ РЕДАКТИРОВАНИЯ

Сделать два варианта:

1. Простая форма для основных параметров.
2. Raw JSON editor для полного редактирования.

Если проще — на первом этапе можно сделать только Raw JSON editor.

---

СОХРАНЕНИЕ

После нажатия кнопки “Сохранить”:

1. Проверить, что JSON валидный.
2. Если JSON невалидный — показать ошибку и не сохранять.
3. Если JSON валидный — сохранить обновлённые правила.
4. После сохранения приложение должно использовать новые правила без перезагрузки страницы.

---

ГДЕ ХРАНИТЬ

На первом этапе можно хранить правила в localStorage.

Ключ:

rouletteRules

При запуске приложения:

1. Проверить localStorage.rouletteRules.
2. Если правила есть — использовать их.
3. Если правил нет — использовать дефолтный файл rouletteRules.json.

---

КНОПКИ

На экране правил добавить:

* Редактировать
* Сохранить
* Отмена
* Сбросить к дефолтным правилам

---

СБРОС

Кнопка “Сбросить к дефолтным правилам” должна:

1. Удалить пользовательские правила из localStorage.
2. Загрузить исходные правила из rouletteRules.json.
3. Обновить интерфейс.

---

ВАЛИДАЦИЯ

Перед сохранением проверить:

1. JSON валидный.
2. Есть обязательные разделы:

* version
* payouts
* trackBets
* completeBets
* neighbours

3. В payouts есть:

* straightUp
* split
* street
* corner
* sixLine

4. Значения выплат должны быть числами.

5. Делители серий должны быть положительными числами.

Если проверка не прошла — показать понятное сообщение об ошибке.

---

ВАЖНО

После изменения правил:

* расчёты выплат должны использовать новые payouts;
* расчёты серий должны использовать новые divisors;
* комплиты в будущем должны использовать новые completeBets.

---

ОГРАНИЧЕНИЯ

* Не добавлять сервер.
* Не добавлять базу данных.
* Не менять дизайн рулеточного поля.
* Не менять геометрию трека.
* Не менять генерацию Spin, кроме использования актуальных правил.
* Не ломать существующие настройки.
* Не сохранять правила в файл на диске через браузер.
* Хранить пользовательские изменения только в localStorage.

---

КРИТЕРИИ ГОТОВНОСТИ

* Экран “Правила игры” умеет показывать текущие правила.
* Есть режим редактирования.
* Можно изменить JSON правил.
* Невалидный JSON не сохраняется.
* Валидный JSON сохраняется в localStorage.
* После сохранения приложение сразу использует новые правила.
* Есть кнопка отмены.
* Есть кнопка сброса к дефолтным правилам.
* После сброса используются правила из исходного rouletteRules.json.
