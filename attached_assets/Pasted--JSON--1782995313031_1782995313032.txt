ДОПОЛНЕНИЕ К ТЗ

JSON с правилами рулетки должен быть центральным источником правил для всего приложения.

Это не временный файл и не справочник только для просмотра.

Приложение должно постоянно обращаться к нему при:

* генерации ставок;
* расчёте выплат;
* расчёте серий;
* расчёте комплитов;
* расчёте соседей номера;
* построении отчётов;
* проверке ответов пользователя.

---

ТРЕБОВАНИЕ К АРХИТЕКТУРЕ

Нужно создать единый сервис/модуль доступа к правилам, например:

rouletteRulesService

или

useRouletteRules

Через него должны получаться все правила.

Запрещено напрямую импортировать JSON в разные компоненты хаотично.

---

ПРАВИЛЬНЫЙ ПОДХОД

Компоненты не должны знать, где физически лежат правила.

Компоненты должны обращаться к функциям:

getPayouts()
getTrackBetRule(type)
getCompleteBetRule(number)
getNeighboursRule(number)
getAllRules()
updateRules(newRules)
resetRules()

---

ХРАНЕНИЕ

Дефолтные правила лежат в файле:

rouletteRules.json

Пользовательские изменения хранятся в localStorage.

При запуске приложения:

1. Если в localStorage есть сохранённые правила — использовать их.
2. Если сохранённых правил нет — использовать дефолтный rouletteRules.json.

---

ОБНОВЛЕНИЕ ПРАВИЛ

После изменения правил через экран “Правила игры”:

* новые правила должны сразу применяться в приложении;
* не требуется перезагрузка страницы;
* следующий Spin должен использовать уже обновлённые правила.

---

ВАЖНО

В будущем мы будем постоянно дополнять этот JSON:

* новыми типами ставок;
* правилами комплитов;
* правилами неполного комплита дюжины;
* правилами соседей;
* пересечениями ставок;
* формулами расчётов;
* правилами отчётов.

Поэтому структура должна быть расширяемой.

---

ОГРАНИЧЕНИЯ

* Не хардкодить правила в компонентах.
* Не размазывать правила по разным файлам.
* Не делать отдельную логику выплат вне rules service.
* Не ломать текущий Spin.
* Не менять визуальную часть рулетки.
* Не менять существующие настройки.

---

КРИТЕРИИ ГОТОВНОСТИ

* Есть единый сервис доступа к правилам.
* Все текущие выплаты берутся через этот сервис.
* Все текущие делители серий берутся через этот сервис.
* Экран правил редактирует тот же объект правил, который использует приложение.
* После изменения правил следующий Spin использует обновлённые значения.
* JSON можно безопасно расширять новыми разделами.
