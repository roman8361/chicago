Продолжаем развитие Roulette Dealer Trainer.

Сейчас уже есть:

* TrainingTemplate;
* TrainingAssignment;
* создание аттестации;
* просмотр аттестации;
* изменение списка дилеров;
* изменение настроек аттестации;
* кнопка `Удалить аттестацию`.

Нужно реализовать только следующий этап:

**удаление уже созданной аттестации.**

## 1. Кнопка "Удалить аттестацию"

На странице:

`/manager/attestations/:templateId`

кнопка:

`Удалить аттестацию`

должна быть активной.

При нажатии нельзя сразу удалять данные.

Сначала обязательно показать подтверждение.

## 2. Подтверждение удаления

Используй существующий Dialog/Modal проекта, если он уже есть.

Пример:

```text
Удалить аттестацию?

Будут удалены сама аттестация и все назначения дилеров.

Это действие нельзя отменить.

[ Удалить ]
[ Отмена ]
```

Не нужно показывать технические названия:

`TrainingTemplate`
или
`TrainingAssignment`

в пользовательском интерфейсе.

## 3. Что должно удаляться

После подтверждения необходимо удалить:

1. выбранный `TrainingTemplate`;
2. ВСЕ `TrainingAssignment`, у которых:

trainingTemplateId = id удаляемого Template

Например:

```text
TrainingTemplate #100

Assignment #1 → Иванов
Assignment #2 → Петров
Assignment #3 → Сидоров
```

После удаления должны исчезнуть:

```text
Template #100
Assignment #1
Assignment #2
Assignment #3
```

## 4. Что нельзя удалять

Очень важно:

НЕ удалять сущности Dealer.

То есть после удаления аттестации:

```text
Иванов
Петров
Сидоров
```

должны продолжать находиться в разделе:

`Управление дилерами`.

Удаляется только аттестация и связи с ней.

## 5. Реализация storage

Используй существующие storage-модули TrainingTemplate и TrainingAssignment.

Если уже существуют функции:

```ts
deleteTrainingTemplate(id)
deleteTrainingAssignment(id)
```

можно расширить минимально.

Желательно добавить удобную операцию вроде:

```ts
deleteAssignmentsByTemplateId(templateId)
```

или аналогичную.

Не размазывай ручную работу с localStorage по React-компоненту.

## 6. Порядок удаления

Логически выполнить:

```text
найти Template
      ↓
удалить связанные Assignments
      ↓
удалить Template
```

Поскольку сейчас используется localStorage и нет транзакций базы данных, достаточно выполнить операции последовательно.

Не нужно создавать сложную transaction abstraction.

## 7. После успешного удаления

После удаления вернуть руководителя в список аттестаций.

Предпочтительный маршрут:

`/manager/attestations`

Если отдельный список аттестаций ещё не реализован полноценно, допустимо вернуть на:

`/manager`

Но если `/manager/attestations` уже существует — использовать его.

Удалённая аттестация больше не должна отображаться.

## 8. Обновление списка

Если пользователь после удаления возвращается в список:

```text
Аттестации
```

данные должны перечитаться из storage.

Не должно требоваться вручную обновлять страницу браузера.

## 9. Отмена удаления

Если пользователь нажимает:

`Отмена`

Dialog закрывается.

Не менять:

* Template;
* Assignment;
* Dealer.

## 10. Неизвестный Template

Если пользователь открыл:

`/manager/attestations/unknown-id`

и Template не существует:

показывать существующий экран:

```text
Аттестация не найдена

[ Вернуться в кабинет ]
```

Кнопка удаления в такой ситуации не нужна.

## 11. Защита от повторного нажатия

После подтверждения удаления желательно временно отключить кнопку удаления, пока выполняется операция.

Даже несмотря на localStorage, не должно возникать двойных действий из-за быстрого двойного клика.

Не делать сложную инфраструктуру.

## 12. Существующие Assignment других аттестаций

Удаление одной аттестации не должно затрагивать назначения других Template.

Например:

```text
Template #100
 ├─ Иванов
 └─ Петров

Template #200
 ├─ Иванов
 └─ Сидоров
```

Удаляем Template #100.

После этого должны остаться:

```text
Template #200
 ├─ Иванов
 └─ Сидоров
```

Assignment Иванова для Template #200 нельзя удалить только потому, что тот же Dealer участвовал в другой аттестации.

Удаление выполняется исключительно по:

`trainingTemplateId`.

## 13. Количество аттестаций

Если в кабинете руководителя отображается количество или список аттестаций, он должен автоматически обновиться.

Например:

было:

`Аттестаций: 4`

после удаления:

`Аттестаций: 3`

Если такого счётчика сейчас нет — добавлять его специально не нужно.

## 14. Старые данные wizard

Удаление существующей аттестации не должно затрагивать текущий Training Wizard.

Если в state хранится какой-то черновик новой аттестации, удаление другого Template не должно его очищать.

## 15. Пока статус не ограничивает удаление

Сейчас аттестации ещё не проходят полноценный lifecycle.

Поэтому разрешаем удаление созданной аттестации.

Позже после появления:

* IN_PROGRESS;
* COMPLETED;

мы отдельно определим правило:

можно ли удалять такую аттестацию или нужно архивировать.

Сейчас эту логику не добавлять.

## 16. Пока никакого soft delete

Сейчас используется localStorage и тестовая архитектура.

Поэтому выполняем физическое удаление.

Не добавлять:

```ts
deleted = true
```

или:

```ts
deletedAt
```

Soft Delete имеет смысл добавить позже вместе с backend.

## 17. Не генерировать Spin

Удаление аттестации никак не связано с генерацией Roulette.

Не создавать и не менять:

* GeneratedSpin;
* winningNumber;
* bets;
* questions;
* results.

## 18. Не менять Roulette

Не изменять:

* Roulette;
* Settings;
* Spin;
* генераторы ставок;
* racetrack;
* вопросы;
* звуки;
* игровое поле.

## 19. Проверка основного сценария

Проверь:

1. Создаю аттестацию.
2. Назначаю Иванова, Петрова и Сидорова.
3. Открываю созданную аттестацию.
4. Нажимаю `Удалить аттестацию`.
5. Появляется подтверждение.
6. Нажимаю `Отмена`.
7. Аттестация остаётся.
8. Повторно нажимаю `Удалить аттестацию`.
9. Подтверждаю.
10. TrainingTemplate удалён.
11. Все Assignment этого Template удалены.
12. Открывается список аттестаций/кабинет.
13. Удалённой аттестации там нет.
14. Иванов, Петров и Сидоров остаются в списке дилеров.
15. После перезагрузки браузера удалённая аттестация не появляется.

## 20. Проверка изоляции данных

Создай две аттестации:

```text
Аттестация A:
Иванов
Петров

Аттестация B:
Иванов
Сидоров
```

Удалить A.

Убедиться:

* Template A удалён;
* Assignment A удалены;
* Template B существует;
* Assignment B существуют;
* Dealer Иванов существует;
* Dealer Петров существует;
* Dealer Сидоров существует.

## 21. После выполнения

Кратко сообщи:

1. какие файлы созданы;
2. какие файлы изменены;
3. как реализовано подтверждение удаления;
4. как удаляется TrainingTemplate;
5. как удаляются связанные Assignment;
6. как гарантируется, что Assignment других Template не удаляются;
7. куда происходит переход после удаления;
8. подтверждение, что Dealer не удаляются;
9. подтверждение, что используется физическое удаление из localStorage;
10. подтверждение, что Roulette не изменялась.

Выполни только этот этап.

Не переходи самостоятельно к генерации Spin или кабинету дилера.
