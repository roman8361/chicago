# Отчёт об импорте двойных комбинаций русского покера

## Источник и колонки

- Файл: `attached_assets/Принцип_построения_базы_бонусов_1792433247834.xlsx`
- Лист: `Двойные комбинации в РП`
- Использованы: D — название группы, E — бонусные комбинации, F:K — шесть карт, Y — итоговая комбинация, Z — исходный порядковый номер.
- L:X не интерпретированы и не включены в массив карт: их назначение не было подтверждено. Исходные строки Excel сохранены через `sourceRow` и `sourceRows`.
- Excel-файл не изменялся.

## Проверки и согласованные исправления

Все 86 раздач проверены: ровно шесть карт, допустимые коды, отсутствие повторов внутри раздачи и уникальные идентификаторы. Порядковые номера источника Z идут от 1 до 86.

Исправлена только повторная карта в согласованных строках:

| Ячейка | Исходное значение | Код в JSON |
|---|---|---|
| J48 | K♠ | `ck` |
| K58 | 10♠ | `d10` |
| J108 | K♦ | `hk` |
| J110 | K♦ | `ck` |
| J112 | K♦ | `hk` |
| H117 | 4♦ | `h4` |
| J142 | 10♣ | `cj` |

После замен дополнительных ошибок в импортированных 86 раздачах не обнаружено. Исходные значения и ячейки исправлений зафиксированы в JSON в `cardCorrections`.

## Неоднозначные данные

Строки 157–172 содержат шестикарточные наборы в F:K, но не имеют названия группы в D, бонусной комбинации в E, результата в Y или номера в Z. Они не импортированы, поскольку их нельзя корректно распределить по группам без предположений. Эти строки перечислены в метаданных JSON как `unclassifiedCardRows`.

Чтобы добавить такую строку позже, сначала нужно определить её группу и соответствующие комбинации. После этого её можно добавить в `deals` нужной группы, сохранив исходные номера строк.
